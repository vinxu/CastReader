# Isolated Supervisor lifecycle regression

On a Linux host with `supervisord`, `supervisorctl`, and `/usr/bin/python3`, run `python3 test-supervisor-release-isolated.py --release-tool /absolute/path/to/release-fixed-deepfilter-worker.py --execute-isolated` after reviewing both scripts. The test creates its own temporary configuration, Unix socket, daemon, logs, and sleep-only `castreader-clone` process; every Supervisor CLI call is forced to that isolated configuration, never the production daemon. It runs the release tool's real drain, automatic-replacement suppression, `STOPPED`/PID-zero handling, and explicit restart, reporting actual CLI return codes. Expect roughly 55 seconds (95-second execution limit plus bounded cleanup). The dedicated daemon and its child are shut down in `finally`; temporary files are removed, or retained with a `-needs-cleanup` suffix if the test daemon cannot exit. This does not deploy code, restart production, or create any real voice.

# 已定位的 Global 网关 502：流式响应合同冲突

记录时间：2026-09-06。修复源提交 `26d0832c7da8a604792abc7592e110cc6f2755e1`，直接父版本为线上完整版本 `3ce12a7c794e3d9788a7982a66a62f70a9407678`。本记录不代表候选已经切到生产；实际发布结果另见上线回执。

固定非用户输入为 `Dr. Hale’s field note names ꜣ in the U.S. edition.`，`en / am_adam`，省略 `stream`。R132 修复缺失发音后，模型本身成功生成，但公共网关仍返回 502。16:48:10.961 UTC、16:51:13.021 UTC 的公共请求均复现，返回 `TTS upstream unavailable`。Vercel 请求日志确认原部署 `dpl_58jqfHzCrV91FpC8s2unBG7XXcfX`、`/api/captioned_speech_partly`、502；不能仅凭该错误文案把它归因为网络故障。

## 同入口、同参数的直接证据

使用已有生产环境中同一个 `TTS_UPSTREAM_URL`，保持同区、同音色和同文本，直接响应 HTTP 200、`application/json`，但正文实际是两条 NDJSON：

| 情形 | 音频文档 | 音频字节 | 完整解码采样数（24 kHz） |
|---|---:|---:|---:|
| 省略 stream，上游默认 true | 2 | 76,077 + 1,920 = 77,997 | 114,048 + 2,880 = 116,928 |
| 显式 stream:false | 1 | 77,997 | 116,928 |

第二条包含 0.12 秒音频，没有时间戳；它不是可以丢弃的纯元数据。两条都只有 `audio/audio_format/timestamps`，没有 `processed_text/unprocessed_text`。

原网关 `retrySpeechRequest` 为了在同一预算内处理断流，读取完整 body 后执行单一 `JSON.parse`。两条 NDJSON 会导致解析异常，三次重复生成后落入泛化的 502 catch。网关后面仍有旧的“只取首行”逻辑，但该逻辑到达不了；即使只放宽前面的解析，也会丢掉第二条尾音频。

## 本次修改

普通 Kokoro 请求仍先使用现有无损文本分段；仅在发给模型时显式 `stream:false`，取得当前段的完整单 JSON 音频。网关对完整 JSON 解析，不再取首行。所有客户端收到的仍是原有单段 JSON 合同；客户端持续请求后续段的行为不变。

克隆请求在该逻辑前独立返回，本次没有修改克隆模型请求、身份、额度或恢复路径。区域选择、禁止重定向、请求预算和余文保留均不变。时间戳不作为保留音频的条件。

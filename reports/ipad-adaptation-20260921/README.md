## Module 5 investigation

- Window-owned reader, Kindle/offline centers, voice panels, bottom insets, YouTube extraction/routes and presentation contexts replace shared UI state. Account/storage services and the actual audio output remain global. Merely browsing another window does not claim audio; an explicit Play checkpoints and revokes the prior owner before replacing its queue.
- Native Read/Explain ownership recovery reuses cached audio at the exact segment time. Stale VM close, settings updates, preview completion and Kindle continuous-page callbacks are fenced by session tokens. Account boundaries advance the ownership generation rather than reusing a token.
- Closing a foreground window is verified using UIKit's real scene destruction. iPad returns to Home after that action, so the QA control explicitly reopens the surviving scene, matching the user's return. Production code does not force another scene to the front. Closing the owner moves the actual VM/reader; if there is no surviving scene, the app retains ready audio and suspends further Kindle page capture until a surface returns.

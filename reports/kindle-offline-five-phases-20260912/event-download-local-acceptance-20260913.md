# Kindle 下载正确性加固与网页内部等待：本地验收

日期：2026-09-13。实现父提交 `5f226ea`，发布祖先 `b6dd4d7`；工作树为 `CastReader-kindle-offline-five-phases-20260912`。本轮已经修改应用代码、增加故障测试并完成设备包及 Release 编译。用户要求先完成本地测试、稍后连接手机，因此新包尚未安装，新整书耗时尚未测量。

## 已落地的内容保护

- 将合法后继限制为共享归一化边界或相邻范围，拒绝内部重叠、缺口、倒序和重复。保留本书实际出现的封面边界及共享端点语义。
- 读取书籍清单时重新核对资源记录与任务代次、页序号、源起止位置的绑定及资源 ID。即使总页数、位置链和图片摘要都正确，交换两页图片引用也不能通过。
- 源页未被可信证据确认为零字数时，空 OCR 结果不能写成有效识别缓存，也不能自动跳到下一页。允许原位重试；旧空缓存不会阻止重新识别。图片保存阶段仍无 OCR。
- 用六页、三章的本机书验证按序播放，并故意重复投递、迟到投递语音事件；增加旧页 OCR 在手动换章后才返回的测试，验证不会替换当前页或播放旧章。

## 已落地的采集优化

- 原生端逐次跨 WebKit 询问改为一个网页内部等待 Promise，DOM 变化和图片 load 事件触发检查，保留网页内 50 毫秒兜底检查。
- 仍要求源范围与当前目标匹配、加载状态结束、同一图片及源证据稳定至少 50 毫秒；相同图片保留 600 毫秒等待和原生版式稳定复核。事件到达不直接等于成功，不放宽成功条件。
- 网页等待有独立请求标识、25 秒上限、最多一次原目标恢复、取消清理和旧取消隔离。Swift 取消会终止对应网页等待，收到结果后仍检查任务及阅读会话有效性。
- 离线采集缓存候选元素集合，相关 DOM 变化时重新发现；每次仍读取当前图片身份、尺寸和几何。原有在线阅读入口继续使用原发现流程。
- 单个阅读器仍一次只翻一页，固定当前页图片与源位置后才提交，随后推进下一页。没有加入批量盲收图、并发翻页或新的下载管理器。

以上是实现变化，不能直接当作真机速度证据。新增等待耗时、加载检查次数等记录，供下轮判断等待具体消耗；当前仍以此前 169.177 秒为最近一次整书结果，不宣称达到 30–60 秒。

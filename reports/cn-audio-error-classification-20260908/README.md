## 1. 已修复的问题及边界

| 已证明的问题 | 修复后的行为 | 对播放的影响 |
| --- | --- | --- |
| 连续朗读监控中，响应体读取失败被兜底归为 `unexpected_monitor_error / monitor_fault`，原始错误种类丢失 | 区分等待响应头、读取响应体、超时/中断、真正的 JSON 解析失败；保留允许列表内的错误名和传输错误码 | 监控分类修正，不增加用户播放检查或拦截 |
| 监控只看最终结果，会在重试成功时丢失前一次失败 | 持久化每次尝试的匿名键、阶段、HTTP 状态、错误码、耗时和结果；成功周期也保留失败尝试 | 可以分别衡量上游波动和最终供给失败 |
| 中国区 DeepSeek 的 `response.json()` catch 混淆了 SyntaxError、TypeError、AbortError 和外层超时 | 真正解析失败、响应体传输失败、超时、主动取消各自分类；原始 `LLM_DEADLINE_EXCEEDED` / `REQUEST_DISCONNECTED` 保持原语义 | 原来错误日志中的“非法 JSON”不能再被误当成模型内容一定有问题 |
| 响应体读取暂时失败后直接终止整个解读调用 | 对尚未交付任何内容的 `DEEPSEEK_BODY_READ_FAILED`，在原总预算内等待 100ms，并只对同一中国区 DeepSeek 接口额外尝试一次 | 在可恢复的供给错误上继续获取讲解，避免这类偶发读取失败立即使解读中断 |

恢复调用复用原有组合取消信号、原有超时、模型、请求体及该调用的请求键。最多两次尝试；第一轮失败时剩余自身预算须大于 250ms，外层预算仍可随时取消。没有新增海外上游，也没有变更现有中国区的固定提供商与禁止重定向设置。

**本次恢复的适用范围是 DeepSeek 非流式 JSON 响应体读取失败。** HTTP 拒绝、无效 JSON、已经过期的总预算、调用方断开和业务错误不会触发这次新增恢复；也没有修改流式 LLM 路径、国际区模型选择、会员额度或客户端播放。历史那条被记录为非法 JSON 的异常已丢失原始原因，本轮可以修正今后的记录与处理，不能逆推出历史那次一定是某一种传输故障。

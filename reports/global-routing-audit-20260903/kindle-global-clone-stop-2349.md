## 结论

本次不是 502，也不是翻页失败或时间戳失败。Kokoro 连续朗读期间发生音色切换，下一页第一句在克隆音频质量检查处被拒绝，返回 `VOICE_GENERATED_AUDIO_REJECTED` / HTTP 503。iOS 将该错误当成临时故障，重复请求相同固定生成参数，最终进入播放错误状态。

## 导致失败拖长的恢复问题

- Worker 每次都依次使用同两个固定采样种子和同一个 greedy 参数；外层 HTTP 重试不会换一套有效的生成策略。此次原句预取三次、前台四次的指标完全重复。
- Worker 对此类拒绝设置 `X-Voice-Retryable: false`，网关错误类型没有完整保留该标志。
- iOS `CastReader/Services/APIService.swift:760` 对所有 503 都使用 `.temporaryUnavailable`，再按 350/900/1800 毫秒延迟重试三次，没有按已解析的结构化错误码区分。
- 仅减少重试可缩短等待，不能解决下一页第一句无可播放结果的问题。修复还需覆盖同区域克隆生成的恢复策略与频谱检查校准。

原始设备日志、OCR、候选 WAV 和独立 ASR 结果保存在本机私有目录 `/tmp/castreader-kindle-global-stop-20260903/`；美国节点诊断副本位于同名临时目录。报告未包含用户正文、音色录音或凭据。

创建音色时的降噪/录音一致性检查是另一阶段，不是每段朗读都重新运行。9/3 `3c7a1ce` 已把其中的相对说话人一致性下降改为告警；这不能自动改变生成音频的频谱拒绝规则。

设计偏差在于：多个局部补丁把“可能有质量问题”统一提升为整段请求失败，再由另一层不区分原因地重试。模型、质量评分、时间戳、客户端重试没有共用“持续播放优先”的失败处置。历史长稳记录主要是固定 24 条多语言语料反复运行，不能替代真实用户音色与整本书不同段落组合的误拒测试。

后续应把可解码、非空语音作为基本可用性边界，将频谱/音高等不确定质量信号用于告警与离线改进，将时间戳失败限定为高亮降级；真正不可用的输出才进入同区域、同音色的有限恢复，且重试必须改变有效生成条件。需要清理已不走的历史模式，并把连续跨页播放而非单接口成功设为主要验收标准。本节是审计结论，尚未改动上述生产策略。

## 2026-09-04 已实施并发布

上面的“尚未改动”只描述最初定位时点。现已按“播放第一，高亮第二”的产品约束修改并完成两区服务器发布：

- 克隆音频能够解码且不是空音频时，频谱、音高、削波、直流偏移以及文本时长推算只记录后台告警，不再丢弃音频或触发重复生成。
- 词级时间戳计算发生任何异常时，保留相同 MP3、音色和正文，返回空时间戳，让四端使用句子级高亮。
- 无法解码、非有限样本、空音频和近乎静音仍视为没有可播放内容；鉴权、配额、音色归属和区域隔离没有改变。
- Web 文件朗读改走共用的区域 TTS 网关。现成音频不再等待高亮缓存；新音频先通过现有 `audioBase64` 合同返回，存储和数据库缓存写入放到响应之后。缓存读取最多占用 500 毫秒，时间戳 JSON 缺失或异常时继续返回音频。

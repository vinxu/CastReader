# 部署后的用户数据与监控复核

## 结论

**尚未全部达到预期。中国区本次普通音色网关修复在观测范围内有效；国际区仍有持续的网关 502、production 客户端事件上报的首段失败和播放中断。不能把模型进程存活或 HTTP 200 当作用户连续听完。**

本次只读查询已有日志、业务账本、客户端事件和已存在的监控结果；没有修改代码、生产配置、部署或启动新合成探针。本文的“没有修改代码”指应用和服务代码；本地查询脚本与脱敏报告属于审计产物。

共同统计窗口为 **2026-09-06 北京时间 02:50:21–08:24:11**，即 `2026-09-05T18:50:21Z` 至 `2026-09-06T00:24:11Z`，约 5 小时 34 分钟。另检查 US Kokoro 自 16:38:43 UTC、US QuickRead 自 17:45:23 UTC、CN QuickRead 自 17:51:37 UTC 上线起的完整窗口。查询时新产生且超出 cutoff 的记录没有混入分母。

## 用户侧可感知问题仍然存在

Global `mobile_funnel_events` 采用服务端 `received_at` 限定窗口，共 **816 条 production 环境事件、29 个匿名设备**；816 条的客户端所选线路和入口线路均为 Global，记录的 route mismatch 为 0。设备是安装标识，不是已验证的独立自然人；production 标签也不能绝对排除人工测试。

按设备和 `read_session_id` 在内存中关联开始、首音频和失败事件，未保存原始身份：

| 平台 | 窗口内开始的朗读会话 | 已上报首音频 | 客户端上报失败结束（`result=failed`） | 明确异常 |
|---|---:|---:|---:|---|
| iOS | 46 | 43 | 2 | Kindle 翻页失败 1 次；播放后 TTS 失败 1 次 |
| Android | 51 | 19 | 31 | 集中在一个设备，西语 `ef_dora`，全部首音频之前失败 |

这些是客户端定义的朗读会话/尝试，不能等同于独立用户操作数。窗口末端仍可能在播放，取消、额度拦截和没有结束事件也不等于故障，因此没有用“结束数÷开始数”制造播放完成率。

三项具体问题：

1. **iOS Kindle 播放后翻页中断仍有失败上报。** 北京时间 04:45:30 收到失败事件：`page_turn_failed / navigation / kindle_page_advance_failed`。客户端 1.2.33、英文普通音色 `am_echo`，该会话已上报首音频并播放 1,266 秒（21 分 6 秒）。这是客户端上报的导航失败，现有数据不足以把它归因于模型或某条 502。
2. **iOS 仍有播到中途的 TTS 失败。** 04:48:17 收到 `tts_failed / tts`，剪贴板内容、英文 `af_heart`，已播放 537 秒（8 分 57 秒）。缺少贯通客户端与网关的同一请求标识，尚不能锁定哪条服务端响应导致失败。
3. **Android 西语普通音色存在集中首段失败。** 07:50:17–07:53:09，一台 production 环境 1.0.45 设备上报 31 个文件朗读会话失败，语言 `es`、音色 `ef_dora`、错误 `generation_failed / tts_failed`；31 次均无首音频、播放秒数为 0。同期 GPU 日志未记录 HTTP 400/500/timeout；音色文件与西语支持存在。不能据此断言模型崩溃，也不能只凭时间接近把它全部归为监控同款 502。

随后按精确 TTS 路径、15 秒分片补齐上述短窗的保留请求日志，去重后没有触及页数上限：Kindle 失败附近 60 秒为 **96 条、全部 200**；剪贴板失败附近 60 秒为 **131 条、全部 200**；Android 失败前后 3 分 45 秒为 **84 条，82 条 200、2 条 502，没有 400/401/403/429**。这些包含当时所有调用者，缺少 UA/trace，不能声称这些 200 就是失败设备的响应，也不能把两条 502 配给它的 31 次失败。它们说明不能仅从该端点的 5xx 数量解释客户端失败；还需区分请求未到达、200 响应内容/解析和客户端播放流程。见[客户端附近的网关短窗](global/vercel-client-window-status.json)。

**额度与主动操作单列：** iOS 另有 2 条 `blocked / listen_quota`，属于用户允许保留的业务限制；关闭内容、切换模式等取消事件不计入上述技术失败。

有首音频的样本中，iOS 延迟中位/P95/最大为 **2.036/5.044/47.328 秒**，Android 为 **1.963/13.683/13.683 秒**。这是混合音色的客户端上报耗时，且不包含完全未出声的失败，不能当成某个模型的纯生成速度或全体请求性能。

旧版/浏览器事件还记录：1 次 `tts_network_error`、1 次 `tts_response_invalid`；解读失败为 1 次 `server_error_400` 和 1 次 `extraction_empty`。后者可能发生在内容提取阶段，不应直接算作供应商崩溃。旧表的 `created_at` 可由客户端控制，晚到事件会进入历史窗口；它与移动表存在重复写入，**两张表不相加**。

证据：[移动事件与会话关联](global/client-observation.json)、[旧版错误分类](global/legacy-error-observation.json)、[查询脚本](global/collect-client-events.mjs)。

## 解读、克隆和模型本身的边界

- **US QuickRead 有正常生产后端供给。** 从自身上线到 cutoff，25 个任务通过身份/权益闸门，另有 1 次业务额度拒绝；25 个任务均持久化了可用首块，20 个生成了所有块，5 个仍只生成部分块。部分生成可能是用户未继续请求或断开，不能据此算成 20/25 用户听完。应用日志未记录技术错误/超时；Caddy 有一次响应未完成/取消，无法区分用户取消与网络断开。HTTP access log 缺失，不能给完整接口错误率。
- **CN QuickRead 缺少可评价的真实使用样本。** 查询未见窗口内新任务、持久化推进或解读漏斗事件；其 access log 被关闭，不能把日志为空写成零请求、零错误或稳定性通过。
- **克隆样本过少。** CN 窗口内没有正常克隆合成账本记录；US 完整上线窗口只有 5 次 captioned synth 和 1 次降噪 prompt build，共同窗口仅 1 次 synth，未记录结构化失败。不能据此证明克隆长文、并发或四端连续播放均稳定。
- **R132 仍有一处需要继续定位的英文边界。** US Kokoro 自身上线到 cutoff 的诊断中，有 6 个 HTTP 500，来自两个 correlation ID 各三次，集中于北京时间 01:32:59–01:33:09；失败的是内部 2 字符生成单元的英文发音恢复。两个 ID 与已保存运维回执没有精确匹配，来源不明。不能称为已证实的真实用户故障，也不能从部署后报告里省略。共同窗口内的 GPU 诊断未见 HTTP 失败；诊断不是所有请求的访问日志，不能用诊断事件数作请求分母。

CN Next/QuickRead/两个 GPU 隧道，以及 US 已核对的 QuickRead/Kokoro/Clone/Nari，在可见身份与日志范围内没有重启或版本漂移；CN 可读 kernel 日志未见 OOM。**进程不崩溃和用户连续播放正常是不同的验收项。**

证据：[US 后端审计](us-backends/README.md)、[QuickRead 聚合](us-backends/quickread-aggregate.json)、[GPU 聚合](us-backends/gpu-aggregate.json)。

## 区域与可观测性

CN 195 段探针结果指向 `castreader-cn4090 / cn-environment`，Global 816 条移动事件的选择与入口线路一致；本轮未发现这些样本中有 CN/Global 串线。`gateway=vercel-r2` 是旧的固定标签，不代表 CN 请求去了 Vercel。

但探针只覆盖固定语言和普通音色；US 探针在取得有效音频前就失败，部分请求缺少 hop/trace 信息。因此本次数据不足以重新认证录音、克隆、存储、解读和四端全链路均无跨境。

Vercel 聚合指标查询返回 `payment_required`，本次没有增购，使用现有保留日志。5xx 查询分片没有触及返回上限；客户端附近的短窗最初查询触及上限，已用精确路径和 15 秒分片重新取得无截断结果。它仍是保留日志范围的完整查询，不等于平台保证所有网络请求都被记录。全局用户请求分母、跨客户端会话和服务器请求的关联，以及 CN QuickRead access log，仍是明确的观测缺口。

Global 业务数据通过同一个已验证 Supabase 项目的 HTTPS REST 接口只读取得。最初 PostgreSQL 审计连接的证书链验证失败，本次保持证书校验并改用已正常验证证书的 HTTPS 路径。此情况属于审计连接方式，不是已观测到的应用故障。Supabase 的证书校验要求见[官方说明](https://supabase.com/docs/guides/platform/ssl-enforcement)。

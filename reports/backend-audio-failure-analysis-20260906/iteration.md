# 六条失败后的客户端迭代（2026-09-06）

已完成代码修改、回归验证与独立分支提交。历史六条事件的原始异常和 request ID 仍然缺失；本轮修复的是从发布基线中确认的中断、漏播及误报路径，不能宣称六次现场根因全部复现。

## 已落地的修改

| 路径 | 已确认的问题 | 修改后的行为 |
|---|---|---|
| iOS Kindle 自动翻页 | 模式切换、任务取消和同步弹窗被合并为翻页失败；在新模式接管前后可能结束错误的朗读会话 | 三个异步边界重新核对取消、模式和弹窗；模式切换退出旧操作，弹窗交给既有恢复任务，不由旧翻页任务上报导航失败 |
| Android PDF 解读预取 | 预取脱离当前管线，异步共享变量可能导致同批重复请求；异常被吞成空块 | 预取随当前解读协程结束，保存单次请求结果；失败不会提前取消正在播放的当前块，需要该块时保留失败阶段与原始 cause |
| Android PDF 普通 TTS | PDF 直接调用 Retrofit，未使用普通朗读控制器已有的响应解码恢复 | 接入同一普通音色恢复策略，最多额外一次；接口与音色保持一致，克隆不进入普通音色重试 |
| Android PDF 连续生成 | 取块失败会跳块，TTS 中途失败会返回部分块；固定 24 次循环可能丢掉余文 | 不再把失败伪装成成功或跳过未读内容；移除 24 段截断，以每次消耗正文约束循环，保留未处理后缀 |
| Android PDF 快道 | 快道期限包含 TTS 生成，慢克隆可能被取消后进入另一轮生成；标准兜底只读第零块 | 快道只竞争讲解文本，选定后再生成一次音频；兜底计划消费全部块后才进入后续正文 |
| Android PDF 标注/播放 | compose 失败信息被吞；阻塞 HTTP 读体不能及时响应协程期限；MediaPlayer 错误可能不结束等待 | compose 改为可取消的 HTTP 调用，PDF 回填等待 2 秒后使用本地标注；标注绘制允许降级；播放器错误释放等待并保留 playback 阶段，取消不记故障 |
| Android 解读分析事件 | 仅记录前两块开始；失败时用已完成块数作全文分母，出现失败同时 complete | 每块实际启动时记进度；非成功且全文总量未知时完成度为 unknown |

普通 TTS 原有的同区请求和鉴权边界仍由既有路由层执行。本轮没有新增跨境地址、切换生产路由、切换克隆音色、修改会员或额度配置，也没有删除六条原始失败记录。QuickRead 402 仍进入业务限制处理；技术异常的原始正文/响应/密钥不进入新的分析事件。

实际供给在有界恢复后仍失败、或真实音频不可播放时，客户端仍需要记录终止，不能凭空补出音频。本轮不以“跳过内容”“无限重试”或“隐藏失败记录”作为稳定性改善。完整用户现场长时播放效果必须在新客户端发布后验证。

后续发包必须包含对应完整提交链，不能只取最后一个补丁。主工作树存在其他任务未提交改动，本轮没有覆盖或混入它们。

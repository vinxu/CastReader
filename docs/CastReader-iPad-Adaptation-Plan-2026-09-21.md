# CastReader iPad 完整适配计划

日期：2026-09-21。状态：已获用户授权并进入实施；代码位于独立 `codex/ipad-adaptation` 工作树。以下保留原始完整范围和验收标准，实际执行证据见 [实施记录](../reports/ipad-adaptation-20260921/README.md)。用户随后指定仅使用现有 11 英寸 iPad 模拟器；因此其他硬件、系统和真实购买等项目仍须按第 12 节标记验证边界，不能用单模拟器结果替代。未执行 App Store 上传或提交。

## 1. 目标与完成定义

把现有 CastReader 做成同一 App、同一账号和订阅体系下的原生 iPhone / iPad 通用应用。iPad 上完整保留「朗读 + 词级高亮 + 自动跟随」和「讲解音频 + 原文标注」，并让大屏、横屏、分屏、自由窗口、键盘及触控板成为正常使用方式。

完整适配包括三个层次，必须全部验收后才能称为完成：

1. **功能完整**：现有发布基线中每一个面向用户的入口和功能在 iPad 上可用，地区差异遵循现有规则。
2. **体验完整**：界面按窗口空间组织；字体、弹窗、阅读宽度、操作距离合理；键盘、指针和辅助功能可以完成核心流程。
3. **行为完整**：旋转、缩放、切窗口、后台播放、重新登录、恢复购买、重新打开文档都不造成串音、丢位置、错高亮或重复计费。

推荐将本计划作为一个完整项目，按里程碑逐步内部验收。前面阶段产物可以进入内部测试，但不能以“开启 iPad 设备类型”作为项目完成点。

## 3. 范围与默认产品决策

### 3.1 完整纳入

- 同 Bundle ID `com.same.castreader` 的 Universal App，复用现有内购产品、账号、订阅和后端鉴权。
- 首页、导入、文库、历史、设置、登录、Pro、免费额度、音色发现、私人/朋友/社区声音及现有创建、管理、分享流程。
- 照片与多页扫描、文本、Markdown、PDF、EPUB、DOCX、网页、YouTube 字幕，以及 Kindle 在线/离线、微信读书、Google Play 图书、Kobo、O’Reilly。
- 云盘导入、系统 Files、分享扩展、Widget、App Intents / 快捷指令、已有深链及提醒入口。
- iPad mini、标准 iPad、Air / Pro 中大尺寸；四方向、系统支持的分屏/Slide Over/Stage Manager/窗口化、外接键盘和触控板。
- App 内多个文档窗口，以及适用设备上的外接显示器窗口移动。
- iPhone 原有功能、数据与界面回归。

### 3.2 明确边界

- 本次是原生 iPad App 适配。沿用已记录的产品边界，**不增加 iPhone/iPad Safari Web Extension**；Safari 分享菜单进入现有 Share Extension 则在范围内。
- 不在这次适配中增加 Mac Catalyst、Vision Pro 独立产品或独立 iPad 付费 SKU。
- Apple Pencil 支持点击、系统文本选择和 Scribble 文本输入；任意手写笔记、绘画、批注导出属于后续新功能。现有 AI 原文手写标注必须完整适配。
- PDF 双页和 EPUB 双栏是可选增强，首个完整适配版本默认使用更稳定的单页/单栏阅读。第三方站点自身出现的双页布局必须被正确处理。
- 保留已有跨端数据行为；不能把“同账号 Pro 一致”承诺成尚未实现的所有本地文件、私人缓存和阅读进度自动云同步。跨设备同步新增能力单独评估。
- 云端 TTS、授权和第三方服务的网络依赖沿用现状；不宣称全功能离线。

### 3.3 推荐的核心交互

1. 窄窗口呈现紧凑导航；宽窗口提供导航侧栏和内容区；阅读时允许收起导航，充分显示原文。
2. 目录、音色和解读字幕按需要打开，宽度足够时停靠为辅助面板；默认不同时铺满多个面板。
3. 同时打开多个文档窗口；**全 App 仅一个实际播放会话**。单纯浏览另一个窗口不抢播放，明确按下播放才转移控制权。
4. 播放、解读、声音选择、语速、Aa、睡眠定时均可通过触摸完成，并补充键盘和指针操作。
5. 以当前窗口/容器的宽高、可见区域和字体尺寸布局，设备型号只用于能力检测与测试分组。

Apple 当前建议充分利用 iPad 内容空间、减少不必要的全屏过渡，并支持多种输入方式；本计划据此设计。[Designing for iPadOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-ipados)

## 4. 布局与导航设计

### 4.1 自适应规则

以下 pt 数字是首轮原型参数，不是系统 size class 定义；在真实字体、语言、键盘和设备上验证后微调。

| 当前窗口可用宽度 | 默认结构 | 阅读状态 |
| --- | --- | --- |
| 小于 600 pt | 单列；紧凑导航，次级页面 push 或 sheet | 原文优先，短播放条，目录/设置临时展示 |
| 600–999 pt | 内容居中，导航侧栏按需展开；首页卡片可分列 | 单栏阅读；辅助内容用 popover、sheet 或替换式面板 |
| 1000–1279 pt | 可固定约 240–280 pt 导航侧栏；内容获得剩余宽度 | 开始阅读可自动收起侧栏；正文宽度独立限制 |
| 至少 1280 pt 且内容空间足够 | 可显示导航 + 原文 + 约 280–340 pt 辅助面板 | 保证原文最小可用宽度，再决定是否保留两侧面板 |

补充规则：

- 正文推荐宽度约 680–840 pt，普通内容页约 960–1200 pt；随字号与语言调整，避免一行文本横跨整个 13 英寸屏幕。
- 内容区过窄时先收起导航，再将辅助面板改为临时展示。大字号优先保证阅读和操作，不维持多栏数量。
- 高度不足约 500 pt 或键盘使可视内容过小时，减少封面/装饰区高度、压缩工具条，把次级操作放入菜单。
- 采用系统安全区和实际播放器高度。正文最后一行、列表最后一项、弹窗取消按钮始终可到达。
- 旋转或拖动窗口不能重新创建阅读会话。布局改变不触发自动播放、重新生成解释或重新扣额。

### 4.2 导航结构

iPad 顶层建议为「首页 / 文库 / 音色」，导入是明确的 `+ 导入` 动作，设置与账号放在工具栏或侧栏底部。中国与国际区域继续使用既有入口可见性。

- iPadOS 18+ 优先评估系统可切换 Tab / Sidebar 的容器；17.6 用 `NavigationSplitView` 等可用组件实现相同路由。先完成小原型，再固定实现方式，避免两套容器拥有不同业务状态。
- iPhone 保留当前入口习惯；共享导入路由、页面和会话，不要求随 iPad 一起重做导航。
- 目录属于当前文档的次级导航，不混入顶层音色/文库切换。
- 返回、收起阅读器、关闭文档窗口、停止播放分别有清晰含义。

系统 Tab / Sidebar 的适用方式参考 [Apple Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)。

宽屏阅读示意（辅助面板按需展开）：

```text
│ 导航切换  文档标题           朗读 / 解读     导入  Aa  更多       │
├────────────┬───────────────────────────────┬────────────────┤
│ 首页       │                               │ 目录 / 解读字幕 │

└─────────────────────────────────────────────────────────────┘
```

| 内容 | iPad 方案 | 必须验证 |
| --- | --- | --- |

## 6. 阅读器专项

### 6.1 统一几何与恢复约定

将语义阅读位置与界面坐标分开：

- 文本/EPUB：文档版本、段落标识、当前语音片段及 processed text 中的字符位置。
- PDF/照片：页标识、原页归一化位置或词/字符范围、缩放比例、视口中心。
- 商业阅读器：平台可验证的内容位置、章节/页身份、当前文本锚点与布局版本；不能只保存改变排版后即失效的可见页号。
- 各阅读视图记录自己的 viewport / geometry revision；过期 JS、OCR、布局、滚动和翻页回调不能覆盖新位置。

窗口变化处理流程：保存语义锚点 → 更新可用区域 → 使受影响的几何缓存失效 → 完成当前布局 → 重新定位高亮与标注 → 恢复当前阅读点。音频会话保持；仅当第三方重排使当前正文无法确认时，进入明确的“恢复阅读位置”状态并有界重试，不能盲目跳页。

拖动过程中合并昂贵重排，停止缩放后做最终校正。不能每帧重新 OCR、重建 WebView 或请求 TTS。用户手动浏览时保持其阅读位置；跟随播放的恢复遵守原有自动跟随规则。

### 6.2 分渲染器要求

| 阅读源 | 适配工作 | 硬性保留 |
| --- | --- | --- |
| 文本 / Markdown / EPUB | 使用容器宽度测量；限制阅读行长；宽度/字号/侧栏变化都刷新 glyph 与 mark 几何；目录可停靠 | 高亮仍落在 TTS `processedDisplayText`；插图、SVG、段落连续 ID、目录和续读 |
| PDF | PDFKit 适合宽度/页面；页缩放和工具栏遮挡统一换算；缩略图/页导航作为辅助面板 | 文本 PDF 与扫描 PDF 原页、OCR bbox、旋转页和缓存恢复；大 PDF 分页释放内存 |
| 照片 / 多页扫描 | fit width / fit page、缩放、拖动和选区；重排保留归一化视口与用户 zoom | Vision 左下原点到显示坐标转换正确；不能宽度一变就丢缩放 |

| Kindle 离线 | 下载管理、页列表和阅读页适配；图片按视口和屏幕比例降采样 | 已下载内容和原进度迁移；实际离线能力以当前实现和音频缓存为准 |
| 微信读书 | 去除 iPad 路径的竖屏依赖；验证网页宽屏、Canvas/DOM 与目录；重排后恢复真实位置 | 不重建活跃 WebView；跨页预读、短章尾和完整字幕；不保存新受限正文 |

第三方源逐一建立“全屏竖/横 → 窄分屏 → 展开侧栏/音色 → 继续读/解读 → 重开”的验收用例。UA 改动必须单站点验证，不能把所有 `.mobile` 批量改成 `.desktop`。

### 6.3 解读与播放控件

- 解读主视觉始终是原文上的手写标注。完整讲解字幕可以放辅助面板；不改成仅显示聊天文本。
- 标注保存语义锚点、动作、确定性 seed 与播放状态；窗口重排重算路径，不重新请求解释、不重复播绘已完成标注。
- 播放条可紧凑/展开，但实际操作指向同一会话。状态至少包含准备、播放、暂停、等待片段、恢复、失败和完成。
- 保留 `moreSegmentsExpected`、暂停意图、显式开始解读、声音切换、旧响应过滤和睡眠定时。
- 迷你播放器可在主内容底部停靠；为内容提供精确 inset，正确避让键盘、安全区和系统窗口控件。
- 对同一文档同时打开两个窗口，播放状态可共享，浏览位置各自保留；仅用户选择“跟随当前播放”才同步滚动。

## 7. 多窗口、播放与状态架构

### 7.1 状态的三种所有权

以下名称为建议设计名，实施时可沿用现有类型扩展，避免为重命名而重构。

| 层级 | 持有的状态 | 不应持有的状态 |
| --- | --- | --- |
| App 级服务 | 登录、Pro、额度、服务路由、缓存仓库、唯一音频播放器、唯一实际播放所有者、睡眠定时 | 某个窗口当前的 sheet、导航路径、几何尺寸 |
| 文档/阅读会话 | 内容身份与版本、Read/Explain VM、已生成音频/标注、恢复锚点、受控异步任务 | 任意窗口上的全局弹窗开关 |
| Scene / 阅读表面 | 导航、当前文档、面板状态、键盘焦点、滚动/缩放、presenter、WebView 与几何注册 | 独立重复计算的 Pro、重复的全局播放计时 |

推荐演进方向：

- 在现有播放器外明确 `PlaybackOwner`：至少包含 sessionID、mode、generation 和发起 sceneID。所有完成、翻页、重试、换声回调校验所有权。
- 将当前 `PlayerCoordinator` 的展示状态与播放控制逐步分开；复用现有 VM 和恢复服务，避免整体重写朗读管线。
- `SceneCoordinator` 管理当前窗口的路由与展示；`PresentationContext` 提供准确 `UIWindowScene` 和 presenter，供 OAuth、购买、文件选择与分享使用。
- 审核 `KindlePlaybackCenter`、`KindleOfflinePlaybackCenter`、`PlaybackVoicePanelCenter`、YouTube 路由、`BottomOverlayMetrics` 等共享对象。共享数据可以保留，当前窗口的 UI 状态必须按 scene 区分。
- `ReaderWebAppearanceCenter` 等按 documentID 注册的界面对象，扩展为 sceneID + readingSurfaceID；同一文档在两个窗口里不能互相覆盖注册。
- 原生 `TextViewRegistry` 目前是阅读 View 局部实例，保持局部归属；避免重构时将它错误改为全局。
- History、缓存写入、导入结果与播放计费通过统一存储/actor 串行更新；并发打开/删除同一文档不会破坏数据。

### 7.2 明确用户可观察的规则

| 操作 | 预期行为 |
| --- | --- |
| A 窗口朗读，打开 B 窗口浏览文库/文档 | A 继续播放；B 不自动 activate 播放回调 |
| 在 B 明确点播放/开始解读 | 保存 A 进度，原子转移播放所有权，B 开始；A 显示已暂停/播放已转移 |
| A、B 显示同一文档 | 可独立滚动；播放命令仍只有一个来源，不能重复生成/计费 |
| 关闭非播放窗口 | 清理该窗口 UI，不干扰音频 |
| 关闭播放所属窗口 | 保存位置，App 级会话保留已就绪音频；将后续阅读所需表面迁移至可用窗口，其他窗口可接管展示 |
| 用户主动停止播放/关闭播放会话 | 取消当前生成与预读、保存位置、清理播放器；明确处理睡眠定时 |
| 系统回收进程后恢复窗口 | 恢复文档和阅读位置，默认暂停；不自动出声、不重新领取试用 |
| 分享/Widget/深链打开已有文档 | 优先定位已有目标窗口；否则在合适窗口打开；幂等消费一次 |
| 同时在不同窗口发起登录/购买 | 全局事务只执行一次，系统 UI 回到准确的发起窗口；所有窗口同步结果 |
| 切账号/退出登录 | 各窗口统一清除旧账号受保护状态、停止不再有权执行的任务，缓存按现有账户隔离规则处理 |
| 正式播放期间明确点击音色试听 | 暂挂正式播放，试听取得短期所有权；结束/取消后恢复原意图；期间新的播放/暂停命令优先，不能过期自动恢复 |

进度区分 `playback checkpoint` 与各窗口 `viewport checkpoint`。后台窗口浏览不能覆盖实际朗读位置；同文档窗口冲突按用户最后明确操作及写入版本仲裁。

窗口关闭与退到后台分别测试。商业网页的后续翻页/OCR可能需要有效渲染表面，不能只保留 AVPlayer 就宣称可无限续读：优先保留或迁移所需阅读会话；如果所有可用 scene 已关闭、平台无法继续确认下一页，播完安全队列后保存位置并暂停，重新打开可继续，禁止播放未经确认的下一页或进入无限重试。该边界必须在真机验证并与现有后台播放能力区分。

### 7.3 分阶段启用，避免半成品多窗口

先完成单场景自适应与所有权基础，再在内部候选启用并验证多文档窗口。实际归档现已生成 multiple scenes 为 true，所以 P0 必须明确控制该开关：基础阶段如果不能保证安全，内部候选暂时禁用额外文档窗口；最终完整版恢复并通过双窗口测试。不能仅隐藏“新窗口”按钮却忽略系统创建 scene 的路径。

多任务必须按 scene 响应，窗口尺寸不等于屏幕尺寸。Apple 对动态窗口和场景提供了明确指导；新版本 API 用 availability 保护，17.6 保持有效的几何监听路径。[Multitasking](https://developer.apple.com/documentation/uikit/multitasking-on-ipad-mac-and-apple-vision-pro)、[Building a desktop-class iPad app](https://developer.apple.com/documentation/uikit/building-a-desktop-class-ipad-app)

## 8. 工程与平台工作

1. 主 App 的 Debug / Release 更新为设备类型 `1,2`，逐 target 核验版本、图标、签名、App Group、Keychain、URL Scheme 和 entitlement。新增 Swift 文件用 `xcodeproj` Ruby 工具登记，遵守传统工程四处引用要求。
2. 保留最低系统 17.6，暂不为适配本身提高最低版本。检查新容器、toolbar、inspector、窗口几何 API 的可用性；分别定义 17.6、18、26 及发布时最新正式系统行为。
3. iPad 支持四方向及动态窗口尺寸。对 iPad 路径移除微信读书/YouTube 的应用级方向锁；iPhone 原策略单独保留并回归。
4. 继续不使用 `UIRequiresFullScreen`。核验最终归档实际 Launch Screen、scene manifest、方向及设备类型；工程文件里的配置与产物都要检查。
5. 全面审计 `UIScreen.main`、第一个 window、固定尺寸、全局 orientation 和单例 UI 状态。按实际容器/scene/window 获取宽高和显示比例；不是无差别替换所有常数。
6. 相册优先采用适合当前最低系统的系统照片选择器，核对授权与返回模型；Files 使用安全作用域访问、导入后受控复制、取消及资源释放。
7. 相机、扫描、录音在失焦、窗口变化或其他 App 占用时有中断/恢复 UI。系统扫描器无法在某环境继续时保留流程并提供替代输入；不要声称调用自定义 AVCapture API 就能修复所有系统扫描器限制。
8. 现有后台音频能力、锁屏播放信息、耳机控制、蓝牙/AirPlay 路由、中断和拔耳机行为在 iPad 真机复验。
9. 外接屏使用窗口所在 screen 的坐标与比例；移动窗口后更新弹窗、光栅尺寸、焦点和高亮。不新增独立演示模式。
10. 保留现有 Launch Screen 并验证新 SDK 构建。Apple TN3192 已说明 iOS/iPadOS 27 的提交相关 Launch Screen 要求；实际发布时再次核对 SDK 与商店要求，不以本机 Xcode 26.6 的编译成功替代新系统验收。

参考：[TN3192](https://developer.apple.com/documentation/technotes/tn3192-migrating-your-app-from-the-deprecated-uirequiresfullscreen-key)、[iPad 多任务相机](https://developer.apple.com/documentation/avkit/accessing-the-camera-while-multitasking-on-ipad)。

## 9. iPad 输入与辅助功能

### 9.1 键盘与指针

| 快捷键建议 | 动作 | 焦点规则 |
| --- | --- | --- |
| Space | 播放/暂停 | 仅阅读/播放上下文；文本编辑、网页输入或系统控件聚焦时不拦截 |
| ⌘O | 打开文件导入 | 作用于当前窗口 |
| ⌘F | 当前文档搜索；不支持则只提供页面已有搜索 | 不为了快捷键新增尚无底层能力的全文搜索 |
| ⌘1 / ⌘2 / ⌘3 | 首页 / 文库 / 音色 | 当前窗口顶层切换 |
| ⌥← / ⌥→ | 现有上一/下一段或页 | 随阅读源显示真实语义；编辑中不抢系统移动光标 |
| Esc | 关闭当前弹层/退出临时选择 | 不当成停止音频或销毁文档 |

具体键位在原型阶段做冲突检查，Command 长按帮助和系统菜单能发现；可用动作按页面状态正确启用/禁用。补充 Tab / Shift-Tab / 方向键焦点、滚轮滚动、拖动、悬停反馈、右键/长按菜单。

### 9.2 拖放与 Pencil

- 从 Files、Safari、Notes 等拖入文件、URL、图片和文本，复用现有导入校验与存储路径；多个项目形成有界队列，显示逐项状态。
- 限制数量、大小、解包体积和并发；同一投递只消费一次；窗口关闭后的任务结果不能误投其他窗口。
- 只对应用有权导出的现有用户文件/文本提供拖出；不扩大第三方平台受限内容的导出能力。
- Pencil 点按和系统文本选择可靠；文本输入支持 Scribble。AI 动画标注不因 Pencil 触碰而改变语义或落点。

### 9.3 辅助功能与国际化

- VoiceOver 标签、控件顺序、选中状态和进度可读；词级高亮刷新不触发每个词的系统朗读，避免与 TTS 争用。
- Dynamic Type 包括辅助大字号；按钮可换行、工具栏可收纳、表单可滚动，核心触控区域按至少 44×44 pt 设计。
- Full Keyboard Access、Switch Control、减弱动态效果、提高对比度、浅色/深色模式纳入验收；选中/失败状态不能仅靠颜色表达。
- 覆盖现有编译资源中的所有界面语言，重点检查中文、英文及长文案语言；审计版式的方向性，Arabic/RTL 文本作为内容样本测试，不宣称新增完整阿拉伯语界面。
- 系统字号与阅读 Aa 设置协调，避免双倍放大或阅读器完全忽略可访问性需求。

## 10. 账号、会员、数据与升级

### 10.1 权益必须同口径

沿用当前发布源码的移动会员状态、canonical user、StoreKit 与服务端权益口径，不根据旧 AGENTS 的历史 API 描述另建 iPad 路径。

必测：同账号 iPhone/iPad、Web 已有 Pro 登录 iPad、Apple 购买/恢复、退出再登录、同安装换账号、免费额度耗尽、订阅过期/撤销、网络失败、未知余额及多个窗口同时刷新。

仓库已有安装归属冲突导致有效 Pro 无法返回的记录。该问题属于后端/账号行为，iPad UI 适配不能替代修复验证；开工时确认相应修复的真实部署状态，再用非客户测试账号覆盖等价路径。不能把改绑设备、赠送会员或清零用量当作适配修复。

两窗口只对唯一实际播放累计使用量；播放暂停、只读浏览、几何重排、另一窗口加入观察均不重复累计。音色试听遵循现有计量合同。

### 10.2 从旧 iPhone 兼容版升级

- 保持 Bundle ID、App Group、Keychain access group、订阅产品和数据目录一致。
- 在已装旧包的 iPad 上原地升级，核对登录、文库、书架绑定、离线包、私人声音、阅读进度、设置和 Widget。
- 旧的屏幕像素位置不直接作为新宽屏位置：保留内容身份，转为语义锚点；无法可靠恢复时回到最近有效段落并说明，不默默清空历史。
- 缓存格式只有在需要时提升版本；原文件和真实阅读位置不随派生几何缓存一起删除。
- 新窗口状态与内容数据分开存储；损坏的窗口状态可单独丢弃，不影响用户文档。
- 跨设备验证必须分别记录权益、文件来源、位置同步现状，避免把本地文档未自动出现误判为会员失效。

## 11. 性能、可靠性与观测

### 11.1 原则

- 限制活跃 WKWebView、OCR 和文档解析并发；背景窗口保留状态，对非播放表面做资源回收。恢复不能影响前台音频。
- 大 PDF/EPUB 保持已有懒加载、降采样、缓存和取消检查；图片像素预算取决于窗口和缩放，不能直接乘整个 iPad 屏幕面积。
- 先建立同设备、同样本、同网络的基线，再优化。已有模拟器 PDF 峰值记录不能作为 iPad 真机内存结论。
- 不随适配重写上游 TTS，也不把远端冷启动时间算成布局性能。

### 11.2 建议的可量化验收目标

这些是项目拟定门槛，首轮真机基线可收紧；若调整必须记录原因。

| 项目 | 目标与测量方式 |
| --- | --- |
| 本地常用 UI 响应 | 真机点击到可见响应 p95 ≤100 ms；没有可复现的长主线程阻塞 |
| 原生阅读重排 | 松开 resize / 旋转布局稳定后 500 ms 内恢复正确原文与高亮；不重播当前段 |
| 第三方阅读重排 | 受控样本稳定后目标 2 s 内完成位置确认；超过则显示恢复状态，有超时与重试出口 |
| 高亮精度 | 在可控时间戳样本上保持词/字符正确，稳定布局后原生 bbox 边缘误差目标 ≤2 pt；扫描原文使用可复核词框样本 |
| 音频连续性 | 缓存/受控网络的旋转、缩放、面板开合不重启音频、不增加超过 100 ms 的额外可归因停顿 |
| 空间变化压力 | 一次会话执行至少 30 次窗口缩放/旋转/面板切换，零崩溃、零错误文档、零额外扣额 |
| 长时可靠性 | 中档 iPad 上常规声音至少 60 分钟跨段/跨页；另做克隆和解读专项，零无出口停播 |
| 内存 | 同设备相对稳定单窗基线无不合理回退；双窗/大文档压力下无 jetsam，关闭窗口后内存回落且无持续增长 |
| 能耗与滚动 | Instruments 检查主线程、帧卡顿和能耗；不能用全量持续重排/OCR换取短暂正确布局 |

远端服务延迟单独记录 p50/p95 和请求 ID，不把“MP3 返回 HTTP 200”视为实际播出、高亮、标注通过。

### 11.3 观测字段

在现有遥测中按需增加低基数维度：phone/pad、窗口宽度/高度分组、单/多窗口、阅读源、布局恢复结果、播放所有权冲突、原文高亮恢复耗时。scene/session 标识仅用于必要的技术关联并遵守现有隐私规则，不上传正文、账号凭据或屏幕内容，不做设备指纹。

## 15. 发布准备与退出标准

1. 使用同一个 App Store 条目和现有内购产品，核查 iPhone/iPad 设备支持、版本号、签名和扩展一致；版本号在真正发布时读取 ASC 再定。
2. 准备真实 iPad 截图，覆盖首页、原文同步朗读、解读标注、PDF/EPUB 和音色，体现实际宽屏布局。按现有本地化范围审计，不擅自把当前资源数量当成未来语言清单。
3. Apple 当前截图规格要求运行于 iPad 的 App 提供 13 英寸显示组截图，支持如 2064×2752 / 2752×2064 或 2048×2732 / 2732×2048。上传前再次核对规则和 ASC 接受状态。[Screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)
4. 审核说明提供 iPad 的导入→朗读→解读、账号/购买恢复、两区入口说明；按已有 SOP 处理测试资料、权限说明和合规检查。

6. 保留可回退的源码和候选记录。Universal 发布后的故障处理以修复更新为主，不把移除 iPad 支持作为回滚方案，也不假设商店能立即恢复旧二进制。
7. 发布后按 phone/pad、来源与窗口状态观察崩溃、导入成功、阅读恢复、播放失败和会员错误；沿用现有发布观察流程。该计划本身不创建监控任务或触发发布。

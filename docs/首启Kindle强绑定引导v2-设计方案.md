# 首启 Kindle 强绑定引导 v2 · 设计方案

> 2026-08-04：产品重新确认以本方案的第 0、1 屏为唯一实现依据。第 0 屏必须是 Kindle 价值页，第 1 屏必须直接给出三个 Amazon 站点；[v3](./首启Kindle强绑定引导v3-零内容一键体验方案.md) 的本地试听首屏和单卡站点确认不再生效。登录、扫描、首听的稳定性加固仍沿用 v3 已实现部分。

2026-08-02。v1（1.2.14 的书库选择页 + 首页激活卡）基础上的演进；基座复用 `BoundLibraryOnboardingStore`、Kindle 站点选择器（1.2.15）、`KindleLibraryRecoveryService`、空书架换站卡（多站点 P1）。激活定义不变：**30 秒真实播放**。

## 0. 两个先决判断

### 「强制」的边界：强的是引导，不是门

- **跳过必须存在**，两个硬理由：
  1. **App Review 5.1.1**：核心功能（粘贴/PDF/拍照朗读）不依赖账号，把 App 锁在第三方登录后面是标准拒审事由——我们刚拿到干净的 4+/Education 记录，不值得赌；
  2. **意图错配**：ASA/ASO 进来的流量以 pdf / articles / dyslexia 词为主，相当比例用户没有 Kindle。对他们强制亚马逊登录 = D0 流失，还没到首次价值就死了。
- 「强制感」的正确来源：**全屏接管、手势不可关、每屏唯一主按钮、异步步骤自动推进**——而不是拿走出口。跳过做成右上角细字，点了进入通用导入引导（v1 的次级路径），不是死胡同。
- 中文环境维持 v1 约定：微信读书在前（Kindle 向导同构复用）。

### 亚马逊登录是全流程最重的一步，设计必须围绕它减负

密码/2FA/验证码都发生在 Amazon 页面内（我们永远不碰凭据）。能做的：站点预选正确（少一次失败）、登录页上方悬浮引导条、**登录成功自动推进**（`id_pk` cookie 是 100% 可靠指标——见 kindle-auth-redirect 备忘）、失败走 RecoveryService 而不是让用户干瞪眼。

## 1. 五屏流程（每屏一个动作）

| 屏 | 内容 | 用户动作 | 自动行为 |
|---|---|---|---|
| **0 价值页** | 顶部标题「把你的 Kindle 书变成有声书」；中部极简插画表现“左侧 Kindle → 右侧有声读物”；主按钮「连接我的 Kindle」与次按钮「我没有 Kindle」固定在底部 | 点主按钮 | — |
| **1 选站** | 「你在哪个亚马逊买书？」+ 直接展示三个候选站点；按设备地区预选的站点高亮 | 点「就是这个」或直接换选 | 预选 = `KindleStorefront.suggested(deviceRegion, appLanguage)` |
| **2 登录** | 全屏 WKWebView（所选站登录页）+ 顶部引导条「在这里登录亚马逊——密码只提交给 Amazon，CastReader 不会看到」 | 在 Amazon 页面内登录 | **检测到 `id_pk` → 自动进入第 3 屏**；跳登录页异常 → RecoveryService |
| **3 扫描** | 「正在读取你的书架…已找到 N 本」实时计数 + 进度条 | 无（无按钮屏） | 扫描完成自动推进；**0 本 → 空书架换站建议卡**（一键回第 1 屏换站重扫） |
| **4 首听** | 书架网格 +「选一本，马上开始听」 | 点任意书 | 打开即 autoplay 第一页；30s 真实播放 → 激活 ✓，向导永久退场 |

交互纪律：顶部 step dots（1/4 起）；每屏**只有一个**主按钮；0 屏之后每屏保留「跳过」细字；每一屏的底部操作组必须贴安全区底部，中部内容通过弹性留白展开，不允许按钮卡在页面中段；返回键回上一屏（第 2 屏返回不销毁 WebView——绑定书库铁律）。

第 0 屏视觉纪律：极简、无说明段落；所有标题统一左对齐；插画位于页面中部，使用透明底 PNG，以橙色块面与黑色线稿直接落在 App 暖白背景上；主次按钮作为一个整体贴近安全区底部。插画只表达一个因果：左侧 Kindle 文字页（长短不一、全部为灰色的文字条）→ 单一橙色箭头 → 右侧耳机与书。禁止插画自带白底、重复书图标、声波纹和无语义装饰色块。

## 2. 异常与兜底

| 情况 | 行为 |
|---|---|
| 登录卡在 2FA/验证码 | 停留第 2 屏不催促；30s 无进展浮出「稍后完成」→ 首页 + v1 激活卡接力 |
| 亚马逊跳回登录页（已知偶发） | RecoveryService 自动恢复；两次失败 → 「稍后完成」 |
| 扫描 0 本 | 换站建议卡（设备地区优先候选）；换站= 回第 1 屏，会话不清 |
| 扫描超时（>60s） | 重试一次 → 仍失败「稍后完成」，书架后台继续 |
| 中途杀 App | `BoundLibraryOnboardingStore` 记录已达屏位；重启从价值页快速通道续接（不重复已完成步骤） |
| 跳过后 | 不再全屏出现；首页 v1 激活卡承接（现有行为） |

## 3. 度量（v1 的测量缺口一并补上）

v1 没有专属漏斗事件（契约里无 onboarding 事件）。v2 新增 2 个事件（契约+校验脚本+测试三件套同步）：

- `onboarding_step`：`{step: value|storefront|login|scan|first_listen, result: shown|done|skipped|failed, source: kindle|weread|other}`
- 激活仍复用现有播放管线（30s 判定在 Store 内），`onboarding_step{step:first_listen, result:done}` 与之对齐

北极星：**首启 → 30s 激活率**。护栏：D0 卸载率、第 2 屏 skipped 占比（>60% 说明登录太重，回退到软引导）。

## 4. 上线与验收

- 目标版本 1.2.16；无 A/B 基建，用 v1（1.2.14/15 安装 cohort）作前后对照，靠新漏斗事件读数。
- 验收脚本：新装（全新模拟器）→ 五屏直通 ≤90s 完成首听；跳过路径完整可用；`-CastReaderSkipLibraryOnboarding` 继续生效（采集/测试依赖它）。
- Android / 扩展：iOS 验收 + 漏斗读数两周后再对齐（v1 合同同款流程）。

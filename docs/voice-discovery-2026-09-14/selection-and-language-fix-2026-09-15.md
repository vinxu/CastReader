# 音色选择、发现语言与播放缓存修复 · 2026-09-15

中文发现推荐中文来源的音色，英文发现推荐英文来源的音色；推荐主体仍是常规音色，社区克隆仅进入独立的「精选音色」模块。来源语言用于推荐，`supportedLanguages` 用于判断能否生成，两者互不替代。

## 统一使用规则

| 音色 | 选择入口和存储 | 朗读 / 解读 | 额度 |
|---|---|---|---|
| 常规（Kokoro） | 发现 / 全部音色 → 对应语言偏好；清除该语言的个人音色覆盖 | 朗读按内容语言，解读按讲解输出语言读取同一偏好 | 保持已有免费 / Pro 规则 |
| 社区克隆（`vl_`） | 精选 / 全部音色 → 一次应用至该音色支持的输出语言；移除这些语言的个人音色覆盖 | 保留原 `vl_` ID，进入受保护的生成 API | 成功生成消耗月额度 |
| 录制 / 朋友授权（`vc_`） | 我的声音 → 校验账号、授权、Pro、能力和额度后，应用至支持的输出语言 | 保留原 `vc_` ID，进入相同受保护的生成 API | 成功生成消耗月额度 |

克隆跨语言共用是本次采用的默认规则。选回常规音色只覆盖它对应的语言。浏览语言切换本身不再修改音色选择。试听仅播放预生成样本，不修改偏好、不调用文本生成、不消耗生成额度；正式使用的音色通过独立的选择操作确定。

目前 API 中的社区克隆支持 10 种输出语言（中、英、日、韩、德、法、西、葡、意、俄），不能把“多语言”解释为包含未支持的语言。全部目录仍可搜索到这些音色，使用前保留语言检查。

## 发现与运营

- `referenceLanguage` 保留到 iOS；旧数据可从唯一的 `previewLanguages` 原始语言回退，再回退至 `language`。
- 不能仅使用 `language`：部分韩语、俄语原始音色在旧目录被编码为英语兼容条目。
- 运营仍只有中国区 / 国际区。两个区域分别发布包含中文 6 个、英文 6 个的精选候选池；客户端按发现语言显示对应 6 个。
- 当前区域精选子专题保留「名人风格 / 角色演绎 / 自然旁白」。常规专题、顺序和插画保持现有运营内容。
- 全部音色使用「常规音色 / Curated voices」两个 Tab；搜索覆盖全部 283 个常规与 1,323 个社区音色，不再受当前发现语言截断。
- 搜索继续使用后台索引、120ms 防抖、有限结果缓存；界面使用 LazyVStack。没有在主线程增加全目录扫描。

## 已定位的播放问题与修改

1. 原来社区 / 个人音色只写入浏览语言。选英文声音后朗读中文仍读中文旧偏好。现在克隆一次应用至实际支持的语言。
2. 个人与常规 / 社区偏好分两次发布，播放端可能读到中间状态。现在统一提交两份偏好后发布一次 `voiceSelectionRevision`，朗读 / 解读在提交完成后响应。
3. 非活动的朗读 VM 保留旧音频，恢复时直接装回。音色变化会清空这份音频缓存，保留阅读位置供新声音恢复。
4. 解读块没有音色身份。现在每个 `PreparedBlock` 保存真实生成时的 voice ID，正常入队、预取结果入队、所有权恢复、重播都核对该 ID；不匹配时只重生成音频，保留讲解文字和标注。
5. 解读切换失败以前会重新装入旧声音。现在停止旧音频并显示失败；点击重试复用已有讲解文字，仍请求已选的新声音。
6. API 本身已用 `vc_ / vl_` 判断克隆鉴权与路由，没有发现强制改回 Kokoro 的逻辑；修正了只把 `vc_` 标记为 clone 的误导性调试日志。三类 ID 的 `voice` / `voice_code` 编码已验证。

# 语音管线延迟优化：实施与验证

2026-09-18。源码：`codex/mobile-voice-explore-20260914`，`febfeab` 加本地增量补丁。本轮不提交 App Store，不改变服务端并发、额度或计费规则。

## 逐项实现

| 阶段 | 实现 | 收益的验证方法 |
| --- | --- | --- |
| 1. 增量预读 | 同一 `SpeechStreamBuffer` 从后台预读晋升到前台播放；第一片可播即可转正，尾片继续追加。成功、失败、暂停、过期回调分别处理 | 可控 HTTP 将尾片延迟 1.7 秒；真实 AVPlayer 在尾片返回前已播放下一段首片。覆盖文本、EPUB、PDF、微信读书、Kindle、Kobo、Google Play 图书、O’Reilly 共用 VM。尾片 500 后只重试未完成内容 |
| 2. 从当前位置换声 | 校验原段文本、旧音频文本与当前片段；只请求当前短片段起点后的后缀。已读前缀保留文字/时间戳上下文，不保留无用音频。优先用实时播放游标，避免等待历史写入。目标声音缓存限制 3 项/8 MiB，并校验账号边界 | 请求正文必须不含已读前缀；目标位置、高亮上下文、暂停意图保留；换回已完成声音不得产生新 HTTP 请求。中文拆片、英文拆词/合词仍走原有验证恢复 |
| 3. 按秒预读 | 共用有界窗口取代只给 Kindle 常规音色的特殊全段预读。按倍速、实际音频时长及生成耗时工作；约 12–20 秒目标，最多 8 个后续段落；额外段文字上限 1600。未消费音频请求前检查 4 MiB/64 片约束 | 短段测试：第 6 段的慢请求在当前第 0–1 段时开始，按顺序每段仅生成一次。长段缓冲满或暂停后不新增请求。窗口缩小时保留已经发出的工作，不取消重发 |
| 4. 解读短块与观测 | 能唯一对应讲解文字的标注，与最多 180 字符的讲解短块一同准备、定时、发布；后续只追加，已播标注时间不重算。新块与换声复用同一底层生产接口、优先级及背压；保留旧快道 | 第二讲解短块延迟 1.8 秒时，第一块已播放且原文标注已触发；第二块到达后第一块标注时间不变。歧义/改写标注继续使用原有整块服务端 compose，不声称所有解读都已经流式化 |

请求前背压允许已经发出的单片返回，所以内存/时长预算存在最多一个响应的超出量，不是 HTTP 响应硬截断。前台与后台保留原有调度上限，没有用大幅增加并发换取流畅。

## 位置与失败边界

- 无法证明音频文字与原文前缀一致时，不裁剪请求；保留原有位置验证和可解释的恢复入口。数字展开、重复文字、不同分片边界不能用猜测字符偏移替代验证。
- 被裁去的前缀只作为显示/定位上下文，不进入播放队列。音色缓存命中也必须先验证目标片段存在真实音频。
- 中文无词时间戳时允许重读已验证短片段；不能从旧声音的秒数推测新声音的字位置。英文词级位置继续由 processedText 与 timestamps 确认。
- 朗读预读晋升后，尾片失败不触发段落完成；保留续传检查点，重试不重复已播前缀。解读短块失败显示错误，不把部分块误报为整个块完成；失去所有权后不恢复已失效的半块缓存。
- 解读语音规范化导致锚词不能精确对应时，仅在这个已确定的短块内使用已有均匀定时降级；不改写此前发布的标注时间。无法在讲解中唯一归属的原文标注从一开始就保留服务端 compose 路径。
- 平台提取、手动翻页确认、页间恢复和 DOM/PDF/OCR 定位逻辑未替换；共享的是语音生产与预读。平台真实登录/页面渲染测试与可控生产者测试分别记录。

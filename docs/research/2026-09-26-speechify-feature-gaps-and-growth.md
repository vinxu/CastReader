# Speechify 功能缺口与 CastReader 增长机会调研

调研日期：2026-09-26。本报告保留竞品能力与评论证据，功能补齐只是增长假设，不能据此承诺追上 Speechify 的用户规模。

> **同日更新：执行优先级已修正。** 经用户指出基础能力大多已完成，并复核 CastReader 的最新完整搜索数据后，本文后面的“先补官网文件入口／先做 PDF 学生入口”和功能 P0／P1 排序不再作为当前行动建议。当前以[定位与验证方案](./2026-09-26-castreader-positioning-and-validation.md)为准：保留 Kindle／EPUB 手机主轴，优先验证 AO3／Wattpad 的新增听读用户，先建立来源、实际使用与重复使用的证据，再决定功能投入。下文原建议作为研究过程记录保留，不等于已核实的产品待办。

**证据边界。** 未找到 Speechify 按功能划分的 DAU、渗透率、留存或收入贡献。官网“60M+ Users”是厂商规模口径，不能当作月活或付费人数，更不能归因给某个功能。本报告用官方功能文档证明“有此能力”，用公开用户评论证明“有人实际使用或明确需要”，以产品判断安排优先级；三者不混同。[Speechify 官网](https://speechify.com/)、[Apple 开发者访谈，2026-03-03](https://developer.apple.com/news/?id=xjifig9f)。

CastReader 跨端边界可核对 [官网 Integrations](https://castreader.com/integrations) 与 [统一进度设计及交付记录](/Users/xuxuheng/Documents/CastReader/docs/Unified-Listening-Progress-System-2026-09-09.md)。旧文档只作为历史证据，跨端未完成的判断还结合当前公开说明与主线本机存储实现；已有云文档 API 不被忽略。

**若目标是扩大用户量，还应先修复一个比新功能更直接的入口。** Speechify 提供无需安装扩展的浏览器文件朗读入口。CastReader 当前公开 Integrations 页面明确标记 castreader.com 的上传工具不可用，并将本地文件用户导向扩展或手机。这里的差距是公开入口和首次价值路径，不是说 CastReader 没有 Web 后端代码。[Speechify Web 操作指南](https://speechify.com/blog/ultimate-guide-to-the-speechify-web-app-for-text-to-speech/)、[CastReader 当前说明](https://castreader.com/integrations)。

建议把一个来源打通：搜索“PDF read aloud / listen to research papers”→打开落地页→上传自己的文本型 PDF→开始听并看到高亮→明确保存后在手机继续。先服务一个常见文件类型，不承诺所有 PDF、复杂扫描和超大文件。上线前实际核验身份、文件访问与首听流程；本报告没有改动入口或发布网站。

这条路径可能同时提高网站访客激活率和手机新增，也为云文库创造真实需求。其增长效果需要测量，不能仅因 Speechify 有 Web App 就断言它是该产品增长的主要来源。

**目标人群建议。** 先挑“需要完成大量 PDF/教材阅读的学生与专业人士”做一个清晰获客入口，同时保留 Kindle 长篇听书为已有优势场景。Apple 的访谈确认学生是 Speechify 早期用户的重要组成部分，但未给出当前占比。[Apple 访谈](https://developer.apple.com/news/?id=xjifig9f)。对注意力困难用户，应把卖点落在跟读、少操作和可靠恢复，不作治疗或效果保证。

CastReader 已有“原文讲解标注”“自己/亲友的声音”“多来源书库”三个可继续验证的区别点。将其转成可展示的实际任务：读懂一段难文、用喜欢的声音连续听完一章、第二天一键回到原处。近期 Speechify 评论为“简单可靠的朗读”和“私人声音可持续使用”提供了竞争线索，不足以证明 Speechify 全体用户都想迁移。

**建议执行顺序。**

1. 先核查当前真实首听漏斗：自己的内容是否顺利导入、首音等待、第一分钟内失败或退出、第二天能否找到进度。保留按来源、国家、版本分组的数据。历史增长文档不能当作今日数据。
2. 修复公开 Web 文件首听路径，并用任务明确的 PDF 落地页验证新增。继续提高英文 1.5–3× 长文听感、跨页连续性和错误恢复；这些是竞争资格。
3. 完成普通文章/PDF 的“保存→另一设备出现→从准确位置继续”。它比同账号 Pro 同步更能把多端产品连起来。
4. 按真实反馈在“通用高品质离线”和“永久笔记”中选下一项；离线面向通勤与重度收听，笔记面向学习复习。不要两者全量并行后才发现没人用。
5. 复用 Explain 加入选段追问与小测验。通用语音输入、会议助手、AI Work、播客发现流留到有独立需求证据后再投。

**衡量方法。** 北极星建议采用“每周至少 3 天、累计有效收听至少 30 分钟的用户数”，同时保留更轻用户的激活与留存指标；这是拟议口径，不是行业标准。首听漏斗看上传/导入成功率、真实首音延迟 P50/P95、用户内容连续收听满 60 秒的比例。跨端看保存到另一设备首次成功播放的转化和恢复准确率。离线看真正发生的断网播放成功率及重复使用，不看下载按钮点击量。笔记/测验看 7 天内回看与复习，而非生成次数。任何功能组留存更高都可能受重度用户自选择影响，应以可控实验或明确的前后 cohort 验证增量。

第一轮可以邀请 8–12 位目标用户做任务测试，寻找操作障碍，不把这样的小样本当增长显著性结论；没有另行授权，不自动联系任何用户。若现有流量不足以做 A/B，先运行单一版本，固定口径并观察成熟 cohort。获客、留存和付费需要分别验证，不用评价数、下载数或免费试用数替代活跃用户。

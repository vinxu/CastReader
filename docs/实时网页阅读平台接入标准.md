# CastReader 实时网页阅读平台接入标准

> 版本：1.1（2026-07-29）  
> 适用平台：Google Play Books、Kobo、微信读书、Kindle Cloud Reader，以及后续通过 WebView 接入的在线阅读平台。  
> 参考实现：Google Play Books iOS 与 Kobo iOS。平台专有细节见
> [`GooglePlayBooks-iOS适配方案.md`](./GooglePlayBooks-iOS适配方案.md) 和
> [`Kobo适配-产品技术与Android实施规范.md`](./Kobo适配-产品技术与Android实施规范.md)。

## 1. 目的与边界

CastReader 是 TTS 工具，不是另造一套书城或阅读器。实时网页阅读平台接入的目标是：

1. 用户在平台自己的网页中登录并保留其合法会话。
2. CastReader 同步书架元数据，并从书架打开官方阅读页。
3. 只读取当前真实可见页，提供朗读、解读、词级高亮、自动翻页和手动翻页续播。
4. 平台网页继续负责排版、版权控制、翻页和账号安全；CastReader 不落库正文，不绕过访问控制。
5. 新平台只实现平台适配器，不复制一套播放、解读、额度或 UI 状态机。

本文中的关键词：

- **MUST / 必须**：不满足即不能认为接入完成。
- **SHOULD / 应当**：默认必须实现，只有可说明且可降级的技术限制才能例外。
- **MAY / 可以**：体验增强，不影响基本正确性。

## 2. 统一产品合同

### 2.1 入口、绑定和书架

每个实时网页阅读平台必须满足同一产品流程：

```
选择阅读平台
  → 打开平台官方登录/书架页
  → 确认登录态
  → 持续扫描并同步书架
  → 从 CastReader 书架打开官方阅读页
  → 朗读 / 解读
```

产品要求：

1. 平台入口与 Kindle、微信读书同级展示；首次询问“平时在哪里看书”时使用同一选择模型。
2. 绑定页必须明确显示当前阶段：登录、等待书架、同步中、同步完成或可恢复错误。
3. “找到 0 本书”只能在**已确认登录、已进入我的书架、虚拟列表扫描到末尾且 DOM 稳定**后展示。
4. 加载中得到的空结果、网络错误、部分虚拟列表或页面尚未渲染，必须视为“不完整快照”，不能覆盖旧书架。
5. 绑定后的条目必须展示平台书架；点击书籍必须恢复其规范化阅读 URL 和阅读锚点。
6. 解除平台绑定默认只删除 CastReader 内的平台书架、进度和账号关联，不清共享网页登录态。
7. 清除平台/Google 网页登录态必须是单独且明确的操作，并说明会影响哪些平台。

### 2.2 朗读

朗读必须具备：

- 当前可见页的准确文本提取；
- 流式 TTS、词级高亮和自动播放；
- 页内预生成下一段音频；
- 读完当前页后自动翻页，并在新页继续；
- 跨页断句：一句话跨页时不重复、不漏读、不抢跑；
- 手动滑页时立即暂停旧页，确认新页后按原播放意图继续；
- 手势回弹时恢复原页、原音频位置和原高亮；
- 进入后台、Web 内容进程重启、iframe 替换后的可恢复行为。

### 2.3 解读

解读必须与朗读并列存在，不能因接入新平台被隐藏或退化为原文朗读：

- LLM 讲解内容由 TTS 播放；
- 标注落在当前页原文的稳定字符坐标上；
- 解读完成当前页后自动翻页并继续；
- 模式切换必须转移播放器回调所有权，旧模式不能继续发音、翻页或绘制标注；
- 可预取下一页首个解读块，但只能在新页真实提交且身份完全匹配后消费。

### 2.4 统一播放器体验

1. Web、PDF、Google Play Books、微信读书等入口的底部播放器，应与 Kindle 的紧凑高度和布局对齐。
2. Loading 图标必须显示在原橙色播放按钮内部，不能用纯 Loading 控件替换整颗按钮。
3. 短暂的句间切换必须防抖；只有真正进入可感知等待后才显示 Loading，避免按钮闪烁。
4. 播放器和字幕不能遮挡正文。正文可用区域应消费播放器的**实测高度和安全区**，不能依赖固定猜测值。
5. 登录过程开始后，绑定提示卡和大按钮必须隐藏或收起，不能覆盖密码、Passkey、2FA 等官方页面。

## 3. 分层架构

一个平台接入必须被拆成下列职责，平台专有代码不得渗入共享播放器：

| 层 | 统一职责 | 平台适配职责 |
|---|---|---|
| Session Profile | 持久 Web 数据分区、Cookie 生命周期 | 所需 UA、允许域、登录页/书架页 |
| Library Adapter | 绑定状态、增量合并、账号切换 | 登录证据、书架 DOM、虚拟列表遍历 |
| Reader Adapter | 当前页事件、翻页意图、生命周期 | 正文 frame、可见页、物理翻页动作 |
| Page Extractor | `VisiblePageSnapshot` | DOM/Canvas/OCR 到稳定源坐标的映射 |
| Native Coordinator | 朗读/解读、预加载、翻页状态机 | 不包含选择器和站点 DOM |
| Renderer Bridge | 高亮、标注、清理 | DOM Range、Canvas bbox 或图片 bbox |
| Diagnostics | 统一事件和关联 ID | 可加不含凭据的平台诊断字段 |

建议的统一平台接口语义：

```text
connect()
disconnectLocalState()
scanLibrary() -> PartialOrCompleteLibrarySnapshot
open(book, anchor)
observeVisiblePage() -> VisiblePageSnapshot
requestTurn(direction, identity) -> Accepted | Rejected
renderHighlight(sourceRange, pageIdentity)
renderMarks(sourceRanges, pageIdentity)
destroy()
```

平台适配器不得直接：

- 调用 TTS/LLM 后端；
- 决定 Pro 或额度；
- 独占共享音频播放器；
- 用 URL 变化代替页面提交；
- 因网络错误自动解绑；
- 持久化正文。

## 4. 登录、Passkey 与网页会话

### 4.1 会话复用的正确边界

1. 同一平台族的 WebView 必须显式复用同一个持久数据分区：
   - iOS：固定标识的 `WKWebsiteDataStore`；
   - Android：同一 App WebView profile、`CookieManager` 和持久存储。
2. 绑定、书架和阅读器必须使用同一分区，否则用户会重复登录。
3. 平台解绑不得删除该共享分区。
4. App 原生 Google OAuth 登录与 Google 网页 Cookie 是两套凭据。原生 OAuth token **不能**注入 Google Play Books 来冒充网页登录。
5. 同一持久 Web 分区内，如果用户已经登录 Google，其他使用 Google 网页登录的平台通常可以快速确认账号；是否仍要求二次验证由 Google 决定。

### 4.2 Passkey

Passkey 页面由 Google 和系统认证服务控制。适配器必须遵守：

- 不读取、不保存密码、Passkey、验证码或 token；
- 允许官方页面打开弹窗、新窗口或系统认证界面，并保证它们复用同一 Web 配置；
- 失败后保留“尝试其他方式”，不能制造死循环；
- 不能承诺直接复用手机 Google App 中的账号或 Passkey；
- 记录认证路径、页面域名和成功/失败分类，但不得记录账号或凭据。

WKWebView/Android WebView 中的跨设备 Passkey 可能因依赖域、系统凭据提供方、蓝牙邻近验证、
RP ID 或 WebView 能力限制而失败。产品降级策略是保留官方替代认证路径，并通过持久网页会话
把这次登录的成本摊薄到后续平台，而不是自行接管 Google 凭据。

### 4.3 登录页 UI

1. 底部原生“登录”按钮必须触发与网页可见登录入口**同一个语义动作**，不能只关闭弹层。
2. 一旦进入 `accounts.*` 或官方认证阶段，原生登录卡必须隐藏。
3. 登录完成后不能停在白屏。必须识别返回书架/阅读器、弹窗关闭和主 WebView 恢复三条路径。
4. 登录过程中的 SwiftUI/Compose 重组、主题变化、前后台切换不得无条件 reload，从而替换正在认证的 document。

## 5. 书架同步合同

### 5.1 快照模型

书架扫描结果必须带：

```text
accountIdentityHash
books[]
isAuthenticated
isLibraryContext
reachedVirtualListEnd
isDOMStable
isComplete
observedAt
```

完整快照要求所有可信证据同时成立。否则只能增量合并：

| 场景 | 允许新增/更新 | 允许删除旧书 |
|---|---:|---:|
| 正在加载 | 是 | 否 |
| 网络失败 | 否或部分 | 否 |
| 虚拟列表未到底 | 是 | 否 |
| 未确认账号 | 是（暂存） | 否 |
| 完整且同账号快照 | 是 | 是 |
| 可信账号切换 | 新账号重建 | 只清旧账号的平台数据 |

### 5.2 元数据和隐私

- 只保存书名、作者、封面 URL/缓存、平台书 ID、规范阅读 URL、进度和账号单向摘要；
- 平台书 ID 和 URL 必须规范化并校验允许域；
- 不保存邮箱原文、Cookie 值、正文或认证 token；
- 封面使用项目统一持久缓存，避免列表滚动反复下载。

## 6. 正文 frame 与桥接安全

Google Play Books 的主页面只是壳，正文位于跨源
`books.googleusercontent.com` iframe；Kobo 则把 EPUB 章节放在
`readnow.kobo.com` 顶层页面下的同源 `srcdoc` iframe，并预加载多章。两者都必须遵守：

1. iOS 需要在必要时 `forMainFrameOnly: false` 注入；Android 需用受控 frame relay 或平台允许的消息通道。
2. 主壳只能转发，不能运行通用正文提取器，否则会把工具栏、目录和登录 UI 当正文。
3. 每个正文 frame 创建不可复用的 `frameSessionID`。
4. native 只接受当前 owner frame 的正文、高亮和翻页事件。
5. 所有消息校验：
   - 允许的 origin/host/path；
   - 消息 schema 与版本；
   - frame session；
   - 当前书和页面身份；
   - 当前模式/epoch。
6. Android `addJavascriptInterface` 暴露面必须最小化，不允许向任意导航后的页面暴露通用 native 能力；销毁时必须移除接口。

同源也不等于同一个 JavaScript realm。Kobo 顶层脚本访问章节 iframe 时：

- 不能用顶层 `node instanceof HTMLElement` 判断 iframe 中的节点；
- DOM Range 必须由 `element.ownerDocument.createRange()` 创建；
- 样式必须从 `element.ownerDocument.defaultView` 获取；
- overlay、解读 SVG、动画帧和滚动坐标必须属于 Range 的 `ownerDocument`；
- 换页时必须遍历所有曾绘制过的 owner document 清理旧高亮和 marks。

Kobo 的后续 iframe 是官方预加载缓冲区，不是“当前页之后的朗读队列”。正文快照只能来自
当前真正与外层 viewport 相交的 iframe/列 fragment；屏外 iframe 最多用于只读、可校验的
一页或一句预览。

## 7. 当前可见页模型

### 7.1 `VisiblePageSnapshot`

统一快照至少包含：

```text
platform
bookID
frameSessionID
pageSignature          // 不透明 wire identity，逐字节保存
contentFingerprint     // 当前真实可见正文的内容指纹
paragraphs[] {
  sourceParagraphID
  sourceStartUTF16
  sourceEndUTF16
  visibleText
  speechText
  geometry
}
language
layoutDirection
capturedAt
```

硬约束：

1. `pageSignature`、`turnID`、`frameSessionID` 等身份字段是**不透明值**，不得 `trim`、大小写转换或重新序列化。
2. DOM 存在不等于可见；预渲染区、透明副本和屏外列不能进入当前页。
3. 同 URL 不等于同一页；URL 的 `pg` 也不能作为唯一提交证据。
4. 同指纹 refresh 只重建 DOM/Canvas 映射，不重启音频或 LLM。

### 7.2 裁剪

Google Play Books 会把整个 segment/章节放入 DOM，再依赖 CSS columns/clip 显示一页。
因此必须按元素字符 Range 的实际矩形与阅读内容视口求交，而不是读 `.textContent`。

裁剪规则：

- 同时处理横向列、纵向裁剪、双栏和竖排书；
- 内容下边界由当前阅读面动态计算，不能硬编码工具栏高度；
- 一行/块只有在其 block-axis 至少约 98% 可见时才属于当前页；
- 被底部裁掉的半行必须整体留给下一页；
- 极小交集矩形、排版测量副本和控件文本必须排除；
- 高亮使用与提取相同的源坐标与可见性过滤。

### 7.3 跨页句

为了自然语音，当前页末段可以把 `speechText` 延伸到自然句末，但必须同时保留：

- `visibleEndUTF16`：当前页最后真实可见字符；
- `speechEndUTF16`：本次实际生成语音的句末；
- `sourceParagraphID`：稳定源段落；
- 已消费游标：新页裁掉已经说过的前缀，且恰好消费一次。

预读延伸不得改变当前页可见正文，也不能让标注画到屏外。

## 8. 翻页身份和状态机

### 8.1 自动翻页身份

每次自动翻页都生成：

```text
turnID
baselineSignature
originFrameSessionID
direction
modeEpoch
```

请求、接受、失败、迟到提交必须完整匹配。JS/native 可为慢动画保留短期 tombstone，
但旧 frame、旧模式或另一个请求不能借迟到结果接管页面。

### 8.2 提交证据

1. 物理翻页动作每个语义请求只执行一次。
2. 可从按钮、按键、热区选择一个动作；超时后不得再补发另一动作，否则可能跳两页。
3. 只有**稳定的新可见页证据**才能提交：
   - 新 signature/fingerprint；
   - 仍属于发起请求的 frame；
   - 布局稳定窗口通过；
   - 内容非空或有可信书末证据。
4. 超时不是成功，也不能清书架、清登录或自动重试多次。

### 8.3 手动翻页

1. 可信 pointer/touch/key intent 出现时立即暂停旧页。
2. 用户仍按住时不能因短 watchdog 恢复旧页。
3. 回弹到严格基线时恢复原音频位置和原高亮。
4. A → B → C 的连续滑动只提交最终稳定页，不在 B 重启。
5. 新页提交后，只有手势前正在播放才自动续播。

## 9. 页尾音频、高亮和翻页的硬边界

这是所有实时网页平台的 P0 正确性约束。

### 9.1 正常页尾（没有跨页句）

必须按下面的顺序执行：

```
最后一个音频 item 实际播放完成
  → 保留最后词高亮到完成边界
  → 请求一次物理翻页
  → 新页稳定提交
  → 清旧页视觉并由新页接管
  → 消费预加载音频或开始新页生成
```

禁止：

- 根据 `duration - 0.65s` / `duration - 0.85s` 等固定 lead 提前翻页；
- 在 AVPlayer/ExoPlayer 报告 item end 之前清掉最后一句高亮；
- 因下一页音频已缓存而提前提交下一页。

### 9.2 真正跨页的一句话

若同一条不可变音频包含当前页尾和下一页页首：

1. 用 TTS 的**词级时间戳**找到当前页最后一个可见词的 `endTime`。
2. 到达该精确边界时暂停/gate 同一音频。
3. 保留旧页最后可见词高亮，发起一次翻页。
4. 新页稳定提交后，将同一音频从边界继续播放，并由新页接管剩余词的高亮。
5. 若时间戳无法可靠映射，必须降级为等待整个 segment 播放完成再翻页，不能用 UTF-16 字符比例抢跑。

字符比例 `duration × visibleChars / speechChars` 只能作为诊断估计，不能作为物理翻页权威。

### 9.3 高亮所有权

- 页面处于 `turnRequested/pageChanging` 时，不能无条件抑制当前页最后词高亮；
- `clearPageVisuals()` 只能发生在音频边界和页面交接协议允许的时刻；
- 新页提交后旧页 overlay 必须销毁，不能残留；
- carry sentence 的新页高亮必须使用新页 DOM 坐标，不能继续画在旧页；
- 翻页、模式切换、WebView 销毁都必须取消迟到的高亮回调。

## 10. 预加载合同

预加载是性能优化，不是页面真相。

### 10.1 可以预加载什么

- 当前页后续段落 TTS；
- 可证明属于下一视觉页的首段/整页 TTS；
- 下一页首个解读 block；
- 平台阅读器外壳或静态资源。

### 10.2 消费门槛

预加载产物必须绑定：

```text
sourcePageIdentity
predictedNextFingerprint
voice
speed generation parameters
language
mode/depth
text fingerprint
request epoch
```

只有新页提交后全部匹配才能消费，否则丢弃。不得为了命中缓存：

- 物理翻页预览 iframe；
- 改变 Google/平台当前分页状态；
- 把预测页当成真实页；
- 跳过当前页剩余文本。

### 10.3 没有整页预览时

平台若不给出下一页完整 DOM，可以只做：

- 当前页内下一段流式生成；
- 当前 segment 的单句 source preview；
- 翻页后立即提取并从已缓存的 carry sentence 接续。

此时产品上应称为“页内预加载/跨页句预备”，不能声称完整下一页已经预加载。

## 11. 解读状态机

1. 解读输入永远来自当前已提交页的完整可见文本，不受朗读跨页已消费游标影响。
2. 每个解读请求绑定页面 fingerprint、模式 epoch、语言和深度。
3. `onDocumentFinished` 只能由当前激活的 Explain VM 处理一次。
4. 解读页结束后遵守与朗读相同的严格翻页身份和提交协议。
5. 下一页预取在预测与真实页不一致时必须失效并重新生成。
6. 切回朗读时，解读的音频、marks、翻页请求和迟到回调全部取消。

## 12. 生命周期与资源释放

必须区分：

- **暂停/最小化**：保留当前 WebView 以支持恢复和后台播放；
- **替换/关闭**：显式销毁。

`destroy()` 必须：

1. 取消 Task/协程、timer、观察器和网络请求；
2. 移除 JS message handler / JavascriptInterface；
3. 移除 user scripts；
4. 摘掉 delegate/client；
5. `stopLoading()`；
6. 清理 Combine/Flow 订阅；
7. 销毁附属/弹窗/恢复 WebView；
8. Android 从父 ViewGroup 移除后调用 `WebView.destroy()`。

不能把拆除只写在 `deinit`、`finalize` 或依赖 GC。连续打开五本书时，任意时刻必须只有一个活跃阅读器实例继续联网。

前后台规则：

- 后台暂停物理翻页确认计时；
- 页尾在后台到达时，动作延迟到前台且只执行一次；
- Web 内容进程重启后恢复书、URL/锚点、模式和播放意图，不能自动从头播放；
- 从点击书到可读内容出现，全程有稳定 loading，不裸露白屏。

## 14. 测试与验收矩阵

### 14.1 纯契约测试

- opaque identity 含前后空白时仍逐字节匹配；
- 一次语义翻页只执行一次物理动作；
- 迟到结果只能由原 turn identity 接收；
- 不完整书架快照不能删除旧书；
- 预加载只有全维度匹配才消费；
- 模式回调单一所有权；
- normal 页尾必须等待 item end；
- cross-page 仅可靠词时间戳可提前到可见词边界；
- 时间戳不可靠时 fail closed。

### 14.2 Web fixture

- 主壳 + 单层/多层跨源 frame relay；
- 双栏、横向 CSS columns、纵向页、竖排；
- 3.5 行可见：半行必须完整留到下一页；
- 固定/动态底栏高度；
- 排版测量副本和极小交集矩形；
- 慢翻页动画、回弹、A → B → C 连滑；
- iframe owner 替换、旧 iframe 迟到消息；
- URL 不变但页面改变、URL 改变但内容未提交；
- 高亮在旧页清除和新页接管的准确时点。

### 14.3 真机门禁

每个平台至少覆盖：

1. 全新网页分区登录；
2. 已登录快速确认；
3. 密码/Passkey/2FA 或替代路径；
4. 书架首屏、虚拟列表到底、空书架；
5. 冷启动从书架开书；
6. 朗读首音、词级高亮、自动翻页；
7. 页尾最后一句完整播完且高亮不提前消失；
8. 跨页句不重读、不漏读；
9. 手动滑页立即暂停、回弹恢复、新页续播；
10. 解读、marks 和解读自动翻页；
11. 模式连续切换；
12. 前后台、断网恢复、Web 内容进程重启；
13. 关闭重开恢复锚点；
14. 解绑后网页登录仍保留；
15. 连续换五本书，无残留 WebView。

## 15. 已踩过的坑

| 坑 | 根因 | 标准处置 |
|---|---|---|
| 登录按钮只让弹层消失 | 原生 CTA 没触发官方语义入口 | CTA 与网页入口共用动作并验证导航 |
| 认证页被底部卡片遮挡 | 登录提示未随阶段隐藏 | 进入 auth 后收起 |
| 登录后白屏 | 弹窗/主页返回状态未收敛 | 识别三条返回路径并保留 loading |
| 页面未出来就显示 0 本书 | 把第一次空扫描当完成 | 完整快照门槛 |
| 解绑清掉其他 Google 登录 | 误删共享 data store | 本地解绑与网页退出分离 |
| 期待 App OAuth 直接登录网页 | 混淆 OAuth token 与 Web Cookie | 只复用持久网页会话 |
| Passkey 默认失败 | WebView/依赖域/跨设备能力限制 | 官方替代路径 + 保留后续会话 |
| 主页面工具栏被朗读 | 壳 frame 使用通用提取器 | origin/path 分流，壳只 relay |
| 整章一页读完 | 读取被 CSS 裁剪的 `.textContent` | Range 几何裁剪 |
| 底部半行被切掉 | 任何相交都算可见/固定 guard | 98% block 完整度 + 动态 clip |
| 旧页高亮残留 | 页面提交后未销毁旧 overlay | 明确高亮所有权交接 |
| 最后一句高亮提前消失 | 提前 lead 清视觉并翻页 | normal 等 item end；cross 用词时间戳 |
| 播着播着静止且无 Loading | 队列等待态和 UI 防抖不一致 | `moreSegmentsExpected` + 延迟 Loading |
| 体感无预加载 | 只有页内流式或预测不能消费 | 区分预备、命中和真实提交日志 |
| 翻页跳两页 | 超时后换另一动作重试 | 每语义请求一次物理动作 |
| 恢复 URL 丢 `pg` | URL 规范化/重载过度 | 保存完整可信锚点 |
| signature 含空白匹配失败 | 把 wire identity 做了 trim | opaque identity 不变换 |
| 旧 WebView 越积越多 | 依赖析构/GC | 显式 destroy |
| 解读切换无反应 | 共享播放器回调所有权错乱 | activate/deactivate 单一所有权 |
| Kobo 从章节开头读而非当前页 | 只选可见 iframe，未裁 iframe 内 CSS columns | 对元素 fragment 做 outer viewport 投影与字符 Range 裁剪 |
| Kobo 把整本预加载章节一起读 | 遍历当前 iframe 及其后的所有 iframe | 当前快照只读真实可见 frame；预览严格限一页/一句 |
| Kobo 手动翻页检测不到 | 只看 iframe 内容，transform 翻页时 DOM/URL 不变 | signature 使用当前可见源切片，监听触摸意图并稳定提交 |
| Kobo 高亮画到顶层或不显示 | iframe Range 坐标与顶层 document 混用 | overlay/SVG 使用 Range 的 owner document/window |
| Kobo 自动翻到下一章或跳两页 | 优先 next chapter，或同一请求轮换按钮/按键 | 排除 chapter 控件；每个 turn 只执行一种物理动作一次 |

## 16. Android 落地映射

Android 应复用现有 Kindle/微信读书的共享能力，但必须保持本合同语义：

| iOS | Android |
|---|---|
| `WKWebsiteDataStore` | App WebView profile + `CookieManager` |
| `WKUserScript` all frames | 受控 iframe relay / 平台脚本注入 |
| `WKScriptMessageHandler` | 最小化 `JavascriptInterface` 或 WebMessage |
| AVPlayer item end | ExoPlayer `STATE_ENDED` / media item transition |
| Combine/Task epoch | Flow/coroutine Job + generation epoch |
| `destroy()` 摘 delegate | remove interface/client、detach、`WebView.destroy()` |

Android 特别注意：

- `evaluateJavascript` 默认只在主 frame，不能假定可以直接操作跨源正文 iframe；
- JavascriptInterface 在导航到非白名单页面时有安全风险；
- ExoPlayer 的缓冲完成不等于播放完成，物理翻页必须等待真实媒体边界；
- Activity/Fragment 重建不能重复创建并同时保留多个 WebView；
- 系统返回、手势返回、键盘和网页横滑需要与阅读翻页手势仲裁；
- Cookie 共享和平台解绑的产品语义必须与 iOS 一致。

## 19. iOS 可复制实现与 Kobo 基线

### 19.1 共享骨架

新商业网页阅读平台不得再复制 Google Play Books 的 native 状态机。iOS 当前共享骨架为：

| 实现 | 职责 |
|---|---|
| `CommercialWebSession` | App 级持久 `WKWebsiteDataStore`；绑定、书架、阅读器和 OAuth popup 共用 |
| `LiveWebPlatformID` | source kind、UA、主导航白名单、脚本消息白名单、错误/进度路由 |
| `WebReaderView` | 根据 profile 注入平台脚本并创建 WebView |
| `WebReaderBridge` | 单一朗读/解读、预加载、跨页句、自动/手动 turn 状态机 |
| `cr-bridge.ts` | page-local DOM 映射、词级 Range、高亮与 marks owner-document 渲染 |
| 平台 reader adapter | 当前页提取、signature、翻页物理动作、手势观察 |
| 平台 library adapter/store | 登录证据、稳定书架快照、账号隔离、本地解绑 |

当前为了安全迁移，Kobo reader adapter 使用成熟的 `googleBooks*` 私有 wire event 和
`gbNextPage/gbRefresh` 调用名，但所有 payload 都带 `source: "kobo"`。这些名字是兼容层，
不是新平台继续复制 Google 专有类型的理由；后续可在不改变行为合同的前提下统一改名。

### 19.2 新平台最小实现清单

复制下一平台时，应只新增：

1. `LiveWebPlatformID` profile 和严格 URL/origin/message policy；
2. 绑定/书架扫描脚本、模型、store 与薄 UI；
3. reader DOM adapter：`extract()`、`signature()`、`next/prev once`、手动翻页观察；
4. 平台 URL/书架/页面纯合同测试和真实 DOM fixture；
5. 入口、设置、文库过滤和 analytics 枚举映射。

不得新增第二个 TTS VM、Explain VM、播放器、播放器 UI 或 native 翻页协调器。

### 19.3 Kobo DOM 合同

Kobo reflowable 书的已知结构和处理方式：

- 顶层：`https://readnow.kobo.com/<UUID>`；
- 正文：多个同源 `srcdoc` iframe，章节内常见 `.koboSpan[id]`；
- 分页：iframe/章节内 CSS columns，加顶层 transform/官方 page control；
- source identity：章节逻辑属性 + 首尾 `koboSpan` + 段落序号/内容的稳定哈希；
- current page：外层 viewport 与 iframe 交集映射回 iframe 坐标，再按 Range fragment
  得到 UTF-16 可见切片；
- signature：只由当前可见源段 ID 与 UTF-16 范围组成，不能使用像素动画坐标；
- 自动翻页：只找 page control，显式排除 chapter control；按钮、按键、热区只选一种；
- 手动翻页：触摸/边缘点击/页键发 intent，transform 稳定后提交；回弹到 baseline 即取消；
- 预加载：优先只读相邻视觉页；几何不可证明时只预取一个 source-order 句子；
- fixed-layout/canvas 书：明确显示暂不支持，不能把 OCR 或工具栏文本冒充 DOM 正文。

### 19.4 扩展参考的使用边界

成熟 Kobo Chrome 扩展是选择器、iframe 可见性、词级高亮和翻页控件的行为基准，但移动端
接入不能原样复制它的长队列策略。应复用：

- 最大 viewport 相交面积选择当前 iframe；
- per-fragment 可见性，而不是整段 bounding box；
- 词走到屏外列时使用 Kobo 官方 next-page 语义；
- 自动翻页与用户翻页分离。

必须改进：

- 不能从当前 iframe 一直收集后面所有预加载章节；
- 不能仅用 iframe 内容长度/首段文本作为页变化 signature，因为 transform 翻页时内容不变；
- 不能优先点击 next chapter；
- 不能在一次 turn 超时后再换另一物理动作补点。

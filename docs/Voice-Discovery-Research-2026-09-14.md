# 音色发现：先理解供给，再设计内容流

2026-09-14。按用户最新要求，本轮先分析实际音色，不继续修改界面。本文件更新此前“常规 / 精选”两组的产品方向；现有接入、额度、语言及播放合同仍可复用。

**结论**

CastReader 应让用户发现“我愿意用来听这篇内容的声音”。Kokoro 和社区声音共同参与场景专题，使用权益作为每个声音的明确属性。社区声音增加风格、辨识度和同一声音跨语言使用的选择；Kokoro 继续承担日常持续朗读，也应得到有吸引力的策展。两者不构成天然的音质高低排序。

线上 Kokoro 数量依据服务端目录，不依据客户端离线 fallback。目录统一标为 kokoro，其中也包含 CastReader 扩展训练的音色。

克隆的样本语言与合成语言必须分开。当前 1,323 条 on_demand 记录返回的是相同的 10 语言配置，这不是 13,230 次逐声音、逐语言质量验收。不能把德语样本声音从中文朗读候选中直接排除，也不能把英文样本声音自动当成英语教学的发音标准。语言设置表达“读哪种语言”，样本语言只保留为内部来源信息。

## 标签揭示的机会与缺口

以下仅统计 1,323 条社区素材，标签可以重叠，不能相加成总音色数。

| 已有用途标签 | 条目数 |
|---|---:|
| 旁白 | 377 |
| 教学 | 239 |
| 故事 | 233 |
| 角色配音 | 154 |
| 广告 | 106 |
| 对话 | 92 |
| 播报 | 91 |
| 纪录片 | 58 |
| 游戏 | 45 |
| 播客 | 7 |
| 冥想 | 5 |
| 有声书 | 1 |

“有声书”只有 1 条标签，不代表只有 1 个适合读书的声音。当前标签由原描述和来源标签规范化抽取，不是统一听评；应该结合旁白、故事、节奏、清晰度再筛选。播客、冥想目前不宜仅凭字面标签做大规模常驻频道。

明确的缺口：

- 941 条有从原描述整理的风格信息；382 条（28.9%）只剩性别、年龄、时长等信息，没有有效的音色、表达、语速或用途标签。518 条（39.2%）没有用途标签。自动将全部条目硬塞进专题会产生伪精确分类。
- 社区男声 861、女声 321、中性 42、未知 99。原始供给的比例不是首页推荐必须照搬的比例；在质量和相关性合格的前提下，需要照顾声音的多样性。
- 1,323 个 ID 对应 1,147 个规范化名称；Arnold 同名 13 条、Adam 10 条。Kokoro 和社区之间也有 Adam、Sarah 等重名。名称是素材别名，不是人物身份依据。同名不同录音不能直接合并。
- Kokoro 的 100 条中文描述只有 27 种不同文本；英文 67 条有 50 种描述。重复的“清晰自然、适合长篇”难以帮助选择。部分多语种描述还带有“共享解码器修复版”等实现信息，展示前需要去除。
- Kokoro 的 Pro 标签与音质不是同一维度，例如免费 Heart 的目录等级为 A；收费声音中存在更低目录等级。不同来源的等级也未统一校准。不能用“普通 / 高级”替代真正的声音介绍。
- 公开目录的默认排序使用 rank、ID，不足以支撑“热门”“大家都在听”等人气文案。

## 推荐的组织方式

使用三层结构：长期存在的场景入口、可轮换的编辑专题、用于筛选和推荐的细粒度标签。每个声音可属于多个场景；每条声音的 ID、头像、收藏和选中状态保持统一。

长期场景先围绕 CastReader 的朗读与解读产品：日常文章、知识讲解、故事叙事、轻松陪伴。角色感作为探索兴趣入口。广告、游戏已有供给，可以留在全部音色与专题中，但不必主导工具型朗读产品的首屏。

细粒度标签保留三个用户能感知的方向：音色（低沉、明亮、温暖、柔和）、表达（沉稳、活泼、亲切、戏剧感）、节奏（舒缓、平稳、轻快）。语言、声线、使用权益作为独立筛选维度。未知值留空，不用头像或名称补猜。

依据现有标签做了五组可复现的候选召回：

| 专题方向 | 社区候选数 | 召回依据与评选重点 |
|---|---:|---|
| 把复杂内容听明白 | 244 | 教学/纪录片 + 清晰/沉稳/平稳/专业；继续验证数字、术语、停顿与跟读 |
| 听出故事里的画面 | 220 | 旁白/故事 + 表现力/戏剧感/低沉/共鸣/神秘；继续验证叙事自然度与长段稳定性 |
| 温柔一点，慢慢听 | 99 | 温暖/温柔/柔和 + 沉稳/亲切/平稳/舒缓/流畅；不能仅凭慢语速认定耐听 |
| 像朋友讲给你听 | 88 | 对话/自然交谈 + 亲切/自然交谈/沉稳；听是否过度播音或夸张 |
| 给文字一点角色感 | 146 | 角色/游戏 + 俏皮/戏剧感/表现力/活泼；验证实际生成能否保留特色 |

这些是元数据候选池，既非互斥分类，也非正式上线名单。完整 ID 与召回规则已保存，后续可以精确复核。

Kokoro 加入同一套评选，例如 Heart、Bella 的现有描述适合进入明亮平稳候选，Nicole 进入沉稳舒缓候选，Lachlan 进入温暖自然候选。社区“于琳-专家”的温暖、清晰、温柔、平稳标签，可同时进入讲解与陪伴候选；“Arland”可同时进入讲解与故事候选。以上都是基于描述的评选起点，不是本轮听评结论。

此外，Kokoro 的现有目录包含英、美、澳、美国南方、菲律宾英语等标注，可以形成口音专题的候选来源；口音专题需要实际发音复核，不能把声音原籍、素材语言和目标语言口音混为一谈。

## 内容流怎样服务发现

首批建议选择约 24–36 个声音建立经过试听复核的首页内容池，Kokoro 与社区共同参与；这只是编辑池，不是把完整库缩到几十个。完整可用目录继续通过搜索、场景和“查看全部”进入。主列表按用户选定的朗读语言筛出实际可用声音。

内容流可按“少量声音快速比较 → 一个有视觉主题的专题 → 一组直接试听的声音 → 下一个专题”的节奏交替，而不是把每个区块都做成大横幅，也不是所有区块使用相同列表。

| 用户此刻的问题 | 内容形式 | 内容规则 |
|---|---|---|
| 先听哪个？ | 3 个声音的紧凑推荐组 | 风格差别明显，直接试听，不让同一声音连续重复出现 |
| 这类内容适合什么声音？ | 故事、讲解等主题大卡 | 一句短标题，点击进入真正的精选集；卡片不是说明书 |
| 我喜欢这种听感，还有吗？ | 温柔、低沉、明亮等横向声音组 | 同方向内也保留性别、节奏、表现方式的差异 |
| 想听个新鲜的 | 少量角色感或特色声音 | 不挤掉日常朗读入口；不把最夸张的声音当默认推荐 |
| 想一直用熟悉的声音 | 最近、收藏；场景内可筛不使用月额度 | 保留用户习惯，让长期使用回到低摩擦路径 |

首屏不强制按库存比例随机混排。先满足目标语言可用、实际试听就绪和相应场景质量，再结合用户偏好、已有收藏和新鲜感安排顺序。额度状态影响推荐，但不偷偷替换已选声音。没有行为证据时使用“编辑推荐”“声音专题”，不虚构热度或个性化理由。

## 把“听出区别”作为核心交互

同一目标语言提供相同的 8–12 秒对比文本；对讲解、故事等专题再提供一段匹配场景的实际生成示例。参考录音用于内部选材，不能替代主按钮的实际朗读试听。所有展示为可选的语言都应有对应的预生成试听或明确的可用状态，不把在线生成失败留给用户试错。

试听同一时间只播放一个声音，切换快、响度可比，试听不更改正在使用的朗读声音。选择动作明确设置当前声音；收藏随声音 ID 绑定。卡片只显示名称、一个有区别的短描述、使用权益和播放控件，详细标签留到详情或筛选。

“同一声音读中文、英文等”是社区声音很有价值的展示专题。用同一个声音的两种实际语言示例让用户听到能力，比在头部说明模型原理有效。跨语言效果仍需按声音复核。

## 权益怎样简短但不隐瞒

使用权益贯穿专题、搜索、收藏、最近和播放器。月额度声音使用统一时钟标记和“月额度”短标签；不只标 Pro，因为常规 Pro 声音与月额度声音的使用规则不同。

用户进入详情或选择月额度声音时，给出一行具体信息，例如“所有月额度声音共享 2 小时/月 · 本月剩余 76 分钟”。月额度按生成计量，预生成试听和已有音频重播不重复扣除。余额必须来自实际账号状态，不能用套餐总额伪装余额。

对 Pro 用户常规声音可表达“不限时”；免费用户不能看到暗示免费无限用的文案。提供“不使用月额度”的筛选，使用户可以主动规划长时间朗读。额度用完保留声音选择，提供可明确选择的常规替代声音。

首页不再承担解释完整权益制度的任务，但每次遇到声音都应能认出它是否使用月额度。

## 下一步工作的顺序

1. 用现有标签召回各专题候选，补齐一条真正可区分的本地化短描述；对缺少风格信息的 382 条先补证据。
2. 从两套目录挑选约 24–36 个候选做统一文本与场景文本的实际生成试听，检查风格、清晰度、重复漏读、长段稳定性及朗读同步。优先验证首批目标语言，随后扩展。
3. 形成首批专题的具体声音名单与内容编排，确认每个声音有独立价值，再落地不同样式的推荐区块。
4. 上线后关注试听到选用、收藏、持续使用，以及因额度意外中断的比例；评价发现是否有效，不能只看用户点击了多少卡片。

本轮完成全量元数据盘点、标签来源追溯和候选池召回，没有逐条试听全部声音、没有付费生成、没有修改 UI 或上线目录。这些供给分析已足够确定组织方向，具体推荐名单仍需实际声音评选。

# 微信读书跨页延迟与完整字幕

日期：2026-09-20。本轮使用 iPhone 镜像、真实《茶花女》、曹操音色、线上解读/TTS 验证；没有运行模拟器，没有提交或发布。

## 11 秒花在哪里

原始 11.649 秒是从新页确认到实际播放：请求准备 0.031 秒、讲解生成 4.030 秒、进入 TTS 0.021 秒、三段 TTS 6.587 秒、标注时间计算与入队 0.858 秒、播放器启动 0.122 秒。翻页动作本身约 0.19 秒。瓶颈是生成没有被上一页的播放时间覆盖，不是页面动画用了 11 秒。

真机定位到两种缺陷：

1. **手动翻页后的预读丢失。** 正文候选要等待 600 ms 再提交；JS 紧接着发送新页的下一页预读。原生仍用旧页指纹校验，直接丢弃新预读，JS 去重后不再重发。沿“暂停朗读 → 下一页 → 切解读 → 曹操 → 自动翻页”复现 12.372 秒。
2. **尚未完成的预读被取消重做。** 第一轮修复后继续多播，在第二章再次复现 11.010 秒。预读最后一段 TTS 于 10:30:28.207 返回，10:30:28.663 页面提交时标注合成尚未结束，因此缓存被当作 miss、任务取消，并在 10:30:28.696 重新请求整个计划，直到 10:30:39.673 才播放。

旧路径需要完整音频来计算标注时间。在预读缺失时，这些成本全部落在翻页后。

## 修复

- 手动候选未提交时，最多暂存一份提前到达的预读；只有匹配页面真正提交后才启用，保留 600 ms 的页面稳定确认。
- 预读任务加入代次校验，旧任务的取消/失败回调不能清空新任务。
- 将实际生成任务与预读观察任务分开。页面、正文、语言、音色、深度匹配时，新页接管尚未完成的生成，不再重复请求计划与 TTS。
- 等待属于新页的内容代次；换页、切模式、停止会取消所属任务，旧完成结果不能启动新页。另设 15 秒异常等待保护；正常完成仍按最终音色/语言设置再次验证。
- 不放宽正文匹配阈值，不为了缩短时间提前播放未完成标注时间计算的内容。

## 字幕省略原因与修复

字幕逻辑已经分句，但公共气泡以及普通阅读横屏仍强制 `lineLimit(1)` 和尾部省略，较长分句、长英文词串仍会被 UI 截断。问题在显示层。

现在保留完整文本并自动换行；气泡底部固定在播放栏上方，向上扩展，不挤压固定 72 pt 播放区域，不触发正文重新分页。横屏复用同一气泡，Kindle 共用组件同步适配。真机已看到完整两行长字幕，无省略号，字幕变化时正文位置不变。

## 仍存在的等待与验收边界

- 首次进入解读仍需云端生成，第一轮观测约 10.53 秒；本轮没有加速云端模型。
- 跨章节、过短页后的新内容，或预测正文与实际页不匹配时，仍可能等待约 7–9 秒。这是后续需要优化的预读覆盖范围，不能称为所有跨页均秒播。
- 本轮验证聚焦微信读书的两个延迟缺陷和字幕显示，不代表微信读书全部验收、Kindle 共享字幕或全部语言与横屏真机回归完成。

证据目录：`reports/ios-weread-latency-caption-20260920`。包含两次包的源码身份、原始/第一轮/最终时间线、逐次跨页测量和验证范围；原始控制台留在 `/tmp/castreader-weread-pending-fixed-console.log`，未将登录/会话字段保存到报告。

# CastReader 用户与付费漏斗

> 目标：用同一套链路理解用户如何开始、在哪里失败、为什么留下，以及在什么价值基础上付费。本文不定义具体事件名。

## 1. 总漏斗

| 阶段 | 用户状态 | 进入条件 | 成功条件 | 主要问题 |
| --- | --- | --- | --- | --- |
| 发现 | 打开 App，但还没有阅读意图 | 首次或回访启动 | 选择一个内容来源或恢复内容 | 首页是否让用户知道下一步做什么？ |
| 内容意图 | 已选择 Kindle、文件、网页、照片或文本 | 确认来源 | 内容开始处理 | 哪个入口最符合用户需求？ |
| 内容就绪 | 内容已处理为可阅读状态 | 解析 / OCR / 同步成功 | 阅读器可展示正文 | 哪类内容失败最多、最慢？ |
| 首次播放 | 用户尝试朗读或解读 | 点击朗读 / 解读 | 首音或首块开始播放 | 用户是否能快速听到第一句话？ |
| 首次价值 | 用户开始体验核心能力 | 首次播放成功 | 完成有效阅读会话 | 为什么有人只听几十秒就离开？ |
| 深度使用 | 用户持续阅读 | 首次价值完成 | 继续更长时间、切换模式或完成内容 | 哪些功能与深度使用相关？ |
| 恢复与留存 | 用户有未完成内容或新需求 | 再次打开 App | 再次完成有效阅读 | 历史、继续阅读和 Kindle 恢复是否可靠？ |
| 付费意图 | 用户遇到真实 Pro 需求 | 额度或权益触发 / 主动升级 | 进入购买流程 | 哪个触发时机合理，哪个过早？ |
| 付费成功 | 用户完成购买 | StoreKit / Web 购买成功 | 获得统一权益并继续使用 | 购买后是否立即得到预期价值？ |
| 续订 | 用户完成一个订阅周期 | 权益仍有效 | 成功续订并继续有效使用 | 用户是因为持续价值续订，还是忘记取消？ |

## 2. 内容入口漏斗

不同来源的问题完全不同，不能合并成一个“导入成功率”。

### Kindle

```text
看到 Kindle 模块
→ 点击绑定或打开书架
→ Amazon 页面可用
→ 完成登录 / 同意
→ 书架同步成功
→ 选择书籍
→ 正文打开并恢复位置
→ 首音播放
→ 连续阅读
```

重点观察：

- 绑定入口点击率；
- WebView 打开、登录、同步各阶段流失；
- 失效书籍恢复成功率；
- 书籍打开和正文识别成功率；
- 首音延迟、翻页连续性和恢复位置准确性；
- Kindle 首次价值率、D7 留存和人均阅读分钟。

Amazon 登录取消属于用户取消，不算系统失败。不得采集 Amazon 凭据、页面正文、书名或 Kindle DOM。

### 文件与重排文本

```text
打开快速导入
→ 选择文件类型
→ 文件选择完成
→ 读取 / 解压 / 解析成功
→ 阅读器展示
→ 朗读或解读首段播放
```

PDF、EPUB、DOCX、TXT 必须分开分析，并按文件大小或解析后文本长度分桶。不得记录文件名或正文。

### 摄像头与相册 OCR

```text
选择拍摄 / 相册
→ 权限结果
→ 获得图片
→ OCR 得到可读段落
→ 阅读器展示照片与文字
→ 朗读或解读首段播放
```

重点区分权限拒绝、用户取消、没有识别到文字、识别失败和后续 TTS / 解读失败。不得上传图片、OCR 文字或图片元数据到分析系统。

### 网页、粘贴文本与剪贴板

```text
输入或接受剪贴板提示
→ 确认朗读 / 解读
→ 文本提取或文档构建成功
→ 阅读器展示
→ 首音或首块播放
```

只记录来源枚举、是否成功、长度桶和耗时；不得记录完整 URL、剪贴板或输入正文。

### 历史与继续阅读

```text
看到历史 / Mini Player / Kindle 恢复入口
→ 打开未完成内容
→ 恢复阅读位置
→ 继续播放 ≥3 分钟
```

这是判断 CastReader 能否形成习惯的关键链路，应单独观察恢复入口曝光、点击、恢复成功、继续播放和位置错误。

## 3. 朗读价值漏斗

```text
阅读器就绪
→ 用户发起朗读
→ 首段 TTS 返回
→ 音频开始播放
→ 词级 / 句级高亮正常跟随
→ 播放达到 3 分钟
→ 达到有效阅读阈值
→ 达到 10 / 30 分钟或完成内容
→ 下次恢复
```

每个阶段要分开记录意图、成功和结果：

- 用户点击后立刻取消，不等于 TTS 失败；
- 队列等待下一段不等于播放完成；
- 切到后台不等于离开；
- 用户读完短内容不足 5 分钟，仍可能是成功；
- 额度耗尽属于商业限制，不属于系统质量失败。

关键分析问题：

1. 首音延迟增加时，3 分钟到达率下降多少？
2. 高亮和自动滚动正常的会话是否更容易达到 10 分钟？
3. 后台播放用户的周使用和留存是否更高？
4. 不同语言、音色和速度的持续播放差异是什么？
5. Kindle、长 PDF 和短网页是否应该使用不同的“完成”定义？

## 4. 解读价值漏斗

```text
可解读内容就绪
→ 选择解读场景
→ 发起 extract-plan / fast block0
→ 首块讲解可播放
→ 首个 mark 成功展示
→ 首块播放完成
→ 开始第二块
→ 完成当前解读范围
→ 回到朗读或继续下一批
```

关键分析问题：

1. 哪些场景有高发起率但低首块完成率？
2. 等待时长与首块完成率之间的关系是什么？
3. mark 成功展示是否与解读完成率相关？
4. 用户在哪些内容来源更愿意从朗读切到解读？
5. 用户是一次性解决难点，还是连续听完整篇讲解？
6. 免费解读次数是否足以让用户理解其价值？

解读服务的 401、402、计划失败、首块失败、后续块失败、TTS 失败和锚定失败必须分阶段观察，不能归为一个 `quickread_failed`。

## 5. 留存漏斗

```text
首次有效阅读
→ 当天继续或开始第二份内容
→ 次日再次有效阅读
→ 一周内再次恢复或开始新内容
→ 连续两周成为 WMRU
→ 形成稳定周频
```

留存分析需要区分：

- 同一内容恢复与新内容开始；
- Kindle 长期阅读与短网页一次性消费；
- 朗读用户、解读用户和混合用户；
- 首次成功与首次经历失败；
- 首次价值前是否遇到付费墙；
- 免费、StoreKit Pro、Web / Server Pro。

不能只看“再次打开 App”。如果用户回来但没有读起来，说明产品提醒或入口有效，但核心体验仍有问题。

## 6. 付费漏斗

### 6.1 付费前提

先把用户分为：

1. 尚未完成首次价值；
2. 已完成首次价值但使用较浅；
3. 已形成使用需求并触达限制；
4. 主动寻找 Pro 权益。

这四类用户看到付费页的意义不同，不能混合计算。

### 6.2 统一付费链路

```text
用户获得阅读价值
→ 触达明确的 Pro 需求
→ 付费页有效曝光
→ 查看权益和套餐
→ 选择月付 / 年付
→ 发起商店购买
→ 成功 / 取消 / 失败
→ 本地权益即时生效
→ 服务端统一权益同步
→ 购买后继续有效阅读
→ 续订 / 取消 / 退款
```

付费页触发原因至少分为：朗读额度、解读额度、Pro 音色、倍速、设置页主动升级。未来新增权益时继续使用受控枚举。

### 6.3 商业分析问题

1. 用户通常在累计多少有效分钟、多少次解读后购买？
2. 哪种付费触发转化最高，同时对留存伤害最小？
3. 是否有用户在首次价值前被付费墙打断？
4. 月付与年付用户购买前的使用行为有什么差异？
5. 购买后 24 小时内是否立即继续使用对应 Pro 权益？
6. 购买后 D7 / D30 没有有效阅读的用户占比是多少？
7. 取消和退款之前是否存在质量下降、权益不同步或频繁失败？
8. Web / iOS / Android 的权益归因是否一致？

### 6.4 付费实验护栏

任何付费页、额度或价格实验，除转化率外必须同步看：

- 首次价值达成率；
- WMRU；
- D1 / D7 有效留存；
- 付费页关闭后继续阅读率；
- 购买取消和失败率；
- 购买后 D7 使用率；
- 退款和客服投诉。

短期购买率上涨但首次价值、留存或退款恶化，不视为成功。

## 7. 核心分析切片

- 内容来源和格式；
- 新用户 / 回访用户；
- 匿名 / 登录；
- Free / StoreKit Pro / Server Pro；
- 朗读 / 解读 / 混合；
- 界面语言与朗读语言；
- 内容长度桶；
- 首音 / 首块延迟桶；
- 首次成功 / 首次失败；
- 付费触发原因；
- App 版本、OS 大版本和设备大类。

分群用于发现差异，不等于因果。功能是否导致留存或付费提升，需要后续实验或更严格的对照分析。

## 8. 定性观察计划

数据只能说明哪里发生了变化，不能完整解释为什么。每个版本保持一条轻量定性链路：

### 新用户可用性观察

- 每轮 5～8 位目标用户；
- 使用团队准备的无隐私样例 PDF、网页、照片和 Kindle 测试账号；
- 让用户独立完成“导入 → 听到首音 → 收起 → 恢复 → 尝试解读”；
- 观察犹豫、误解、失败后的反应和用户自己的语言；
- 不让研究人员读取或录制用户真实私人内容。

### 留存与流失访谈

- 每月邀请少量连续使用、使用一次后流失和已付费用户；
- 重点问他们原本想完成什么、为什么选择某种入口、何时觉得有价值、为什么停下；
- 不直接问“你想要什么功能”，优先还原最近一次真实使用过程。

### 支持反馈标签

客服和商店评论使用统一问题标签：导入、Kindle、首音、播放连续性、高亮、解读、语言 / 音色、额度、购买、权益同步、隐私和账号。定量漏斗异常时，能快速找到对应原始反馈。

## 9. 从漏斗到产品优先级

| 最大流失点 | 优先行动 |
| --- | --- |
| 内容意图低 | 优化首页表达、场景入口和示例，不先推付费 |
| 内容就绪率低 | 修解析、OCR、Kindle 同步和错误恢复 |
| 首音成功率低或太慢 | 优先优化 TTS 路由、预生成和加载反馈 |
| 首音成功但 3 分钟到达率低 | 检查音质、高亮、滚动、内容匹配和控制条 |
| 首次价值高但 D7 低 | 优化历史、恢复、Mini Player 和长期阅读连续性 |
| 已形成使用但 Pro 触达低 | 检查权益是否与高价值需求匹配 |
| Pro 触达高但购买低 | 检查套餐表达、价格、购买错误和信任问题 |
| 购买成功但后续使用低 | 检查权益兑现、跨端同步和误购 |

每个周期只选择一个主要瓶颈，避免同时改入口、额度、付费页和核心播放，导致无法解释结果。

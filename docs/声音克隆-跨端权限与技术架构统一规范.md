# 声音克隆跨端权限与技术架构统一规范

> 文档状态：V2 唯一合同（2026-08-27）
> 适用范围：CastReader iOS、Android、Chrome 扩展、castreader.ai、castreader.com 工具入口、全球区与中国区声音克隆服务。
> 关联规范：[Pro 一致性标准](./Pro一致性标准.md)
> 呈现身份子合同：[声音克隆名称与头像跨端合同 V1](./声音克隆-名称与头像跨端合同-v1.md)

本文是声音克隆功能的产品规则、权限判断、接口语义、额度结算、双区域部署和跨端交互的唯一依据。各端不得根据旧文案、旧字段或本地状态另行发明规则。

文中的“必须”“不得”是强约束；“建议”是实现方式，可以在不改变产品合同的前提下调整。

---

## 1. 先给结论

声音克隆必须拆成四项独立能力，任何端都不得把它们合成一个 `canUseVoiceClone`：

1. **创建与管理**：录音、提交、查看、删除自己的声音。
2. **固定试听**：播放服务端预先生成的固定示例，不能输入任意文本。
3. **应用**：把已创建声音用于朗读或解读中的任意正文。
4. **计费**：对成功生成的克隆音频按实际时长扣除 Pro 周期额度。

当前产品规则只有三条：

- 所有已登录用户，无论免费还是 Pro，均可创建多个自己的声音；创建不消耗 120 分钟。
- 免费用户可以创建、管理和固定试听，但不能把克隆音色用于朗读或解读；尝试应用时展示 Pro 付费墙。
- Pro（含 `trialing`）每个会员月度周期有 120 分钟，只有成功生成的克隆朗读/解读音频才按实际音频时长扣除。

因此：

- **120 分钟是使用额度，不是创建次数。**
- **没有“免费只能创建一个”“声音槽位”“删除后恢复名额”规则。**
- 创建暂时不可用，只能是登录、录音质量、并发提交或服务异常等技术原因，不能包装成会员或名额限制。

### 1.1 稳定规则编号

跨端代码、测试、产品验收和缺陷单统一引用以下编号：

| 编号 | 不可变规则 |
| --- | --- |
| `VC-P01` | 已登录免费和 Pro 用户均可创建多个声音 |
| `VC-P02` | 创建、管理和固定试听不消耗 120 分钟 |
| `VC-P03` | 免费用户应用克隆音色时展示 Pro 付费墙 |
| `VC-P04` | Pro/Trialing 每个会员月度窗口共享 7200 秒应用额度 |
| `VC-P05` | 只按成功生成音频的实际时长结算；失败和幂等重试不重复扣 |
| `VC-P06` | 额度耗尽保留声音和试听，提示恢复日期并允许切普通音色 |
| `VC-P07` | 全球与中国账号、数据库、存储、额度和 GPU 完全隔离 |
| `VC-P08` | 账号所属区域决定受保护请求线路，VPN/IP 不改变账号区域 |
| `VC-P09` | 服务端是权限、归属和额度唯一权威；客户端只做提前提示 |
| `VC-P10` | 临时服务故障不得清空声音、误报不存在或静默降级 |

## 2. 产品权限真值表

| 用户状态 | 创建/管理声音 | 固定试听自己的声音 | 应用于朗读/解读 | 应用后的额度处理 | 客户端主要提示 |
| --- | --- | --- | --- | --- | --- |
| 未登录 | 否 | 否 | 否 | 不扣 | 请先登录 |
| 已登录免费用户 | 是，可创建多个 | 是 | 否 | 不扣 | 选择克隆音色应用时展示 Pro 付费墙 |
| Pro，额度充足 | 是，可创建多个 | 是 | 是 | 成功后按实际音频时长扣除 | 展示已用、剩余、进度、恢复日期 |
| Pro，额度耗尽 | 是，可创建多个 | 是 | 否 | 不扣 | 明确额度已用完、恢复日期，并允许切换普通音色 |
| Pro 状态同步中 | 是，登录态有效即可 | 是 | 暂缓裁决 | 不扣 | 刷新权益；不得把 Pro 用户直接送到升级墙 |
| 创建任务正在进行 | 暂时不能重复提交同一账号的新任务 | 已有声音仍可试听 | 已有声音按权限正常使用 | 与创建无关 | “声音正在创建，请稍候”，不是“没有名额” |

| Worker/存储/网络故障 | 本次暂时失败，可重试 | 能播放缓存预览则保留 | 已有声音状态不得被清空 | 不扣失败请求 | 内联显示可重试错误，保留已有声音和选择 |

### 2.1 创建数量

- 当前不按免费/Pro 套餐设置创建数量上限。
- 客户端不得读取 `canCreate`、`freeCreationConsumed`、`nextCreateAt` 来决定商业创建资格。
- 服务端兼容期可以继续返回这些字段，但固定为：

```json
{
  "canCreate": true,
  "freeCreationConsumed": false,
  "nextCreateAt": null
}
```

- 技术防重不等于数量限制。服务端可以用短时创建互斥锁阻止同一账号同时重复提交；任务结束或超时后自动释放。

### 2.2 删除声音

- 用户只能删除自己有权管理的声音。
- 删除不恢复、也不消耗任何“创建名额”，因为当前没有创建名额。
- 删除必须清理数据库记录、Worker 注册信息、加密参考音频、编译提示和预览对象；异步清理失败必须进入可重试队列或告警。
- 客户端收到 `VOICE_NOT_FOUND` 时，只能移除对应的失效声音和对应选择，不能清空整个“我的声音”列表。

## 3. 唯一判断模型

### 3.1 四个权限分别判断

伪代码如下：

```text
canManageVoices = signedIn && routeLocalSessionReady

canCreateVoice =
    canManageVoices
    && !sameAccountCreationInFlight
    && recordingPassesContract

canPreviewVoice =
    canManageVoices
    && userCanAccessVoice
    && fixedPreviewReady

applyCloneVoice(text, voiceId) =
    if !signedIn                         -> AUTH_REQUIRED
    if !routeLocalSessionReady           -> INVALID_SESSION
    if !isProOrTrialing                  -> PRO_REQUIRED
    if remainingSeconds <= 0             -> CLONE_QUOTA_EXHAUSTED
    if !userCanAccessVoice(voiceId)       -> VOICE_NOT_FOUND
    if workerUnavailable                 -> CLONE_WORKER_BUSY
    else                                 -> READY
```

判断顺序必须稳定。尤其要避免：

- 免费用户因为声音存在性检查先失败而看到“声音不存在”，实际应该先看到付费墙。
- Pro 额度耗尽用户被当成免费用户展示升级墙。
- 临时 Worker 错误让客户端删除声音。
- 创建接口残留的旧 `canCreate=false` 阻断所有用户。

### 3.2 服务端是唯一裁决者

- 客户端的 Pro、额度、声音列表缓存只用于提前展示和减少无效请求。
- 服务端必须在每次创建、试听、朗读、解读请求中重新验证路由内登录态、资源归属、Pro 权益和额度。
- 客户端不得直接查询数据库或自行扣减权威额度。
- 客户端可以在收到成功响应及额度响应头后刷新本地显示，但服务端账本始终为准。
- 客户端缓存与服务端冲突时，必须按结构化错误修正局部状态，不得显示笼统“服务暂不可用”覆盖真实原因。

### 3.3 Pro 的统一定义

- iOS：`StoreKit 有效权益 || route-local serverPro`。
- Android：`Google Play 有效权益 || route-local serverPro`。
- Web 与扩展：route-local 服务端权益。
- `active` 和 `trialing` 都视为 Pro。
- 身份归一化遵循 [Pro 一致性标准](./Pro一致性标准.md)，但全球区与中国区账户、会话和数据库完全隔离，不能跨区拼接同一个用户。

## 4. 120 分钟额度合同

### 4.1 周期定义

- 上限固定为 `7200` 秒。
- 恢复时间跟随会员权益周期，不使用自然月的“每月 1 日”。
- 月度会员：以本次订阅周期开始时间为锚点。
- 年度会员：以年度权益开始时间为锚点，切分为连续的月度 120 分钟窗口，最后一个窗口不超过年度权益结束时间。
- 所有 UI 必须直接显示服务端返回的 `resetAt`，不得在客户端自己推算。
- 非 Pro 用户不拥有正文应用额度；其额度 UI可以隐藏或展示升级说明，不能伪造 120 分钟剩余值。

### 4.2 扣额原则

只在以下条件全部满足时扣额：

1. 用户是有效 Pro 或 `trialing`。
2. 克隆声音可访问。
3. Worker 成功生成可验证的音频。
4. 响应合同、MP3 和时间戳校验通过。
5. 服务端取得实际生成音频时长。

以下情况一律不扣：

- 创建声音、录音预处理、质量拒绝。
- 固定试听。
- 网络失败、用户取消、客户端超时、服务端超时。
- Worker 失败、CUDA/OOM、存储失败、响应合同失败。
- 幂等重试命中已有成功结果。
- 缓存音频重播。

### 4.3 预留、结算与幂等

```text
客户端生成稳定 X-Request-ID
        ↓
服务端校验登录 / Pro / 声音归属 / 请求合同
        ↓
按请求最大预估时长预留额度（短 TTL）
        ↓
GPU 生成并验证音频、时间戳
        ↓
按实际成功音频时长结算
        ↓
返回音频 + 最新已用/剩余/恢复时间
```

- 同一用户、同一 `X-Request-ID` 只能有一条账本记录。
- 同一请求 ID 如果文本哈希不同，必须拒绝，不能复用旧结果。
- 成功重试返回同一账本结果，不重复扣额。
- 失败、取消或过期预留必须释放。
- 客户端不能因为播放中断而“退额度”；扣额对象是成功生成的音频，不是实际听完的秒数。

### 4.4 额度展示

至少展示：

- `usedSeconds` / 已使用分钟。
- `remainingSeconds` / 剩余分钟。
- `limitSeconds = 7200`。
- `resetAt` / 恢复日期。
- 剩余百分比或紧凑进度条。

额度卡应紧凑，不制造焦虑。额度耗尽时必须提供：

- “本周期克隆音色额度已用完”。
- 明确恢复日期。
- “切换普通音色”操作。
- 保留已创建声音和固定试听。

不得：

- 给已经是 Pro 的用户弹升级墙。
- 静默回退为普通音色继续生成。
- 继续预取后续克隆段落，制造无效请求。
- 把额度耗尽显示成“服务暂不可用”。

## 5. 创建链路合同

### 5.1 录音与输入

当前版本只开放麦克风录制，不开放上传音频入口。

标准输入合同：

- 格式：WAV 或 FLAC。
- 建议客户端输出：24 kHz、单声道 PCM WAV。
- 时长：3–30 秒。
- 文件大小：不超过 4 MB。
- 引导文案：客户端按系统语言提供固定文案，用户需要准确朗读。
- Transcript：必须随录音提交，最多 600 字符。
- 录音语言：当前引导录音以中文或英文为主；创建后同一音色可在 10 种受支持朗读语言中使用。
- 支持语言：`de/en/es/fr/it/ja/ko/pt/ru/zh`。不得宣传所有语言效果完全相同。

### 5.2 客户端预处理

客户端应在上传前完成轻量、可解释的预处理：

- VAD 裁掉首尾静音。
- 选择有效单人语音段。
- 统一到单声道 24 kHz。
- 保守响度标准化并限制峰值。
- 只对轻中度稳定噪声做轻量降噪，避免过度处理改变音色。

预处理不能取代服务端质量门。服务端仍必须验证：

- 音量过低或过高。
- 静音占比。
- 背景噪声与信噪比。
- 削波失真。
- 明显混响。
- 多人说话。
- 引导文本与录音不匹配。
- 格式、时长和大小。

质量拒绝必须返回具体原因并允许立即重录；不能消耗 120 分钟，也不能被描述为“没有创建名额”。

### 5.3 创建状态机

```text
idle
  └─ record → preprocessing → local_quality_check
                              ├─ rejected → 可解释原因 → rerecord
                              └─ accepted → uploading/registering
                                                ├─ failed → 可重试，保留录音（短期）
                                                └─ active → fixed_preview_pending
                                                                  ├─ preview_failed → 声音仍存在，可重试预览
                                                                  └─ ready
```

要求：

- 进入页面或刷新列表失败时，不弹阻塞式通用错误并清空旧声音。
- 创建成功但预览失败时，不能把整个声音标记成不存在。
- 同一账号已有创建任务进行中时，服务端短时互斥；UI显示进度或稍后重试。
- 当前服务端互斥保护约 10 分钟，这是防重复提交，不是套餐限制。

## 6. 固定试听与正文应用必须分离

### 6.1 固定试听

- 免费和 Pro 均可试听自己已创建的声音。
- 试听使用服务端控制的固定文本或已持久化预览对象。
- 固定试听不接受任意用户正文，不扣 120 分钟。
- 预览不存在时可以触发预览重建；不得把预览 404 等同于声音记录 404。

### 6.2 朗读与解读

- 任意正文生成属于“应用”，只有 Pro 且额度充足时允许。
- 朗读和解读共享同一 120 分钟账本，不能各自再造一份额度。
- 普通预设音色不受克隆音色额度影响，原有 Kokoro/普通 TTS 管线不得回归。
- 中文、日文等方块字语言沿用句子高亮；英文等字母语言可以使用词级时间戳。这是渲染规则，不改变声音克隆权限和额度规则。

## 7. 双区域完全隔离架构

### 7.1 原则

全球区与中国区在以下层面完全隔离：

- 用户账号与登录会话。
- 数据库和声音记录。
- Pro 权益与 120 分钟账本。
- 对象存储和加密对象。
- GPU Worker 与队列。
- 监控、审计日志和故障域。

同一个自然人如果需要两区服务，必须分别登录/创建；不做跨区用户、声音或额度映射。

VPN、当前 IP 或设备位置不能切换已登录账号的区域。**登录账号所属线路决定所有受保护声音克隆请求的线路。**

### 7.2 全球区

```text
iOS / Android / 扩展 / Web
            ↓ route-local cms_ session
api.castreader.ai（全球控制面）
            ├─ 全球数据库 / 权益 / 账本
            ├─ Supabase 私有对象存储（AES-256-GCM 加密）
            └─ 美国区 GPU Worker
```

- 全球参考音频、编译提示和预览存入项目自有 Supabase 私有存储。
- 禁止使用归属未知的 Cloudflare R2，尤其不得再使用 `vidduo-ai` 账号或其 Bucket/密钥。
- 对象不能公开访问，下载必须经服务端授权或短时签名。

### 7.3 中国区

```text
iOS / Android / 扩展 / Web
            ↓ route-local cms_ session
api.castreader.cn（中国控制面）
            ├─ 中国区数据库 / 权益 / 账本
            ├─ 腾讯云 COS 私有对象存储（AES-256-GCM 加密）
            └─ 中国区 GPU Worker
```

录音上传流程：

1. 客户端用中国区会话请求 STS。
2. 客户端把临时参考音频直传私有 COS，减少控制面中转。
3. 临时对象 key 必须包含服务端签发的 canonical user 前缀。
4. 创建接口再次验证对象归属，读取并质量检查。
5. 服务端写入规范化、加密的正式对象和提示。
6. 临时对象在完成或失败后清理。

客户端不得自己拼 COS key、使用全球 token 请求中国资源，或根据 VPN 把中国账号发送到全球控制面。

## 8. API 唯一合同

### 8.1 当前公开路由

```text
GET    /api/voice-clone/voices
POST   /api/voice-clone/voices
DELETE /api/voice-clone/voices/{voiceId}
GET    /api/voice-clone/voices/{voiceId}/preview
POST   /api/voice-clone/captioned-speech
GET    /api/mobile/pro/status/v2
```

补充：

- 全球创建使用 multipart 参考音频；中国区创建使用经 STS 上传后的 COS 临时对象 key。
- `/api/voice-clone/speech` 是兼容期旧入口，不应成为新客户端主路径。
- iOS 在分批发布期间可以对旧预览接口做一次 404 兼容回退；全部生产端升级后应删除回退，避免双重语义。
- Markdown/文件朗读若选择克隆音色，也必须进入同一服务端权益和额度账本，不得单独实现。

### 8.2 必须发送的请求信息

- `Authorization: Bearer <route-local cms_ session>`。
- `X-Auth-Provider: session`。
- 生成请求必须有稳定的 `X-Request-ID`。
- 声音 ID、文本、语言、速度等业务字段。
- 中国区不得携带全球区会话，反之亦然。

### 8.3 响应与兼容字段

声音列表/权益响应应提供：

```json
{
  "voices": [],
  "isPro": true,
  "canApply": true,
  "cloneLimitSeconds": 7200,
  "cloneUsedSeconds": 642,
  "cloneRemainingSeconds": 6558,
  "cloneResetAt": "2026-09-14T00:00:00.000Z",
  "canCreate": true,
  "freeCreationConsumed": false,
  "nextCreateAt": null
}
```

其中：

- `isPro/canApply/clone*` 是运行时权限和额度字段。
- `canCreate/freeCreationConsumed/nextCreateAt` 仅为旧客户端兼容字段；V2 客户端不得用它们进行商业创建判断。
- 生成成功响应或响应头必须携带最新额度快照，便于所有端立即刷新显示。
- 所有错误响应必须有稳定的 `code` 和 `X-Request-ID`，不得只返回自然语言。

## 9. 错误码与统一交互

| 错误码/类别 | 含义 | 客户端动作 | 不得做的事 |
| --- | --- | --- | --- |
| `AUTH_REQUIRED` | 未登录 | 打开登录入口，登录后重试 | 当成服务宕机 |
| `INVALID_SESSION` / 401 | 会话失效或线路不匹配 | 刷新路由内会话；必要时重新登录 | 循环弹登录框、跨区借 token |
| `PRO_REQUIRED` | 免费用户尝试应用 | 展示 Pro 付费墙 | 阻止创建或固定试听 |
| `PRO_SYNC_REQUIRED` 或本地 Pro 收到 403 | 商店权益与服务端不同步 | 刷新权益并提供重试 | 给 Pro 用户弹升级墙 |
| `CLONE_QUOTA_EXHAUSTED` | Pro 周期额度耗尽 | 显示已用/剩余/恢复日期，切换普通音色 | 显示“服务暂不可用”或升级墙 |
| `VOICE_NOT_FOUND` | 指定声音确实不存在/无权访问 | 只清理该 voiceId，刷新列表 | 清空全部声音；用于预览对象 404 |
| `VOICE_CREATION_IN_PROGRESS` | 同账号创建任务在运行 | 保留页面和录音状态，稍后重试 | 显示“创建次数用完” |
| `VOICE_WORKER_BUSY` | 创建 Worker 繁忙 | 内联重试，保留录音和旧声音 | 页面开屏弹框、清空列表 |
| `CLONE_WORKER_BUSY` | 生成 Worker 繁忙 | 暂停预取并重试，保留当前音色 | 删除声音或静默换音色 |
| `QUALITY_REJECTED` 及细分质量码 | 录音未达标 | 展示对应原因并重录 | 扣额度、显示会员限制 |
| `REFERENCE_TEXT_MISMATCH` | 录音与固定文案不符 | 要求按文案重录 | 笼统说“服务异常” |
| `NETWORK_ERROR` / 5xx | 网络或服务临时故障 | 内联提示、保留状态、允许重试 | 清空声音、重复扣额 |
| `VOICE_SLOT_FULL` / `VOICE_CREATION_LIMIT` / `VOICE_FREE_CREATION_CONSUMED` | 旧版本残留语义 | 兼容映射为“配置暂未同步，请重试”，并上报监控 | 恢复“一人一个声音”的 UI 和逻辑 |

### 9.1 被动刷新不得开屏弹错

声音页打开、App 回前台或 Tab 切换时，列表/权益刷新失败：

- 显示上一次缓存数据和非阻塞状态。
- 可以提供“重新加载”。
- 不得立刻弹“声音服务暂时不可用”。
- 不得把缓存中的已有声音清空成“还没有创建的声音”。

只有用户主动执行创建、试听、选择或生成失败时，才针对该动作显示可理解的错误。

## 10. 各端职责边界

### 10.1 所有客户端共同职责

- 使用同一个 V2 权限模型，不复制服务端商业规则。
- 创建按钮只受登录/会话、创建互斥和录音合同影响。
- “我的声音”显示 Pro 标识，表达“应用需要 Pro”，不能表达“创建需要 Pro”。
- 免费用户选择克隆声音用于朗读/解读时展示付费墙。
- Pro 额度耗尽展示额度提示，不展示付费墙。
- 固定试听与正文应用调用不同接口/模式。
- 保留稳定 `X-Request-ID` 进行同一次生成的网络重试。
- 对服务端结构化错误做统一映射，不依赖 HTTP 状态猜测业务含义。
- 普通音色、播放、高亮、自动滚动、QuickRead 和缓存不能因克隆音色接入回归。

### 10.2 iOS

当前核心逻辑已按 V2 处理：

- 创建不再读取旧名额。
- 选择应用时区分登录、Pro 和额度。
- 克隆请求按账号所属线路发送。
- 404 只清理匹配的当前克隆声音。

仍需收口：

- 删除/停用所有“免费只能创建一个”“免费创建名额已使用”“暂时没有创建名额”等遗留本地化文案。
- 保证权限页、声音页和付费墙都使用同一份 ViewModel/错误映射，不在 View 内再次判权。

### 10.3 Android

当前存在旧逻辑偏差，必须迁移：

- `VoiceClonePolicy.canCreate(...)` 仍使用 Pro、服务端 `canCreate` 和 cooldown 作为创建门槛。
- Repository 仍可能把创建失败映射成 `VOICE_SLOT_FULL`。
- Created Tab 仍根据 capability 隐藏/禁用创建按钮。
- 测试仍断言“免费一个声音”。

迁移要求：

- `canCreate = signedIn && sessionReady && !creationInFlight && audioValid`。
- 忽略旧 `canCreate/freeCreationConsumed/nextCreateAt` 商业语义。
- 保留 Pro/额度判断只用于应用。
- 改写旧合同测试，新增与本规范第 14 节一致的矩阵测试。

### 10.4 Chrome 扩展

当前存在旧逻辑偏差，必须迁移：

- capability parser 仍从 `freeCreationConsumed/Pro` 推导 `canCreate`。
- 声音浏览器和创建页仍可能禁用免费用户创建。
- 多语言错误文案仍包含“一个免费声音/槽位已使用”。
- 脚本和浏览器测试仍断言旧规则。

迁移要求与 Android 相同，并额外保证：

- 扩展弹窗、侧栏、上传文件朗读页共用一份权限模块。
- 额度耗尽后停止后台预取。
- 浏览器重启、Service Worker 重启和缓存恢复不会重复扣额或丢失所选声音。

### 10.5 castreader.ai

- 是登录后的应用与全球控制面前端，维持 `noindex`。
- 工具页、声音选择、文本/文件朗读、解读、账户和价格页必须调用同一权限模块。
- 不得直接查数据库决定 Pro 或额度。
- 生成错误不得显示内部键或裸 `server_error_400`。

### 10.6 castreader.com

- 是公开内容、SEO 和工具入口，营销文案必须与本合同一致。
- 不得宣称“无限声音克隆”“免费使用克隆声音朗读”或“免费只能创建一个”。
- 若工具入口允许登录后使用克隆声音，必须调用 route-local 受保护接口和同一账本，不能建立第二套额度。
- `/ai-voice-generator` 的既有搜索意图与 `/voice-cloning` 分开，不能互相覆盖。

## 11. 数据、隐私与合规

- 用户必须确认录制的是本人声音，或已获得明确授权。
- 不允许把公开人物、第三方或未经同意的音频作为创建入口的正常用例。
- 参考音频、编译提示和固定预览必须私有存储并使用 AES-256-GCM 加密。
- 数据库只保存必要元数据和加密对象定位，不保存公开可访问的原始音频 URL。
- 所有管理、试听和应用接口都必须验证 route-local canonical user。
- 日志不得输出会话 token、STS 密钥、对象加密密钥或完整参考音频。
- 删除操作必须可审计，并对对象清理失败告警。
- 分享、赠送或邀请他人使用声音不属于当前公开产品合同；即使后端存在实验路由，也必须保持关闭或 feature flag，未经单独产品和合规评审不得在客户端暴露。

## 12. 禁止的实现方式

以下做法会直接导致“修东墙坏西墙”，全部禁止：

- 用单个 `canUseClone` 同时控制创建、试听和应用。
- 免费用户只能创建一个，或删除后恢复一个名额。
- 用本地 `UserDefaults`、SharedPreferences 或扩展存储记录权威创建资格/额度。
- 客户端按自然月自行计算恢复时间。
- 客户端先扣额度，失败后再尝试补偿。
- 每段重试生成新的 request ID，导致重复扣额。
- 看到任意 404 就删除当前声音。
- Worker/网络失败时清空“我的声音”。
- Pro 额度耗尽时弹升级墙。
- 免费用户点击“创建声音”时弹升级墙。
- 克隆失败后静默改用普通音色。
- 根据 VPN/IP 动态把已登录账号切到另一地区。
- 全球区与中国区共享用户表、声音表、对象存储或额度账本。
- 使用归属未知的 Cloudflare R2 或 `vidduo-ai` 资源。
- 各端自行翻译/硬编码一套错误文案而没有统一错误键。
- 后端兼容字段被新客户端继续当作产品规则。

## 14. 跨端端到端验收矩阵

每次修改声音克隆权限、Pro、登录、路由、存储、TTS 或播放器时，至少覆盖以下场景。iOS、Android、扩展和 Web 对共同场景必须得到相同业务结果；全球区和中国区分别跑一遍。

### 14.1 权限

| 场景 | 期望 |
| --- | --- |
| 未登录打开 Created/My Voices | 可显示登录引导，不循环弹框，不泄露缓存他人声音 |
| 免费用户第一次创建 | 成功，不出现付费墙 |
| 免费用户连续创建多个 | 均可进入正常创建链路，不出现槽位/次数限制 |
| Pro 创建多个 | 与免费创建规则相同，不扣 120 分钟 |
| 免费用户固定试听 | 成功，不扣额度 |
| 免费用户选择克隆音色朗读/解读 | 明确 Pro 付费墙，普通音色仍可用 |
| Pro 额度充足应用 | 成功并按实际音频时长扣额 |
| Pro 额度耗尽应用 | 不发后续 GPU 请求，显示恢复日期，允许切普通音色 |
| Pro 额度耗尽后创建/试听 | 仍可创建和固定试听 |

### 14.2 额度与幂等

| 场景 | 期望 |
| --- | --- |
| 生成成功 | 只扣实际成功音频时长 |
| Worker 失败/超时/OOM | 不扣，预留释放 |
| 客户端取消 | 不结算未成功的请求 |
| 同一 request ID 网络重试 | 返回相同结果或状态，不重复扣 |
| 同一 request ID 换文本 | 服务端拒绝冲突 |
| 缓存重播 | 不重复扣 |
| 多段并发接近额度上限 | 预留保证总额不透支，失败释放 |
| 周期切换 | 使用服务端 `resetAt`，新周期恢复 7200 秒 |

### 14.3 创建质量与健壮性

| 场景 | 期望 |
| --- | --- |
| 3 秒边界、30 秒边界、4 MB 边界 | 客户端与服务端合同一致 |
| 安静、轻噪、不同男女声、不同音高 | 合理通过，不能过度误判回声 |
| 太静、削波、多人、强噪、强混响 | 返回准确原因，可重录 |
| 引导文案不匹配 | 明确要求按文案重录 |
| 创建成功、预览失败 | 声音仍在，预览可重建 |
| 创建中重复点击 | 单任务执行，UI不重复提交 |
| 列表刷新/Worker 临时失败 | 保留已有声音，不开屏弹通用错误 |
| 删除声音 | 只删除目标；存储、Worker 和 DB 最终一致 |

### 14.4 路由与区域

| 场景 | 期望 |
| --- | --- |
| 全球账号 + 任意 VPN/IP | 仍走全球会话、全球 DB、Supabase、美国 GPU |
| 中国账号 + 任意 VPN/IP | 仍走中国会话、中国 DB、COS、中国 GPU |
| 全球 token 调中国接口 | 401/会话错误，不跨区兜底 |
| 中国 token 调全球接口 | 401/会话错误，不跨区兜底 |
| 中国 STS 上传 | 临时 key 归属校验、正式对象加密、临时对象清理 |
| 两区同名 voiceId/用户信息 | 数据互不可见、额度互不影响 |

### 14.5 回归

- 普通音色朗读和解读。
- 中文/日文句子高亮，英文等词级高亮。
- 播放队列、自动滚动、暂停恢复和后台播放。
- QuickRead、文件朗读、Markdown 朗读。
- 弱网重试、缓存恢复、App/浏览器进程重启。
- 会员购买、恢复购买、登录退出、线路内权益刷新。

## 15. 发布、迁移与变更治理

### 15.1 发布顺序

1. 先更新服务端兼容合同：新规则生效，同时保留旧字段。
2. 更新 Web 客户端并跑合同测试。
3. 更新 iOS、Android、Chrome 扩展，确保新端忽略旧创建字段。
4. 分区域灰度并观察结构化错误、创建成功率、额度账本和普通 TTS 回归。
5. 全部活跃客户端跨过兼容版本后，再清理旧字段、错误码、表和接口。

### 15.2 合同版本

建议服务端响应增加：

```json
{
  "voiceClonePolicyVersion": "v2"
}
```

- 不识别 V2 的旧客户端继续收到安全兼容字段。
- V2 客户端只使用本文定义的四项权限。
- 任何产品规则修改必须先更新本文和服务端合同测试，再修改客户端。

### 15.3 代码所有权

- 权益、额度、资源归属、账本和区域隔离：服务端所有。
- 录音、预处理、UI 状态、付费墙和错误呈现：客户端所有。
- API schema、错误码和端到端合同测试：跨端共同所有。
- 单个 Agent/单个平台不得独立更改“谁能创建、谁能应用、如何扣额、何时恢复”而不更新本文和合同测试。

### 15.4 必须监控的指标

- 创建请求数、成功率、失败码分布和 P95。
- 质量门各原因拒绝率，尤其混响误判率。
- 固定预览成功率和预览重建率。
- 克隆生成成功率、P50/P95/RTF、Worker busy/OOM/重启。
- 额度预留、结算、释放、过期和幂等命中数。
- `VOICE_NOT_FOUND`、旧 slot 错误码、跨区会话错误的数量。
- 普通 TTS 的延迟和错误率，确认新模型不影响旧服务。

出现旧 slot 错误码或新客户端发送旧创建门控事件，应视为合同漂移告警，而不是正常产品状态。

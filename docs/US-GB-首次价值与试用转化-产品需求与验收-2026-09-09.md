# US / GB 首次价值 → 试用 → 正价付费：产品需求与验收

日期：2026-09-09。状态：**待承接、未实现、未部署**。本轮用户只授权广告调整与产品需求交接；本文件不是发版或部署授权。接手 agent 不得修改广告。

## 1. 要解决的问题与目标

目标不是多弹付费墙，而是让广告用户尽快听到自己的内容、愿意回来，随后主动试用并成为真实正价用户。

9/9 已取得的基线（不同窗口不能相乘当真实 CAC）：

| 指标 | US | GB | 窗口 / 限制 |
|---|---:|---:|---|
| 实际 CPT | ¥8.49（$1.19） | ¥7.50（$1.05） | 9/7–9/8，Apple Ads 账户日期 |
| 点击安装率 | 6/29 = 20.7% | 7/23 = 30.4% | tapInstalls / taps，不是 totalInstalls |
| 72h 绑定 / EPUB、PDF 导入 | 正式率 UNKNOWN；观察到 1 人 | 3/20 = 15% | 8/31–9/5 UTC 成熟安装 cohort |
| install→trial | 正式率 UNKNOWN；观察到 1 人 | 1/20 = 5% | 同上；US coverage 77.8%，另有身份关联缺口 |

数据证据：[9/9 数据快照](../reports/apple-ads/2026-09-09-growth-snapshot.md)、[本轮策略与经济模型](../reports/apple-ads/2026-09-09-CAC50-65优化方案.md)。不得把 US UNKNOWN 写成 0%，也不能把 GB 的 1/20 视为稳定真实概率。

分阶段目标：点击安装 ≥40%；install→trial 先 ≥10%，再 ≥20%；同 cohort 成熟 trial→paid ≥30% 是本轮改善里程碑，原 ≥35% 保持为闭环验收目标。72h 绑定/导入 ≥20%、install→paid ≥7% 与留存门仍保留。

经济模型必须写对：`CAC = 实际CPT / (点击安装率 × 安装试用率 × 试用转正率)`，这是纯试用转正路径的规划模型，直接付费单列。`$2.5 / 40% / 10% / 30% = $208.33`，不是 $50–65。建议组合 `$1.20 / 40% / 20% / 30% = $50`，只是假设。

**$50–65 是阶段性降本目标，不是扩量门。** 固定汇率 7.15，US 首年净 LTV ¥329，扩量真实 CAC ≤¥263 且连续两个成熟周满足数据、留存、退款与样本门；GB 净 LTV 另核定。不为提高试用数字调整价格、缩短免费额度或放宽财务门槛。

## 3. P0：自己的内容 → 首次听到价值

### P0-A 两条入口，减少重复操作

- 首次入口用简短选择区分“朗读我的文件 / 文字”和“朗读我已有的 Kindle 内容”，随时可换；不是再加一层强制问卷。
- 文件 / 文本 / 拍照 / 已支持的网页入口直接进入现有处理链，不强制先绑书库；不承诺应用提供图书目录、免费书或 Audible 服务。
- Kindle 未连接时引导连接 → 同步状态 → 选择自己的书 → 朗读；已连接者不重复登录，已有可继续内容者优先继续。
- 选择入口不能仅凭广告关键词猜测并锁定；可用可靠来源作排序建议，但用户选择为准。AdServices keywordId 不等于用户真实搜索词。
- 保持受保护 API 的 session 鉴权。减少重复导航和重复登录，不移除安全门、不增加 device_id 冒充账号的匿名通道。
- 示例可帮助理解，但必须标记 sample；示例首听不计“自己的内容激活”。不因示例播放就认为绑定或文件导入成功。

验收：新装用户选定已有的文本 / 文件后不必绕设置或书库页才能开始；Kindle 授权成功但同步未完成时展示真实处理中状态，不将关闭授权窗误判为内容就绪；错误可重试、换入口，重开保留已完成进度。

### P0-B 补齐来源，隔离增长提示与额度策略

- 将文本、拍照 OCR、粘贴、已支持 URL 的原始入口 provenance 保留到 ReadingDocument / 阅读会话及事件，不因统一转换成 `.text` 全部丢成 unknown。
- **不要直接扩展现有 activationSource 就上线**：它也控制 300 秒硬墙，直接扩展可能给文本/OCR 意外新增限制。拆开“可观测首次价值 / 软提示来源”与“既有额度硬墙适用范围”，对照生产 quotaPolicy 验收，额度不变。
- GB 需要独立的服务端可关停策略，复用 first-value 软提示但不得隐式继承 US 硬墙。新增分配须持久化、可追溯，客户端不能根据地区自行假造 eligible。
- 首音频必须来自真实开始可听的播放器回调，而非发出 TTS 请求 / 下载完成 / 点击播放；30 秒与 300 秒按可信播放 delta 累计，拖动、缓冲、暂停不累计。
- 记录内容来源、首音频等待、处理失败、播放失败与退出阶段；失败码受控枚举，不上传文档正文、标题、URL、令牌或原始异常中的个人信息。
- 大文件、无文字 PDF、OCR 失败、授权过期都给可操作错误，不能静默返回首页。不要顺带扩展新文件格式、云盘或新 TTS 能力。

验收：每个入口各一条“内容就绪 → 首音频 → 30 秒 → 继续听”真机证据；快进 30 秒不会造出 30 秒里程碑；杀进程重开不会重复算首次里程碑；账号切换不会继承上个账号的提示进度或 Pro；扩展来源前后 quotaPolicy、可用时长及硬墙范围一致。

## 4. P0：先体验，再主动试用

本轮主要产品变量是“首次价值后试用入口”，不同时改变价格、试用天数、免费额度与默认订阅选择。

- 内容就绪页以“开始听我的内容”为主操作，不以购买挡住首次体验；已有内容就绪软提示改为不阻断的开始听入口，不新叠第二个弹窗。
- 第一次在自己的内容上累计有效收听 ≥30 秒后，提供可关闭的 Pro 软提示；与硬额度墙、系统权限、评价弹窗互斥，不能层叠。
- 软提示每个安装身份 × 实验 assignment 最多主动出现一次。关闭后本 session 不再主动弹；现有手动 Pro 入口、真实额度闸门保留。渲染曝光与用户级去重分别统计。
- 文案与任务一致：PDF / OCR / 文字强调继续朗读、同步高亮及当前可售 Pro 能力；Kindle 强调继续听自己的内容。未实现或不是 Pro 专属的能力不得宣传为新解锁。
- 试用资格、时长、当前价格、到期收费金额/周期来自当前 storefront 的 StoreKit 产品与资格；US / GB 当前可售 v2，历史 v1 单独处理；不硬编码“7 天”“免费”或美元价格。
- 不具备免费试用资格时显示订阅入口，不能仍叫免费试用；已有 Pro 不出现试用拉新提示；取消购买立即返回当前内容；pending / 失败不解锁假 Pro，不上报试用成功。
- 试用期支持继续上次内容与进度。提醒沿用现有用户授权、频控和退出机制，不自动申请首启通知、不增加邮件/短信/服务端营销任务。

验收：US/GB storefront 的 eligible、ineligible、已有 Pro、取消、pending、失败、成功、restore 各有测试；价格加载失败显示中性状态，不显示假价；软提示不抢播放器、不清空文档或进度；通知拒绝后不追问。试用转正以 Apple 已验证交易链认定，不以客户端 success / introductory 当正价收入。

## 5. 数据合同与可回答的问题

优先复用 `app_first_open`、`library_connection`、`content_ready`、`read_first_audio` / `onboarding_step.first_audio`、`read_milestone`、`onboarding_step.listen_30s`、`paywall_shown`、`purchase_result` 及服务端 Apple 交易。接手必须核实实际事件名/属性，不把这份文档当已部署 schema。业务同一步有两种已有事件时，只选择一个权威口径，不相加。

必要维度：稳定 install 身份、首启 build、当前 build、US/GB storefront、campaign/adGroup/keyword（缺失明确 UNKNOWN）、实验 assignment/version、入口 source、sample/own、不含内容的文档/会话标识、event_id、发生/接收时间。新增属性必须先更新服务端白名单与合同测试，再接客户端，不能出现客户端埋了但摄入拒绝的版本。

| 问题 | 分子 / 分母与窗口 | 验收重点 |
|---|---|---|
| 广告进来多少 | 点击安装、浏览安装、fresh attributed 分开 | tapInstalls / taps；覆盖有成熟分母；升级/回填不算新装 |
| 有多少真的绑定 / 导入 | 72h sync_completed 或 EPUB/PDF content_ready / 已成熟广告 fresh installs | 保留旧定义，不把文本/OCR混进绑定率补达标 |
| 有多少听到自己的内容 | 72h own-content first_audio / 已成熟广告 fresh installs | 与严格绑定率并列，按 source 拆分；sample 排除 |
| 有多少充分体验 | 同一 own-content 首听群体中有效 ≥30 秒人数；同时给其占所有成熟安装比率 | 播放器回调可信，后台/重试/切段去重 |
| 试用入口是否被看到 | 真实渲染的去重用户 / 符合该软提示条件的用户 | 分 qualified、shown、tap、purchase，不以回调请求当曝光 |
| 安装有多少开始试用 | 安装后固定 72h 内 Apple 验证 trial 人数 / 同窗口成熟安装；另列累计 trial | 固定转化窗口，introductory 只算 trial；直接付费单列 |
| 试用多少转正 | 同一订阅链成熟 trial 的首次正价付费人数 / 已到期且完成对账的 trial 人数 | 按真实试用到期+对账滞后；不是同日 trial / paid 相除 |
| 留下来多少 | W1 / W4 全体及绑定群体，own-content 群体另列 | 沿用 SOP 窗口；D+8 / D+29 成熟再报 |
| 真广告 CAC / LTV | 可归因同 cohort 花费 / 去重正价广告用户；成本、退款、SKU、国家配套 | UTC 花费认证、设备交易连接完整；缺失 UNKNOWN |

数据 P0 依赖：复查 US 77.8% coverage 与未关联试用/付费身份缺口是时间窗口、首次安装识别、设备连接还是摄入问题。给原始记录计数、反连接分类和对账依据，不用“再埋一个事件”代替排查，也不臆造历史 fresh install。

按环节输出成熟度/质量：上游 Apple Ads 可以报告；US 未过 coverage 门时严格下游率及 CAC 仍 UNKNOWN，允许明确标注已观测人数。未成熟写 WAITING_MATURITY，不报 0% P0。安装→trial 固定 72h 窗口是本轮新增并列切片，不能无标签覆盖历史累计 trial 指标。

必须交付两条端到端可复查证据链：

1. 测试安装 → 来源选择 → 内容就绪 → 首音频/30 秒 → 试用提示 → StoreKit sandbox trial → 服务端验证 → cohort 查询。测试身份永久排除 production 经营报表。
2. 生产只读抽样：真实 first open → AdServices → 内容事件 → Apple 已验证交易；只引用已有真实事件，不伪造转正、不为了验收强制购买。尚无真实成熟付费就写待真实 cohort 验证，不能据 sandbox 宣称经济闭环已跑通。

## 6. 实施顺序、测试与交付

1. 快照线上 build / 后端部署 / growth assignment / quotaPolicy / StoreKit SKU；阅读两仓库现行 AGENTS，列明受影响文件与其他 agent 重叠点。
2. 先修本轮会阻断评估的数据合同与查询；对 source、sample、去重、身份、时间窗口写失败测试，再实现最小修复。数据问题可独立交付，不等 UI。
3. 完成入口与首次价值覆盖、软提示时机；保留控制组或至少明确发布前后分层。不因小流量强拆多个多变量实验；随机分配可行时持久化并记录，不能事后挑好看的 cohort。
4. 单元/合同回归：`GrowthLoopProductTests`、`ProductAnalyticsTests`、`ResumeReminderPolicyTests`，以及涉及到的阅读、额度、Pro 测试；新增来源、去重、杀进程恢复、账号切换、错误重试用例。
5. 真机矩阵：US/GB × 新装/升级 × eligible/ineligible/Pro；至少 PDF、EPUB、文字、OCR、Kindle；URL 若当前已支持则回归，不扩展能力。覆盖慢网、离线事件补发、空内容、大文件、后台、音频中断、取消授权/购买、恢复订阅。
6. 对照事件账本核对预期/实际条数、来源、身份、顺序与 SQL 结果，包含重复重放、客户端时钟偏差、跨 UTC 日、旧 build 缺失、未成熟窗口。报告不允许静默丢 unknown/new adGroup。
7. 交付修改清单、测试命令与真实结果、前后演示、事件/查询证据、配置启用/回退方案及尚待真实生产验证项；用户另行批准部署/提交后再执行上线动作。

产品版本首次 build 是独立切点。9/9 广告路由发生变化，首个完整广告效果日为 9/10 Asia/Shanghai；广告变更与产品发版错峰，报告必须同时标记两种切点，不能把新版用户与旧版混算后归功于广告或产品。

### 验收分为两层，不混淆“上线正确”和“增长成功”

- 工程验收：上述入口、资格/额度不回归、每条测试链完整、真实原始事件与查询一致、可关停，才可建议发版。
- 经营验收：每国×词×match 至少 20 taps 或 5 安装用于初步安装表现；≥30 广告安装才初看激活方向，必须给人数与不确定性；试用转正等待真实到期 cohort，1–2 人不认证稳定 30%。沿用 SOP 正价付费样本及连续成熟周要求，未满足不扩量。

## 7. 不在本轮范围

# Pro 正确性与播放连续性：修复约束和验收合同

> 阶段记录归档：本文保留当时的计划、验证与发布状态。2026-09-25 后续客户端修复、送审状态及用户核查结论，以 [本轮交付汇总](CastReader-Pro-Release-Closure-2026-09-25.md) 和现行 [Pro 一致性标准](Pro一致性标准.md) 为准；早期到期计时器等设想不覆盖最终移动端实现。

## 1. 两个独立问题

**账号是否为 Pro** 是支付与有效期事实；**当前播放是否继续** 是已经准入任务的执行状态。不能让一次会员查询失败同时改写这两件事。

- 已确认有效会员：不读免费余额，不消耗免费额度；会员/额度服务抖动不暂停朗读，不让续块重做整套身份和订阅查询。
- 查询超时或服务异常：记录 unknown，保留可恢复的任务、音频和进度；既有容错继续工作。不能伪造“额度已用完”，也不能向数据库写 Pro、顺延到期日。
- 已确认到期或撤销：会员状态按统一规则变成非 Pro，新的任务适用普通额度。已有音频/任务按现有授权边界完成或恢复，不因为 UI 状态刷新而清空队列。确有额度不足，在自然边界明确说明；不新增整本无限续读或额外订阅宽限。
- 用户退出/换账号/可靠确认身份失效：保留既有身份隔离；不把上一账号的 Pro 转给下一账号。内部服务的鉴权错误与用户会话失效必须区分。

这不是要求服务器凭故障判断付费，也不要求客户端在每次播放回调重新认证。会员状态、准入结果、任务恢复分别测试。

## 2. 已确认的历史保障

| 实现 | 已核对行为 | 本轮必须保留 |
|---|---|---|
| 扩展 `src/entrypoints/content.ts` | 新朗读入口统一 gate；会员不启动免费 tracker；播放状态回调不查 status | 不在 RAF、词高亮、音频进度回调里插入权益网络请求 |
| 扩展 `src/shared/listen-gating.ts` | 60 秒缓存；同身份请求合并；启动总预算 1,500ms；失败短退避；正常请求有完整 6 秒上限 | 不叠加多个串行重试预算；缓存与迟到响应必须按账号隔离 |
| 扩展 `trackListenSeconds` | 上报失败返回 null，不中断；上报成功更新当前缓存，避免每 30 秒清缓存导致下一段重新请求 | 计量结果不阻塞音频；不得恢复此前已解决的缓存抖动 |
| CN QuickRead `gateEntitlement` | 只在解读入口检查；一次内部查询至多等 5 秒；内部非 2xx/非法响应等走容错 | 不把这个门改成每块重查或异常即拒绝；现有 5 秒是上限基线，不是新增延迟目标 |
| QuickRead 续块/预取/compose | 同一任务不重复消费；快道与完整规划不各扣一次；恢复复用已生成结果 | 账本查询次数不随句子、标注、音频片段数增长 |
| QuickRead 恢复 | 已发布 block0 能跨 SSE 断开/进程恢复；多个等待者共享生成；元数据异常不替换可播放音频 | 不因支付修复销毁恢复能力，不把技术错误伪装为业务拒绝 |
| iOS 当前源码 | 同账号 status unavailable 保留上次状态；额度上报异步；本地有既有计量/宽限 | 后端不以错误的 false/零余额破坏客户端容错；旧二进制能力边界仍单独列明 |

这些代码既有合理容错，也有已知漏洞。保留容错不代表保留错误主体、错误账本、错误的有效期或无限 stale Pro。

## 3. 最小改动原则

1. **先修事实和选库。** 统一账号归一、有效期规则、Global/CN 权益来源，让已有查询得到正确结果。不得按投诉邮箱加特例。
2. **沿用现有请求边界。** 不为本轮引入强制逐段签名令牌、每块刷新租约或新的跨区认证往返。需要多次查询才能恢复一个播放段落的方案不接受。
3. **会员走直接放行分支。** 已确认 Pro 的准入不查询免费余额、不写免费消费，也不依赖 profile/增长赠额是否成功。
4. **缓存不能一律禁用。** 比较短缓存、同请求内复用与并发合并；缓存按 realm+账号绑定，成功响应覆盖旧状态，已知到期不得被缓存延长。支付/登录显式刷新可失效相关缓存。保留当前候选，先测量再决定是否保留“取消权益缓存”的改动。
5. **支付核验不进播放路径。** Webhook、账本修复、商户核验和对账在独立处理链完成。播放时不临时串查 Stripe、Apple、Google 和全历史订单。
6. **故障不能冒充否定。** 内部服务不可用维持现有容错；后台退避/恢复不阻塞已播放内容。强认证失败、明确业务拒绝与内部服务故障分类处理。
7. **恢复优先于销毁。** 暂时掉线保留 job、block、已生成音频和进度；只有确定终止才释放 ownership 并清理。402 类已终止路径遗漏清理仍需修复，但不能把所有 5xx/断线都纳入终止清理。
8. **本轮不增加商业宽限。** 原有已授权内容的播放容错不写成新的会员有效期；精确到期更新与旧客户端离线显示的边界如实记录。

## 4. 场景决策表

| 场景 | 会员状态 | 当前播放/任务 | 后台动作 |
|---|---|---|---|
| 已确认有效 Pro，免费额度接口超时 | 不因免费接口改成 Free | 继续；免费额度本就不应成为依赖 | 记录辅助故障；无逐段重试 |
| 已确认有效 Pro，status 暂时不可用 | 不能伪造 Free；保留同账号已确认信息及其适用范围 | 已准入内容继续，既有续块/恢复不变 | 有界退避刷新；不写入伪造成功缓存 |
| 同一解读任务 SSE 断开后重连 | 无需重新支付判定 | 恢复同一任务，不重复扣费/生成 | 查询既有任务状态 |
| 新解读的内部账本查询返回 401/403/429/503 或坏 JSON | Unknown，不是“免费额度已耗尽” | 保留既有故障容错；不额外等待串行重试 | 按原因监测，恢复时重新取正确结果 |
| 明确 Free 且免费额度耗尽 | Free | 新任务明确拒绝；既有内容遵守已有完成边界 | 不因下一次超时把已知拒绝重置成余额 |
| 已知到期点到达，未获新有效周期 | Free，不能延长截止 | 不清空已生成队列；后续新准入适用免费规则 | 正常核验续费恢复；不轮询每个音频块 |
| 当前账号退出或切换 | 不继承旧账号 Pro | 使用既有账号/任务隔离 | 失效旧账号缓存；迟到响应不可回写 |
| 解读终止后切回 Listen | 与会员查询无关 | 释放本次 ownership；Listen 可用 | 幂等清理，旧请求不能清理新会话 |

后端无法让已经发布的旧前端立即学会 validUntil、修复本地 OR 或补上播放锁清理。A（服务器兼容修复）与 B（客户端闭环）仍分开验收，不以服务端新增字段冒充旧版已支持。

查询量硬约束：每段 TTS/每个音频片段/每次词高亮 **新增同步权益查询为 0**；同一解读任务续块 **新增权益消费为 0**；有效 Pro **免费额度查询/消费依赖为 0**。任务入口判权次数不得因新链路被翻倍。跨页可能沿用原有“新任务”边界，须按当前客户端实测，不把它误报成同一 job。

延迟门禁：先测基线再比较；保留扩展 1,500ms 启动总预算及现有请求上限，不叠加重试。候选不得新增同步关键路径，也不得出现可重复的首声或续块退化。未测量不宣称“零延迟影响”。只读影子验证限采样，不让每次播放同时跑两套生产查询。

# 移动端统一音色库与 Explore 规划

2026-09-14 · 产品讨论稿，未修改客户端、后端或线上配置。

## 产品决定

把公共预设音色与公共克隆音色放进同一个音色入口，但按使用权益明确分组。用户按听感、用途和语言挑选；模型由后台处理，120 分钟的用量限制必须前台可见。

卖点建议：**“为不同内容，找到合适的声音。”** 权益表述为“常规音色 Pro 不限时；精选音色每月共 120 分钟”。不同声音的表现力与熟悉感必须经过实际生成试听确认，不能按来源自动判定质量。不得用“一直听”“所有音色随心听”暗示精选音色无额度限制。

首期保留底部“音色”入口和现有四个分类，不新增模型 Tab。Explore 默认打开，内部按“常规音色 / 精选音色”分组，组内按听感和用途组织。“已创建”可改为“我的声音”，仅存放用户主动创建的私人声音。

## 2026-09-14 权益修正（取代初稿无区别混排建议）

用户明确指出新增声音中有每月 2 小时限制。初稿只有 Pro 标记，没有在示意中呈现月额度，会诱导用户认为所有 Pro 音色权益相同；本版撤回该设计。

- **入口统一，权益分组。** 常规音色显示“Pro 不限时”；精选音色显示“每月共 120 分钟”。免费用户的常规音色仍遵循免费配额，不能对所有账号承诺不限时。
- **所有消费入口保留区别。** Explore 分组；搜索、听感集合、收藏、最近、播放器和音色详情即使混排，每行也必须有“常规 / 精选·共享月额度”等可见权益说明。仅使用 Pro 或皇冠不能表达时长限制。
- **精选区常显共享额度。** 例如“本月剩余 76 / 120 分钟”。公共精选与自建声音建议共用现有账号克隆额度，明确“所有精选和自己的声音、跨语言合计”，不能让用户误以为每个音色或每种语言各有 120 分钟。这个公共库接入规则是本稿设计，尚未上线；以账户服务发布的实际 quota pool 为准。
- **恢复时间取服务端 resetAt。** 不在客户端推断月初或订阅日；当前已有页面中“每月”和“会员周期”的文案也要按实际服务规则统一。
- **扣量前解释。** 限额声音的选择面板直接显示用途、剩余额度和“使用 · 占精选额度”。选择/设为默认本身不扣时长；不需要每次另弹确认。预制试听免费、不占额度。首次使用可在面板内展开规则。
- **计量单位不能猜。** 已核实 iOS 提供 used/remaining/limit/resetAt，不足以证明按听过时长还是生成音频时长结算。暂用“剩余额度”；接入前核对服务端计量、预取、缓存重播、倍速、取消/失败和跨端共享，不把 76 分钟承诺成还能实际听 76 分钟。若按生成音频计量，规则中明确“按生成音频时长计，尚未听完的已生成部分也计入”。
- **额度耗尽仍有确定出口。** 限额音色仍可试听和收藏，使用按钮显示“本期额度已用完”；展示恢复日期，并提供“改用常规音色”入口。保持文章位置，由用户选声继续；不静默切声，也不默认售卖尚未存在的加量包。
- **品牌名称不能掩盖限制。** “精选”可作为听审后的集合名，但“每月 120 分钟”必须与名字同屏；不能将有额度限制等同于音质更高。常规声音依然是完整产品能力。
- **订阅页同步修改。** 当前 `PaywallView.swift:401` 为笼统的“无限朗读时长”，404 为“用自己的声音朗读和解读 · 每月 120 分钟”。公共库接入时，改成两条明确权益：“常规音色不限时朗读”与“精选及自己的声音，每月共 120 分钟”，购买前就能理解。官网、商店截图与新手引导同口径。

本次示意中的 76 分钟、恢复日期及账号状态均为演示值，并非读取用户账户。生产端额度未知时显示“正在同步额度”，不能默认给满额或标记无限。

## 2026-09-14 多语言修正

用户进一步明确，同一个克隆音色可以用于不同语言。产品必须将三个维度分开：**音色身份、朗读语言、用量权益**。不得因为素材是英语，就只在英语列表中展示该音色。

- 浏览音色时，语言筛选的含义是“能朗读什么语言”，不是“原始录音说什么语言”。跨语言音色可标“多语言”，同一个公共 ID 跨语言复用。
- 阅读时显示“朗读语言：自动识别（可纠正）”。当前内容语言决定合成语言；切换声音不翻译文本，也不改成参考音频的语言。
- 同一个 Rowan 可以读英语、中文等服务已支持的语言。试听优先按当前朗读/试听语言播放 CastReader 实际合成样本；同一音色可以切换试听语言。原始样本语言仅作内部字段或详情中的“参考样本：英语”，不作主卡片的排他语言标签。
- 120 分钟按实际共享池跨音色、跨语言合计；换语言不会得到新额度。限额属性不能从“多语言”标签或模型名推断，必须由独立权益字段决定。
- 模型支持合成某语言、某音色实际输出质量、词级对齐/解读标注可用性是独立能力。后两者待验收不能被表述为“这个声音只支持英文”。接入工作必须补齐计划开放语言的完整阅读流程，不能靠隐藏跨语言声音规避问题，也不能假装尚未完成的跟读已经可用。
- 不把“跨语言”宣传成翻译功能，也不把已知十语种扩张成所有世界语言；可选范围来自服务实际支持能力。

## 页面组织

### Explore：帮助用户发现

第一屏包含朗读/试听语言、权益区别、少量推荐和清楚的试听/使用入口。额度说明优先于装饰性推荐大图。多语言声音不会因参考音频语言不同而被筛掉。

1. **常规音色优先，精选音色独立一组**：给少量有差异的推荐，并让“常规不限时 / 精选每月 120 分钟”同屏可见。没有个性化证据不写“最适合你”。
2. **按听感或用途浏览**：如温暖陪伴、沉稳讲述、清晰跟读、故事感。同一集合可包含不同权益，但保留分组或每行额度标识；同一音色可以出现在多个集合，身份与收藏保持唯一。
3. **全部音色**：统一搜索与渐进加载，保留权益分组，并提供“只看常规音色”筛选。免费/Pro 表示访问权限，常规/精选表示用量规则，不能混为一类。年龄、训练时长、模型参数不作为首屏信息。
4. **新声音**：用少量“新”标记或一个精选推荐位持续更新，避免首页堆满不同榜单。首期不做社区、关注作者或热度排行榜。

每行统一基础操作：头像、名字、一句可感知描述、必要的权益/额度说明、试听、收藏、使用。Pro 仅表示订阅资格，必须额外区分是否占 120 分钟额度。

头像应采用统一裁切和视觉规格；模型之间不换卡片样式。不能依据头像补造性别、年龄或身份。后台保留真实来源和授权依据；面向移动端提供样本前需确认使用范围覆盖该入口，不能因更名而推导权利。

### 播放器内换声：帮助用户快速继续

与 Explore 共用目录、音色身份和选择服务，但默认先展示当前声音、最近、收藏及少量适合当前内容语言的选项。完整探索通过“更多音色”进入。

阅读中默认按内容语言筛选；保留现有手动纠正识别语言的能力。浏览语言只改变列表，不改变文章的合成语言，更不会翻译文章。选择英语声音来读中文必须依据该声音的中文输出验收能力，不依据样本语言猜测。

继续使用现有 `PlaybackVoicePanelCenter` 应用内覆盖层。不得换回会影响 Kindle WKWebView 几何的系统 sheet；不更改阅读位置恢复和字号重排逻辑。

## 一致的交互合同

- **试听**：点播放图标/头像，使用当前目标语言、真实生产合成链路预生成的 8–12 秒标准样本。每种语言使用相同文案和默认速度，便于比较；不自动更改音色、不写入最近、不创建私人声音，也不触发首次注册。音频和模型版本关联更新。
- **音频所有权**：试听开始时保留正文播放状态并暂停正文；任一时刻只允许一个试听源。关闭、结束、切源后按原状态恢复，原本暂停的正文保持暂停。
- **收藏**：只改变收藏。公共标准音色、公共克隆音色、自己的声音都能进入同一收藏与最近列表；私人声音严格按账号隔离。
- **使用**：非阅读场景设为该语言的默认声音，短提示“已设为英语默认音色”。阅读场景显示“使用并继续朗读”，从明确的当前句边界切换，避免跳段和重复整段。
- **成功状态**：请求中显示“正在切换”；新声音准备及首段合成成功后再提交当前声音、更新最近并显示已选。快速连续切换采用最后一次选择，旧响应不得覆盖新选择；可取消，失败保留原偏好和阅读位置。
- **异常**：用“暂时无法使用，请重试”等动作导向文案。可提供用户主动选择的其他声音；不静默换声。目录下架不抹掉收藏，应给出不可用状态。区域不可用的声音不进入该区域的新用户推荐。
- **我的声音**：只有用户主动录制/创建才新增条目。选择公共音色不要求“添加、导入、创建副本”操作，也不在“我的声音”制造数十个自动条目。

## 让“选了就能听”成立的前提

前台减少步骤必须由后台提前完成准备，而不是隐藏一个仍会失败的必经过程。

首批先选择约 **12–20 个多语言声音候选**，经过验收后再确定最终上线数量。可以先从英文参考素材挑选，但这些音色应跨语言使用，不能因此只归类为英文音色。兼顾声音差异、日常长听与高亮稳定性。

每个推荐音色要具备：

1. 当地区域已准备、参考特征持久化、冷启动可恢复；不只依赖进程内热缓存。
2. 使用实际生产链路生成并听审的样本、已确认的语言能力和听感标签。
3. 长文连续朗读、段落衔接、语速变化、取消/恢复、词级高亮验收。
4. 朗读和解读分别验证。解读朗读的是讲解文本，标注还依赖块时间线；普通 MP3 成功不能算完成接入。
5. 可用状态同时受区域、当前模式、语言、权益与质量约束。`ready` 或模型支持语言不能单独决定上架。

同一个公共克隆声音在计划开放的各输出语言下都要验证时间戳/跟读链路。十语种短文合成通过不等于十语种完整阅读体验；对尚缺的语言补齐对齐能力或明确模式边界，不能把声音本身错误归为仅英文。现有私人声音跨语言行为另行回归。

延迟目标建议先测基线再定正式门槛：缓存试听点击到声音 P95 < 1 秒；准备完毕音色首次有声等待 P95 争取 < 3 秒。均为产品目标，不是当前实测结果。精选扩容还应看播放失败率、30 分钟连续阅读和两区峰值排队表现。

## 最小技术改造边界

### 统一身份与目录

新增面向移动产品的统一音色 DTO，包含稳定 `public_voice_id`、名称/头像、展示标签、经过验证的输出语言、分语言试听、权益和模式能力。权益至少包括 `access_tier`、`usage_policy`、`quota_pool_id`、`metering_basis`；账户下发总额、剩额及恢复时间。禁止按 `isPro` 或名称猜测是否限额。私有创建声音保留其所有权身份，公共声音的收藏/选择始终保存公共 ID。

服务器内部解析公共 ID 到区域声音绑定、模型与推理路由。公共 ID 不等同于 Voice API 工作区的 `voice_id`，也不能仅因为一个 ID 加进目录就让 iOS 当作普通预设请求。

当前客户端 `vc_` 分支及两套偏好是兼容约束。实施时增加明确的 voice reference/resolve 层，保留旧 ID 读取与迁移；不要靠伪造前缀绕过标准/私人音色权限。收藏和最近须迁移到统一身份解析。

目录需要区分 `sample_language` 与 `supported_output_languages`，并按语言、区域、模式分别发布真实能力。不要复用当前 catalog 中“on_demand 返回全部模型语言”作为移动端逐音色验收结论。

### 移动端服务桥接

在现有账号 API 后增加公共音色解析和消费端合成适配，使用当前移动端 session、区域路由、Pro 和额度合同。复用准备缓存与推理服务，不把开发者控制台整页嵌进 App，也不将开发者 API Key 或工作区管理凭据放入 App。

公共音色选择不必创建用户自己的克隆条目；所需区域内部绑定由服务器管理。商业权益不能直接套用当前“私人克隆 canApply”开关，需要独立解析并保持一致的移动端 Pro 口径。

向现有播放器返回兼容 `AudioSegment` 的音频、实际合成文本、词时间戳与续传信息，保留长段切分、幂等请求、重试、取消和播放位置。不能只接回一个音频 URL 而丢失跟读。

### 权益建议

免费用户可浏览、试听和收藏；建议保留少量新音色可直接体验，精选库大部分作为 Pro 价值。已有免费及 Pro 音色权益保持原样；是否新增免费克隆试用需单独按真实成本确认。

用户使用同一个 Pro 订阅体系，不引入 API 钱包/模型套餐。当前 120 分钟限制是明确约束，所有相关音色必须在选择前展示共享用量规则、剩余额度及恢复时间。具体计量含义按服务端结算核实后命名，不能先写“剩余可听时长”。

## 分阶段推进与验收

**阶段 1：权益明确的多语言精选 MVP。** 先落实常规/精选分组、跨语言共享额度、正确语言筛选及付费页文案，再做候选听审、两区预准备、分语言生成试听、统一目录/身份、收藏最近合并、播放器换声闭环。验收同一音色跨语言选择，以及 120 分钟正常、低额度、零额度、同步失败和恢复边界。上线语言分别做完整跟读验收，先小范围灰度。

**阶段 2：完善发现。** 根据试听→选择、选择→成功开听、首次有声等待、10 分钟留存、换声放弃率、收藏后复用率来调整集合。不要只用浏览次数证明卖点成立；更多音色也不等于更多持续收听。

**阶段 3：扩大语言和库规模。** 按“声音 × 输出语言 × 区域 × 朗读/解读”逐项放量；增加适合长期阅读的音色，并维护退出/替代推荐机制。候选范围可增大，首屏始终保持少量有差异的推荐。

## 参考设计原则

- Apple 的 [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) 提醒权衡增加 Tab 带来的导航复杂度。本方案据此优先保持“音色”单一入口。
- ElevenLabs 的 [Voice Picker](https://ui.elevenlabs.io/docs/components/voice-picker) 将搜索、预览和选择放在同一选择器中，可借鉴交互密度；CastReader 仍须按自身“持续阅读＋词级跟读”的能力约束音色。

以上产品结构、候选数量和性能目标为本次建议；并非竞品结论或已经实现的功能。

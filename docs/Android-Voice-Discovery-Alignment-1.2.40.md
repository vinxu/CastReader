# CastReader 音色发现迭代：Android 对齐需求

> 对齐基线：iOS **1.2.40（62）**，应用源码 **`5c45b75`**，发布记录提交 `5ad31e4`。该版本于 2026-09-16 提交审核。本文按该包及配套后端的实际能力整理，不代表已完成 Android 实现或验收，也不代表对每个音色、每种输出语言都做过声学验收。
>
> 读者：Android 产品、设计、客户端、后端与测试。本文中的“必须”是本轮对齐要求；“建议”是 Android 实施建议；“后续”不计入本轮交付。

## 1. 本轮目标与最终决策

用户要更快找到喜欢、适合当前内容的声音，能够试听、选中并在朗读和解读中真正使用。发现页需要有专题和内容层次，同时明确哪些声音会消耗月度生成额度。

| 最终决策 | Android 必须对齐的结果 |
| --- | --- |
| 常规音色为主，社区克隆为辅 | 首页主要推荐和场景分类使用常规音色；社区克隆集中在一个“精选音色 / Curated voices”模块。 |
| 用途、听感、人物身份、私人关系分开组织 | 不把“中文、低沉、名人、Pro、睡前”混成同一级分类。 |
| 产品文案不要求用户理解引擎 | 常规音色不展示 Kokoro 型号；精选明确说明“克隆音色 · 多语言适用 · 生成消耗月额度”。 |
| 默认声音不重复显示 Unlimited | 常规卡片不逐条贴“不限时”；非 Pro 用户仍需看到实际适用的 Pro 门槛。 |
| 名字与头像属于每个音色 | 专题列表、卡片、选中入口保留音色自己的名字和头像；专题封面使用独立画面。 |
| 推荐按语言匹配 | 中文发现推荐中文来源，英文发现推荐英文来源；其他有合格来源的语言同理。 |
| 完整音色仍可找到 | “浏览全部音色”分“常规音色 / 精选音色”两 Tab，搜索覆盖完整公共目录。 |
| 私人声音有独立入口 | “听见熟悉的声音”有声音时展示自己和朋友最新 3 条；没有时才显示录制/邀请入口。 |
| 选择必须贯通播放 | 常规、社区克隆、自己/朋友的克隆声音共用选择规则，朗读与解读不能各自保留旧选择。 |
| 内容由运营配置 | 中国区与国际区两套配置；不把某周标题、音色 ID、分类成员或数量写死在 APK。 |

**“常规不扣克隆额度”不等于“所有用户免费无限使用”。** 本轮保留原有免费朗读、Pro、速度、解读和录制资格规则；克隆的月额度是另一个维度。

## 2. 三类声音与四个语言/区域概念

### 2.1 声音类型

| 类型 | 数据与身份 | 出现位置 | 正式生成与额度 |
| --- | --- | --- | --- |
| 常规音色（技术上为 Kokoro） | 公共目录原始 `id`，例如 `af_heart`；保留名字、头像、语言和权益 | 主推荐、场景、全部目录、收藏、最近 | 走常规 TTS；不扣克隆月额度，保留原免费/Pro 规则 |
| 社区克隆音色 | 公共目录 `vl_…`；`usagePolicy=monthly_generation` | 独立精选模块、完整精选目录、收藏、最近 | 走账号鉴权的克隆生成；共享月度生成额度 |
| 自己录制/朋友提供或授权的声音 | 账号音色库 `vc_…`；另有身份、来源、授权状态和能力 | 我的声音、熟悉的声音、阅读器当前音色 | 同一克隆生成链路；检查账号、授权、Pro、输出语言及额度 |

2026-09-15/16 发布验收的公共目录为 **1,606 条：283 常规 + 1,323 社区克隆**。私人音色另从账号库读取，不计入这 1,606 条。数量用于本轮规模回归，产品显示以 API 为准。

### 2.2 四个独立概念

| 概念 | 控制什么 | 不应被它改变的内容 |
| --- | --- | --- |
| 产品运营区域 `cn / international` | 中国文化或英文文化体系下的专题、顺序和候选池 | 切换发现语言不能自动改变运营区域 |
| 服务线路 | 本次访问哪个地区的账号、生成与额度服务 | 不能因选择外国音色就更换账号或计费地区 |
| 界面语言 | 标题、按钮、标签、错误提示的翻译 | 不自动把当前阅读内容改成该语言 |
| 发现/输出语言 | 发现页推荐范围；阅读器使用的生成语言 | 来源试听语言不能覆盖当前输出语言 |

界面语言和发现语言可以不同。例如英文界面选择日语发现，模块标题按界面本地化，声音按日语来源推荐。

克隆音色另有两个重要字段：

- **`referenceLanguage` / 来源语言**：用来回答“这是什么语言文化来源的声音”，用于发现推荐。
- **`supportedLanguages` / 输出语言**：用来回答“能用这个声音读哪些语言”，用于选用和生成。

来源语言解析顺序与 iOS 对齐：优先 `referenceLanguage`；缺失时使用 `previewLanguages` 中唯一的原始语言；仍不能确定才回退 `language`。不能只看 `language`，历史韩语、俄语条目可能兼容编码为英语。

## 3. 页面结构与视觉要求

### 3.1 Voice 主页面

保留四个入口：**最近 / 收藏 / 发现 / 我的声音**。默认进入发现。顶部只有必要的语言选择、筛选及分段导航，不堆叠引擎介绍、权益说明和大段宣传文案。

进入阅读器的音色面板时，应带入当前朗读语言或解读输出语言；从 Voice 主 Tab 进入时，使用用户上次主动选择的发现语言，首次按设备语言与可用目录确定默认值。仅浏览语言不修改音色偏好；用户在阅读器明确纠正语言是另一项显式操作。

### 3.2 发现信息流

| 模块 | 内容与交互 | 范围与数量 |
| --- | --- | --- |
| 本周发现 / 编辑专题 | 大幅专题插画或摄影封面、短标题、音色数量；点击封面/箭头进入专题。封面下有独立的代表音色行，可直接试听和选用 | 来自运营 `feature` 模块；本轮主推荐只取常规声音 |
| 横向音色卡 | 头像、名字、短描述、试听、收藏、选中状态 | `portraits`；iOS 首页最多展示 8 张，完整专题保留更多成员 |
| 紧凑列表推荐 | 头像行交错出现，形成不同内容节奏 | `rows`；iOS 首页展示前 3 条，箭头查看专题 |
| 先听这几个 / 你可能喜欢 | 无偏好时给起步推荐；已有收藏/最近使用时推荐相似声音 | 常规声音，最多 6 个；避开主运营模块已展示的 ID |
| 按场景找声音 | 双行横向分类卡，短标题、图形和当前可见数量 | 使用后台分类；缺少可用分类时用本地四场景兜底 |
| 精选音色 / Curated voices | 标题和入口整行可点击；紧邻一行克隆/多语言/月额度说明；每条声音可试听、收藏、选用 | 单独一个模块；按来源语言过滤后最多取 6 个，首页露出前 3 条 |
| 听见熟悉的声音 / Voices close to you | 有数据时展示最新声音；标题箭头进入完整“我的声音” | 自己+朋友合并最新 3 条，见第 6 节 |
| 浏览全部音色 / Browse all voices | 进入可搜索的双 Tab 目录 | 不受发现语言截断，见第 5 节 |

运营模块在信息流内按后台顺序显示，不固定只有一张 Banner，也不把所有模块都做成同一种大卡。没有合格内容的模块直接隐藏；没有有效运营期次时仍保留常规推荐、可用分类及完整目录。

**封面与头像分工：** 封面讲“这个专题值得听什么”，头像标识“具体是谁的声音”。不可把一排头像放大拼成 Banner 代替专题画面，也不能用专题封面替换成员头像。

### 3.3 音色卡与按钮

- 公共音色名字不由客户端随意改写；头像使用 `avatar.url64 / url256`，缺失或加载失败用稳定占位，不阻塞操作。
- 副标题优先“一个听感 + 一个用途”，例如“明亮 · 长文故事”；信息不足时退回简短描述或性别/通用提示。不要显示 decoder、模型修复版、时间戳模式等技术标签。
- 头像播放按钮或独立“试听”按钮负责试听；名字/选用区域负责选择；爱心负责收藏。三个动作独立，点击不能穿透触发另一个动作。
- 试听按钮需要稳定尺寸与内边距。Android 建议使用至少 **48dp** 的有效触控区域；长译文、小屏、放大字体时优先让说明换行，不挤压播放按钮。
- 加载、播放、停止状态只更新相关声音的控件；选中状态在所有入口一致。
- 常规声音不重复显示 Unlimited；克隆声音保留“月额度”标识，点击可查看说明。原始试听语言与输出能力分开表达，例如“英语 · 试听”。

视觉参考使用本版本真实界面：[中文发现](../AppStoreAssets/1.2.40/zh-Hans/05-voices-1.2.40.png)、[英文发现](../AppStoreAssets/1.2.40/en-US/05-voices-1.2.40.png)。参考信息层级与组件关系，Android 按原生导航、字体和触控尺寸实现，不要求照搬 iOS 像素值。

## 4. 合理分类与推荐规则

### 4.1 分类维度

| 维度 | 本轮结构 | 规则 |
| --- | --- | --- |
| 使用场景 | 日常资讯、长文故事、学习讲解、睡前陪伴 | 主体为常规声音；一个声音可以属于多个确实适合的场景 |
| 听感 | 全部、柔和、沉稳、明亮、轻快 | 作为独立筛选，不与场景并列混排 |
| 人物/表达身份 | 名人风格、角色演绎、自然旁白 | 在精选专题内部展示；成员由运营明确选择 |
| 与我的关系 | 我的声音、朋友的声音 | 来自私人账号数据，不进入公共运营候选池 |
| 其他筛选 | 性别、口音、免费/Pro、是否使用月额度 | 与用途和语言保持独立 |

后台可调整分类标题和成员，但不能为了填满页面让四个场景拥有完全相同的列表。头像、名字、来源身份不随分类改变。

### 4.2 初始归类方法

使用目录的 `bestFor`、`tags`、`collection` 召回，再由运营试听筛选。iOS 本轮规则为：

- 日常资讯：明确的文章、资讯、通用阅读用途。
- 长文故事：故事、文学、有声书、长文等用途；不能仅凭“低沉”就认定适合讲故事。
- 学习讲解：明确教育/讲解用途，或同时有学习用途和清晰表达标签；“清晰”一项不够。
- 睡前陪伴：温暖、柔和、舒缓等特征，排除急促、强烈、过于兴奋的表达。
- 名人/角色分组：使用运营维护的原始 ID，不靠名字关键词自动认定身份，不显示未经证实的官方背书。
- 信息不充分或分类不可靠的声音保留在完整搜索中，不强塞进推荐。

元数据是分类线索，不是“已逐个试听评分”的证明。新增推荐应由运营试听并修正标签；本轮没有全库声学评分系统。

### 4.3 偏好推荐

本轮使用**收藏 + 最近选用**作为偏好，不依赖未建设的服务端个性化模型。公共音色最近使用按成功选择记入，去重、最近优先，iOS 保留 12 条；仅试听不记为选用。

与 iOS 对齐的基础排序：

1. 候选必须可用、可选、支持当前输出语言、有试听，排除 `lab / legacy`；主推荐只取常规声音。
2. 从收藏及最近选用前 3 条常规声音中提取听感/用途偏好。已出现在运营模块的喜欢音色仍能影响偏好。
3. 评分参考：`recommended` 加 12，`status=ga` 加 3，每个相同特征加 2（最多加 6），已收藏候选加 2；同分按 ID 稳定排序。
4. 在靠前候选中交替听感或性别，保持多样性；不为凑比例加入不可用声音。排除运营模块已选 ID，最终最多 6 个。
5. 用户收藏变化后可更新推荐，但不能让正在浏览的专题退出、导航来源消失或滚动位置跳回顶部。

没有收藏/选用历史时标题为“先听这几个”；有历史时为“你可能喜欢”。没有真实热度数据时不要写“最热门”“本周使用第一”。

## 5. 多语言发现、专题与完整目录

### 5.1 推荐筛选顺序

`当前运营区域的已发布候选 → enabled/selectable → 有试听且非 lab/legacy → 来源语言匹配 + 支持当前输出语言 → 去重 → 展示数量上限`。

**必须先按语言筛选，再截取数量。** 不能先拿前 6 个英文声音，再发现日语没有成员。克隆可读多种语言，并不意味着应同时出现在这些语言的来源推荐中。

本轮内容基线：中文、英文各 6 个，日语 5、德语 5、法语 6、西语 5、葡语 6 个对应来源的精选候选。后台还配置韩语 6、俄语 4；当前 iOS 发现入口只有九种语言，没有韩语/俄语入口。意大利语、印地语没有对应的社区来源候选，**不以英文声音补齐**。这些数量是历史验收快照，不是客户端常量。

本轮九种界面/发现入口语言为中、英、日、西、法、德、葡、意、印地语；目录语言码使用 `zh/en/ja/es/fr/de/pt/it/hi`，界面本地化可使用 `zh-Hans/pt-BR` 等资源码，须做规范化。

克隆输出能力目前为 **`de/en/es/fr/it/ja/ko/pt/ru/zh`**。必须以实际 `supportedLanguages` 和能力合同为准；不能写“任何语言都能用”，尤其不能据此声称支持印地语克隆输出。录制语言、原始试听语言、生成输出语言也不能互相替代。

### 5.2 专题详情

- 使用后台标题、成员顺序与有效 ID；页面内提供搜索和听感筛选。
- 常规场景只显示该场景中的常规声音。
- 精选详情只显示当前语言对应的运营精选候选；身份子分类使用后台集合与本专题成员的交集，不把全库同类声音自动加进来。
- 无结果时提示调整搜索/筛选，返回后保留原上下文。
- 离开专题停止本页试听，不能留下隐藏播放器或持续转圈。

### 5.3 浏览全部音色

| Tab | 范围 | 不应误解为 |
| --- | --- | --- |
| 常规音色 / Regular voices | 全部语言的可用常规目录，显示必要语言信息 | 只有当前发现语言的几个推荐 |
| 精选音色 / Curated voices | 全部可用社区克隆目录 | 只有首页精选的 6 个声音 |

两 Tab 都可搜索；搜索可匹配名字、ID、来源语言、口音、描述、用途、标签以及本地化听感/场景。搜索不受发现语言截断，但选择时仍检查当前输出语言是否支持。

完整公共目录不合入私人的 `vc_` 音色；私人声音在“我的声音”中完整管理。不能把公共精选误命名为“我的克隆”。

## 6. 听见熟悉的声音

### 6.1 有可用声音

合并自己录制、朋友邀请录制和朋友授权的声音，按 `createdAt` 倒序取**最新 3 条**。显示自己的头像/名字、来源、月额度标识、独立试听按钮及选择状态；标题箭头进入完整“我的声音”。只有 1/2 条时就显示 1/2 条，不用录制按钮补位。

必须过滤已撤回、已过期、明确未就绪的声音。ISO 8601 时间兼容时区和小数秒；相同时间按服务端顺序稳定排序，缺失时间放后，重复 ID 去重。仅当私人列表变化时重算，不随播放进度或公共目录刷新反复排序。

私人声音不受发现来源语言过滤，但选用时仍检查输出语言、授权和能力。后台 `presentation` 优先决定显示名；其次使用用户别名、已有身份及本地化兜底，不把 `vc_` ID 当作用户名字。

### 6.2 没有可用声音

显示两项入口：“录制自己的声音”“邀请朋友录制声音”。复用现有登录、录制和邀请流程；朋友功能须通过区域和 `/api/capabilities` 校验，不因入口存在就绕过服务端能力控制。未登录先进入账号流程。

创建/接收声音后刷新账号库，成功就绪后自然进入最新 3 条。退出或切换账号立即清除私人列表、待选操作和试听；公共内容缓存不携带私人身份。完整管理页仍承接创建、改名、授权和删除，本轮不重新设计这些合同。

## 7. 试听、选用、生成：三个独立动作

| 动作 | 行为 | 不能做的事 |
| --- | --- | --- |
| 试听 | 获取固定样本并播放；同音色再点停止，点另一个则切换样本 | 不改正式选择、不提交用户正文、不扣生成额度 |
| 选用 | 校验资格、提交音色偏好、更新所有相关入口 | 不为了选中状态先生成一段音频，不等待模型准备完成才显示选择成功 |
| 朗读/解读 | 按输出语言读取统一选择，请求正式音频、校验归属后入队 | 不读取音色浏览页的临时试听状态，不悄悄改成旧声音 |

选用克隆时可以复用当前账号 60 秒内仍有效且有资格的能力快照；未知、过期或需要重新确认时再刷新。**不等于所有选择都零网络请求**，但不能每次点击都串行刷新所有数据或触发合成。

试听和正文播放互斥。试听临时暂停原正文并保存播放所有权；结束后只有原内容、会话和播放意图仍有效才恢复。若用户已正式换音色或主动暂停，不能先恢复旧声音再切新声音。

公开样本按目录提供的 URL 请求。社区 `sampleUrls[目标语言]` 可能仍指向同一份原始语言录音；`previewLanguages` 才描述实际听到的语言。不要承诺切语言后试听一定变成该语言。

私人试听使用授权的固定样本接口。iOS 保留过旧网关 404 时的兼容分支；Android 对齐当前固定预览合同即可，不能把任意正文 TTS 当作免费试听回退。

## 8. 选择如何同步到朗读和解读

### 8.1 统一选择表

客户端维护一个按**输出语言**索引的有效选择，并以一次原子提交发布 revision/事件。UI、朗读、解读、当前音色按钮读取同一数据源。

| 本次选择 | 应更新的范围 |
| --- | --- |
| 常规音色 | 仅更新它对应的语言；清除该语言的私人克隆覆盖，其余语言保持原选择 |
| 社区克隆 `vl_…` | 一次应用到该音色实际支持的所有输出语言；清除这些语言旧的私人音色覆盖 |
| 自己/朋友的 `vc_…` | 校验账号和授权后，一次应用到实际支持的所有输出语言 |
| 仅切换发现语言 | 不写入音色选择 |
| 仅试听/收藏 | 不写入音色选择 |

例：在英文发现选了支持中英的社区声音 A，随后朗读中文也应使用 A；再选中文常规声音 B，则中文使用 B，英文仍使用 A。选中朋友声音 C 后，支持的语言使用 C；再选社区 A，不能被旧私人覆盖继续抢回 C。

朗读按内容语言读取选择；解读按**讲解输出语言**读取选择。目录刷新只更新元数据，不重置已保存的选择；找不到或不兼容时按既有可用性规则处理，不能篡改私人授权状态。

### 8.2 正在播放时切换

切换必须作为带唯一事务 ID 的一次操作：

```text
选择提交
  → 保存语义阅读位置和播放/暂停意图
  → 建立新切换事务，取消旧生成及旧音频预读
  → 停止旧音频，新选择使旧音频缓存失效
  → 新声音优先生成当前位置音频
  → 核验账号、会话、文档位置、voice ID、事务 ID
  → 用新时间戳恢复位置并入队
  → 有效新音频就绪即结束准备状态，按原播放意图继续
```

所有成功、失败、取消、同步早退分支必须结束**对应事务**。旧事务不能结束新事务，也不能把迟到的音频放回队列。切换中用户主动暂停，新音频到达也必须保持暂停。

### 8.3 阅读位置与缓存

- 跨引擎不复用旧音频秒数。以段落、语义词/字符范围及内容身份定位，再对齐新时间戳。
- 必须支持 `can't` 与 `can` + `'t` 这类拆词/合词差异；经前缀、目标内容和连续覆盖校验后再续读，不能直接猜位置导致漏读。
- 对齐失败要结束准备、保留位置并提供重试；不能出现“API 200、队列为空、永久准备中”。
- 非活动的朗读页也要失效旧音色音频，返回时不能重新装回旧缓存。
- 解读已准备块保存生成时的 `voice ID`。换声音后保留讲解文字、标注和上下文，只重生成音频；预取入队、重播、恢复所有权时再次检查身份。
- 生成失败不能静默回放旧声音。显示当前声音失败、允许重试或手动改选常规声音，保留阅读位置。
- 音色切换不能回退 EPUB 目录/断点恢复、网页翻页、字号、睡眠定时、音频中断等既有能力。

## 9. 额度与错误状态

### 9.1 用户能理解的计量

所有社区、自己和朋友的克隆声音，共享已有 Pro **120 分钟/月（2 小时/月）生成额度**，各语言共用，绝非“每个声音各 2 小时”。按**成功生成的音频时长**结算，不按听了多久结算；成功生成的后台预读也属于生成。试听、重复播放已有音频不再次扣费。

余额和重置时间读取服务端。通用状态、私人列表和 TTS 响应头汇入同一额度状态，不为每个卡片单独建立计数器。创建资格/次数与生成时长分开，不把“可录制”当成“可无限生成”。

### 9.2 三态而非布尔值

| 状态 | 展示与交互 |
| --- | --- |
| 已确认有余额 | 显示剩余/总量，可生成；不足一分钟显示“不足 1 分钟” |
| 已确认耗尽 | 提示月额度已用完、重置时间及改选常规的入口；保留阅读位置 |
| 未知/同步失败 | 保留最后确认值；首次未知显示同步中，不能凭空显示 0 或弹耗尽 |

`clonePolicy=unavailable` 或余额 `null` 不等于耗尽。兼容旧服务端“unavailable 却带 0”的错误回包，也应视为未知；未知不能清除此前确认的耗尽。到服务端重置时间后，旧周期的零余额不能永久锁住新周期，应重新确认。

额度请求发起时分配序号，并绑定账号边界；旧状态、旧生成响应及旧 429 不得覆盖更新的结果。此序号是客户端响应顺序保护，不是服务端账本版本。后台预读失败不弹全局额度警告打断当前播放；用户交互请求的明确耗尽才提示。

### 9.3 错误分类

| 证据 | 处理 |
| --- | --- |
| 结构化 `CLONE_QUOTA_EXHAUSTED` / 可信额度确认 | 更新耗尽状态；停止该生成，不循环重试 |
| `VOICE_PREPARING` + `Retry-After` | 正在准备，显示可取消状态，在总期限内等待；不能当成普通三次失败立即终止 |
| 其他 503、超时、网络错误 | 有限重试后可恢复失败；不改成额度耗尽 |
| 登录会话失效 | 按既有会话刷新/登录流程；不清空整库或重置余额 |
| 明确授权撤回、过期或声音删除 | 仅处理对应声音的可用性/选择，不能让旧声音的迟到错误清除新选择 |
| 通用 404 或临时权益同步失败 | 不能直接推断声音已删除、朋友已撤权或余额为零 |
| 取消、快速改选、账号切换 | 清理对应任务，旧响应不再影响 UI、播放器和额度 |

## 10. 后端/API 对接要点

### 10.1 接口职责

| 接口 | 用途 | 对齐要求 |
| --- | --- | --- |
| `GET /api/tts/mobile-catalog?contract=tts-voice-catalog-v1&region=cn\|international` | 完整公共目录 + 当前已发布推荐 + 分类 | 非生成接口；区域显式传入；不要换成开发者付费 Voice API 目录 |
| 目录 `sampleUrl / sampleUrls` 指向的 GET | 常规/社区固定试听 | 优先使用 API 返回 URL，不按声音名字拼路径 |
| `GET /api/voice-clone/public/{vl_id}/preview?language=…` | 当前社区公开试听路径 | 播放原始样本，不携带用户正文，不扣额度 |
| `GET /api/capabilities` | 私人/朋友音色等能力合同 | 使用既有区域及版本能力校验 |
| `GET /api/voice-clone/library` | 统一账号声音库 | 读取身份、来源、授权和能力；旧网关兼容 `/api/voice-clone/voices` 要有明确能力依据 |
| `GET /api/voice-clone/voices/{vc_id}/preview` | 受授权的私人固定试听 | 不能暴露为匿名公共资产 |
| `GET /api/pro/status` | Pro 及克隆额度快照 | 复用现有账号合同，支持未知状态；不额外创造设备维度额度 |
| `POST /api/captioned_speech_partly` | 常规 TTS | 沿用现有区域传输和分段合同 |
| `POST /api/voice-clone/captioned-speech` | 社区/私人克隆正式 TTS | 使用当前地区 `cms_` 会话，保留原 `vl_ / vc_` ID |

移动端服务入口为中国线路 `https://api.castreader.cn`、国际线路 `https://api.castreader.ai`。不要把公共运营控制台的域名当作所有用户的生成线路，也不要接入已经停用的旧 `voice.castreader.cn`。

克隆生成使用 `Authorization: Bearer <当前地区会话>`、`X-Auth-Provider: session`、`X-Request-ID`、`X-TTS-Priority`。客户端不持有上游密钥，不把公共 ID 改写成服务端内部 prompt/worker ID。

### 10.2 公共目录字段

| 层级 | 关键字段 | 使用方式 |
| --- | --- | --- |
| 根 | `contract`, `version`, `editorialRegion`, `languages`, `voices`, `discovery`, `collections` | 完整校验后一次替换旧快照；运营内容可缺省 |
| 语言 | `code`, `locale`, `name`, `status`, `defaultVoice`, `timestampMode` | 默认音色与当前能力；不是固定枚举数量展示 |
| 音色身份 | `id`, `name`, `avatar.url64/url256` | 稳定 ID、原始名字/头像，列表 key 不能用下标 |
| 可用性 | `enabled`, `selectable`, `tier`, `status` | 权益、筛选与推荐准入；实验声音不进入编辑推荐 |
| 能力 | `language`, `referenceLanguage`, `supportedLanguages`, `usagePolicy`, `timestampMode` | 来源推荐、生成语言和计费分别判断 |
| 试听 | `sampleUrl`, `sampleUrls`, `previewLanguages` | 固定样本地址及实际样本语言 |
| 描述 | `genderPresentation`, `accent`, `tags`, `bestFor`, `description`, `descriptionZh`, `recommended`, `collection` | 展示、搜索、初始归类与偏好排序 |
| 运营期次 | `id`, `startsAt`, `endsAt`, `modules` | 按 UTC 有效期展示；已缓存内容到期也要退出 |
| 推荐模块 | `id`, `layout`, `title`, `theme`, `voiceIds`, `artworkURL` | 布局支持 `feature / rows / portraits`，标题为语言字典 |
| 分类集合 | `id`, `title`, `theme`, `voiceIds` | 显式成员与顺序；允许跨集合重叠 |

后端 DTO 使用 `sampleUrl / sampleUrls`，推荐封面字段是 **`artworkURL`**，不要混淆大小写。标题语言字典使用 `zh/en/ja/es/fr/de/pt/it/hi`；缺少当前翻译时可回退英文，再回退本地化主题标题。

目录 ID 重复、合同错误、默认声音缺失、克隆能力字段不完整等应拒绝替换，保留上一份有效目录。未知布局/空模块可跳过，不让一张运营卡片破坏整个可播放目录。

### 10.3 TTS 与额度字段

克隆兼容请求与常规请求保留已有 JSON 字段：`input`, `voice`, `voice_code`（适用入口）、`language`, `response_format`, `return_timestamps`, `speed`, `stream`。`voice/voice_code` 必须是同一选中原始 ID；某些既有入口只支持 `voice`，不要为了本轮改坏其合同。

iOS 兼容 DTO 的 `model` 当前仍编码为 `kokoro`，包括走克隆专用路径时；**不能根据这个遗留字段决定引擎**。按原始声音身份和专用端点路由，Android 对接时复用后端已支持的合同，不自行发明新的 model 值。

响应核心为 `audio`（Base64 MP3），以及可选 `audio_format / duration / timestamps / processed_text / unprocessed_text`。有效音频不能因为可选时间戳缺失就完全无法播放。没有可靠词时间线时降级分段高亮，不伪造逐词时间；iOS 中日及韩语合同采用句/段级高亮。续文必须保留，不能把首次较短生成当作整段结束。

额度状态字段包括 `clonePolicy / cloneCanApply / cloneMonthlyLimitSeconds / cloneMonthlyUsedSeconds / cloneMonthlyRemainingSeconds / cloneQuotaResetAt`；TTS 响应头对应 `X-Clone-Quota-Limit-Seconds / Used-Seconds / Remaining-Seconds / Reset-At`（后面各项沿用相同 `X-Clone-Quota-` 前缀），并可带 `X-Clone-Quota-Mode`。单位为秒，显示才换算分钟；`null` 不得反序列化为 `0`。

同一次生成的网络重试保留请求身份，使用既有后端幂等能力，不把它变成新的付费生成。不同正文请求必须各自生成和结算，不能为了合并准备而复用别人的音频结果。

## 11. 并发、首音和界面性能

### 11.1 首音与并发

- 当前段/当前解读块优先；克隆前台首段未就绪时，后台预读等待，且等待不占网络调度许可。
- 建立切换事务要早于通知预取层。否则下一段先抢到参考音色准备租约，会再次出现“后台成功、当前段连续 503 后停播”。
- 前台克隆开头先生成较短文本：iOS 中日韩最多 48 UTF-16 单位，其他语言最多 120，优先按标点/空格切分。后续文本全部保留；克隆单请求兼容上限为 600 UTF-16 单位，先处理服务端未完成部分，再处理本地剩余。
- iOS `VOICE_PREPARING` 在共用单调时钟 **90 秒总期限**内遵守 `Retry-After`，准备重试最多 12 次；普通瞬时错误使用较少重试。Android 不应叠加 HTTP 层、Repository、播放器三层无界重试。
- 后端按“服务地区 + 声音”合并准备：进程内合并 + 跨实例租约。一个等待者取消不能取消其他人的准备；不同文本的合成、音频和额度独立。
- 首次使用长尾社区声音仍可能需要参考音频下载、降噪和特征准备；不能承诺所有克隆声音瞬时出声。选中反馈应及时，准备进度可取消、有超时、有重试出口。

### 11.2 Android 实施结构建议

建议至少拆为：公共目录 Repository、派生搜索/推荐 Worker、私人音色 Repository、统一选择状态、试听控制器、正文播放/切换协调器、额度状态。Compose 层只消费准备好的 UI 数据。

| 要求 | 对齐方式 |
| --- | --- |
| 完整目录不阻塞主线程 | 缓存读取、JSON 校验、索引、搜索、排序、分类在后台；一次发布不可变快照 |
| 不反复全库扫描 | 预计算 ID 索引、语言成员和数量；状态变化只重算受影响派生数据 |
| 搜索无旧结果覆盖 | iOS 防抖 120ms；Android 使用可取消任务和请求序号，快速输入时仅最新结果生效 |
| 刷新不过量 | 已有目录先显示，后台刷新；iOS 普通刷新间隔 15 分钟，下拉可强刷，同一请求合并 |
| 缓存正确隔离 | 公共缓存按服务线路+运营区域；搜索还包含目录版本和界面语言；推荐包含偏好及发现语言；私人内容绑定账号 |
| 图片按需加载 | 不预取 1,600 多个头像；按尺寸降采样、有界内存/磁盘缓存、同 URL 合并、限制并发；iOS 参考值为并发 4、100 项/24MB 内存 |
| 试听音频有界 | 固定样本磁盘缓存；iOS 参考值为单样本上限 12MiB、总缓存 32MiB、24 小时有效，下载/失败/取消清理部分文件 |
| 播放器可收尾 | 准备有超时（iOS 10 秒），停止释放任务、观察者和音频项；迟到回调需身份校验 |
| 页面不反复重排 | 列表使用稳定 key 和懒加载；避免同方向嵌套无限列表、重复 insets 计算、整个发现页订阅播放 tick |
| 运营列表有边界 | iOS 最多接纳 8 个模块、每模块 24 个有效成员，首页再按布局限制；完整目录单独懒加载 |

本轮 API **仍返回完整元数据，没有服务端分页或服务端搜索**。Android 可直接复用此合同；不要把分页列为本轮后端已经提供的能力。以后规模扩大时再升级合同。

iOS 已出现过两类 UI 卡死：导航搜索/safe-area 相互触发布局，以及短法语推荐页内外两层纵向懒布局循环。Android 无需照搬 UIKit 修复，但必须规避同类“局部播放状态引发整页重排”和嵌套测量问题。实际包最终仅将有界推荐内容改为普通栈，完整目录仍懒加载。

## 12. 两区运营与每周更新

后台为 [音色运营控制台](https://api.castreader.ai/admin/voices)。仅有 **中国区 `cn` / 国际区 `international`** 两套独立配置；中国区偏中文文化，国际区偏英文文化。在同一区域内仍支持不同发现语言的候选池。

后台负责选原始声音、分类成员、标题翻译、模块布局、封面、排序、草稿、发布时间、有效期和撤下。Android 只消费已发布内容，不持有后台权限，也不独立保存一套推荐 ID。中国线路获取公共运营内容，不意味着用户账号、正文、计费或私人 prompt 跨区。

每周可执行的运营流程：

1. 整理当周文化/场景主题，从已接入目录中召回合适声音。
2. 试听候选、核对用途、身份和来源，完善短标题与翻译。
3. 在对应地区保存草稿、预览，确认声音可用与额度说明。
4. 使用带 revision 的发布操作，安排 UTC 起止时间；并发编辑冲突先重新读取再处理。
5. 客户端刷新后展示；期次到期或撤下后回退到有效内容及常规发现。

**当前已具备：** 后台分类/专题推荐、两区独立版本、草稿、定时发布和撤下、客户端缓存与有效期处理。

**尚未启用：** 自动追踪电影/社会热点、自动抓取或创建声音、自动审核新声音、每周无人值守自动发布。现有周草稿工具不等于自动运营正在运行。新增声音入库/授权和资源准备是独立流程，发布专题不能创建声音或改变它的额度。

撤下推荐有缓存传播时间，不应宣称即时。涉及声音本身不可再用时，后端还需禁用该声音映射；只从某专题移除不等于撤销生成资格。新封面先作为公共静态资源部署，再由后台引用，移动端不需重新发版。

## 14. 交付顺序与边界

推荐按以下顺序落地，每阶段保留可回归的结果：

1. **基础链路**：全量目录、账号音色库、试听、三类 ID 的生成路由、统一选择、额度三态。
2. **发现框架**：两区运营内容、专题三种样式、四场景、单一精选模块、完整双 Tab 搜索、熟悉声音最新 3 条。
3. **体验与可靠性**：偏好推荐、多语言、缓存和取消、跨声音续读、前台优先、超时/错误恢复及真机性能验收。

本轮不包含：新增模型或本地 Kokoro 引擎、无限克隆额度、所有语言克隆承诺、服务端分页搜索、第三个运营区、全库声学评分、自动热点爬取与自动新声发布、重新设计朋友授权/付费体系。韩语/俄语发现入口扩展单独排期，不能因为后端能生成就直接改变现有九语常规合同。

本次文档工作未修改 Android/iOS 产品代码、后台配置或发布状态。Android 实际已有多少能力需实施团队核对，本文不假定其现状。

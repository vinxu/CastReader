# CastReader for Mac 功能实现测试与验收总规划

> 2026-10-04 实施范围更新：用户已明确 Mac **仅支持国际版**。全部实施与验收以 Global 为唯一 Mac 产品区域；iOS 既有中国区行为不改变。Mac 必须对齐最新国际版 iOS 的全部功能和实际效果，每个大功能完成测试与真实验证后，才进入下一个功能。执行事实以 `docs/mac-parity/progress.md` 和功能对齐表为准。

日期：2026-10-04，北京时间。状态：规划已完成，已开始 G01 工程与国际版基础验证；后续大功能尚未通过验收。

本规划面向产品负责人和后续实施者，定义 CastReader for Mac 的完整交付范围、复用方式、开发顺序、测试方法、验收标准及上线后的 ROI 判断。建议以 Mac Catalyst 复用已验证的 iPhone/iPad 阅读核心，交付适合电脑操作的文件和书源阅读工具，沿用 CastReader 账号与 Pro。将跨设备同步作为有独立数据协议和验收的工作包。

为覆盖本轮尚未明确的“同步”含义，本规划同时纳入 Kindle、微信读书、Kobo、Google Play Books 四书源接入，以及 Mac、iPhone、iPad、Safari 的书架与进度互通。它们是规划默认范围，不代表已经实现，也不代表第三方账号可以自动互通。若以后明确只需要四书源接入，可单独取消跨设备工作包，不影响 Mac 阅读主干。

最初版本为规划交付；当前已按用户后续指示开始 Mac 实施。实际阶段顺序、构建及测试证据以 `docs/mac-parity/progress.md` 为准；本文 P0–P10 为工作量分解，不允许跨越该进度表的逐项验收门禁。上一轮“约 10 个有效人日”是前期验证的预算建议，不是本完整范围的交付承诺。

配套文档：[测试与验收矩阵](CastReader-Mac-Acceptance-Matrix-2026-10-04.md)。其中每条用例都需在实施时补上执行状态和证据，不能把计划清单当成测试结果。

## 1 产品交付目标

用户能够在 Mac 上打开自己的文档或已授权的书源，稳定完成“朗读音频、词级高亮、自动跟随”，也能够听取讲解并看到原文上的同步标注；随后关闭窗口、退出重开或换设备，仍能找到同一份内容和正确的停止位置。

完整交付必须同时满足以下条件：

1. PDF、EPUB、DOCX、文本和网页的约定格式范围可以导入、阅读、解读、恢复与管理。
2. 四书源各自完成真实登录、书架获取、打开书、连续播放、跨页跨章和重开恢复。
3. Mac 的文件入口、菜单、键盘、指针、窗口和音频生命周期符合本规划的行为约定。
4. 账号、Pro、免费额度及克隆额度遵循现行服务端合同，与已有客户端保持一致。
5. 同步范围内的客户端完成真实双向书架、用户选择上传的文件、朗读进度和解读进度互通；离线和冲突不会丢数据。
6. 现有 iPhone、iPad、Safari 的受影响行为回归通过，最终安装包和验收源码可对应。
7. 完成用户验收、分发、上线回读、支持资料与成本归因。审核等待属于外部状态，不写成已经上线。

### 1.1 交付阶段

| 交付物 | 功能范围 | 对外含义 |
| --- | --- | --- |
| V0 技术验证包 | 可签名运行；PDF 和一个真实书源的 Read/Explain；登录、音频、窗口和本地恢复验证 | 内部验证技术路线，不对外宣称完整产品 |
| R1 Mac 功能候选 | 文件、四书源、网页、声音、账号/权益、桌面交互、本机恢复及 Safari 共存 | 可进行完整 Mac 体验验收；跨设备同步未通过时明确显示当前可用范围 |
| R2 完整交付候选 | R1 加跨设备书架、文件和进度同步；移动端/扩展配套版本及兼容迁移 | 本规划的功能完成点，随后进入正式发布 |
| R3 上线与效果回顾 | 发布状态回读、故障监测、14/30/60 天使用及收益分析 | 本规划的运营完成点 |

### 1.2 范围边界

- Word 首版明确支持 DOCX。旧版二进制 DOC、DOCM 宏文档、加密 Office 文件要准确识别并提供另存为 DOCX/PDF 的路径，不宣传已经支持。原生旧 DOC 转换作为后续独立项。
- PDF 支持文本型、扫描型和混合型；提供阅读和讲解，不提供专业 PDF 编辑、电子签名或批注导出套件。
- EPUB 支持当前解析器可读的 EPUB2/3 重排内容；固定版式、特殊脚本、数学公式等必须逐类说明能力边界。加密 EPUB 不通过移除保护处理。
- 图片和扫描文件可通过拖入、文件选择和已有 OCR 管线进入；手机摄像头式 UI 不直接搬到 Mac。连续互通相机、桌面截图快捷入口可后续增加。
- 现有云盘导入能力纳入适配，不能把“连接云盘”当作 CastReader 自身同步系统。
- 最新基线已确认 O’Reilly、YouTube、Kindle 离线、声音礼物和系统快捷入口存在，全部纳入 iOS 功能对齐及真实验收，见 40 项功能清单；不能仅作为可选回归删除。
- 保留当前网络依赖和缓存能力，也完整保留 iOS 已有的 Kindle 离线页图、Vision OCR 和系统语音播放。不新增 Kokoro 等引擎；云端讲解仍需要网络。
- 全局读取其他 App 屏幕、全局键盘监听、语音输入、常驻后台服务、企业协作、Android/Chrome/Firefox 新同步 UI 为后续项。共享协议须兼容这些客户端的既有行为。

## 3 技术路线和分发决策

### 3.1 默认采用 Mac Catalyst

选择依据是现有应用大量依赖 UIKit 文本布局、PDFKit、WKWebView 和已经验证的 iPad 阅读交互。Mac Catalyst 可以保留这些核心代码，并增加菜单、键盘与窗口适配。[Apple Mac Catalyst](https://developer.apple.com/documentation/uikit/mac-catalyst)

| 方案 | 本项目用途 | 决策 |
| --- | --- | --- |
| iPad App 直接运行于 Apple silicon Mac | 低成本观察现有操作在 Mac 上的表现 | 可作对照实验，不替代桌面交付验收 |
| Mac Catalyst | 共享模型、服务、UIKit 阅读器和大部分 SwiftUI 界面 | 默认主路线，P1 通过后冻结 |
| 原生 AppKit/SwiftUI Mac target | 某项核心能力经证据确认在 Catalyst 无法满足时的备选 | P1 形成具体阻塞和成本比较后再决定；不默认重写 |
| 扩展 Web Reader 桌面封装 | 保留网页专用提取和部分 Web 渲染能力 | 局部复用，不另起一套账号、书架、播放器主干 |

### 3.2 P1 必须消除的技术不确定性

- 当前 Xcode/SDK 下 PDFKit、WKWebView、Vision、StoreKit、AuthenticationServices 和音频 API 的可用性与行为。
- `UIApplication`、scene、`UIScreen`、方向锁、摄像头和 iOS 后台任务的调用点；区分可共用、需适配、Mac 不展示三类。
- 原生文本高亮和 Web 标注在窗口缩放、Retina 与非 Retina 显示器、系统缩放下的位置正确性。
- Google/Apple/已有地区登录方式的回调、Keychain、presentation anchor、取消与重新登录。
- 四书源的桌面 UA、Cookie 隔离、弹窗、扫码、iframe 和双栏变化；至少一个真实书源必须在验证包走完流程。
- 沙盒文件访问、Finder 打开、拖入、云盘下载、持久书签、移动文件和权限失效。
- 真实音频输出、耳机拔出、睡眠唤醒、关闭窗口和退出的行为。
- 正式签名候选能否独立安装启动；不能仅用关闭签名的 Debug 编译作为结论。

P1 输出一份技术决策记录：每项有运行证据、剩余问题、负责工作包和预计成本。无法满足 PDF、书源登录、连续播放或权益这四个主路径时，先修复路线问题，不推进大规模界面开发。

### 3.3 系统与分发的规划默认值

- 优先支持 Apple silicon；当前 Catalyst 构建解析出的最低 macOS 为 14.6，需经过真实最旧系统测试后才确认支持。Intel 单独评估，仅在具有可复现构建与真机覆盖后声明支持。
- 优先 Mac App Store，争取在现有 CastReader App 记录增加 macOS，复用同一订阅产品和账号权益。实际 App ID、capability、商店记录可行性在 P0/P1 核对。
- Apple 支持符合条件的 Catalyst 应用与 iOS 共用 Bundle ID 和 universal purchase；这不自动证明后端跨账号权益和 Safari 登录已经打通。[Apple 添加平台](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-platforms/)
- 现有 Safari Mac 宿主继续按其发布合同交付；新 Mac 主 App 第一版不重复嵌入第二份相同 ID 的 Safari 扩展。
- 官网独立分发为备选渠道，需要单独的签名、公证、更新和支付方案，不在同一个包中混入两种发布假设。Apple 对商店与站外分发列有不同要求。[Apple Mac 分发说明](https://developer.apple.com/macos/distribution/)

## 4 共享架构与实现边界

| 层 | 复用对象 | 本轮工作 |
| --- | --- | --- |
| 内容与索引 | `ReadingDocument`、History、`ContentCatalog` | 补稳定身份、内容版本和同步元数据；保持本机记录兼容 |
| 导入解析 | `DocumentImportPipeline`、PDF/EPUB/DOCX 解析、OCR、云盘 provider | 新增 Mac 文件入口和可取消任务；各入口执行同一资源限制 |
| 阅读定位 | `ReadingResumeCheckpoint`、`ResumeCoordinator`、源定位器 | 补跨设备 locator 转换、失效反馈和模式独立恢复 |
| 音频与解读 | TTS、AudioPlayer、ReadAloud、Explain、QuickRead | 抽出平台音频/生命周期适配；保持会话归属、取消和缓存合同 |
| 桌面宿主 | iPad 自适应布局、scene、键盘逻辑 | 实现侧栏、工具栏、菜单、窗口和焦点管理 |
| 书源与网页 | 四书源 store、Web scripts、WebReaderBridge、扩展提取逻辑 | 在 Mac 环境复验并作最小适配，共用提取协议和 fixture |
| 身份与计费 | Auth、Pro、Quota、克隆额度合同 | 适配 Mac 登录/购买展示，沿用服务端账号和幂等口径 |
| 同步服务 | 现有文库/上传/进度 API，完成盘点后确定 | 为缺失部分增加认证、版本、增量同步和冲突合同 |

平台差异尽量集中在文件访问、窗口、音频、登录呈现和系统入口适配器中。需要 `targetEnvironment(macCatalyst)` 的代码留在这些边界；不为 Mac 复制一整套 Read/Explain VM 或四书源脚本。

以下既有行为作为保留合同：

- 以最新 iOS 实现为准：完整原生正文持续排版，TTS 高亮仍先在 `processedDisplayText` 与 segment timestamps 坐标定位，再由 `NativeReadingTextProjection` 严格投影到原文。保留完整语义前缀、UTF-16 和恢复锚验证；不能退回旧版流式正文缩短再增长的渲染。
- `moreSegmentsExpected`、取消后的请求隔离、队列等待与失败恢复继续成立。
- Read/Explain 与多文档窗口共用一个实际播放会话；只有显式播放才转移控制权。
- PDF/照片与 Web 页面使用各自已验证的几何映射，避免缩放/滚动产生二次偏移。
- 保留最新主线的 Kindle 页序/预取、手动翻页确认、预热遮挡、微信读书和 Kobo 恢复及四书源双栏修复。
- Pro 的判定、付款入账和额度扣费不能由 Mac 客户端另起规则。

## 5 功能清单和完成标准

所有 F 编号都需在配套矩阵中有测试。以下“完成”是目标定义，当前状态统一为待实施。

### 5.1 桌面入口和交互

| 编号 | 需要实现的功能 | 完成标准 |
| --- | --- | --- |
| F01 工程与环境 | Catalyst 构建、Global 固定策略、依赖、签名、隔离测试宿主 | Debug/Release 可复现；发布包不含调试开关和 fixture；iOS target 仍可构建 |
| F02 窗口与导航 | 继续听、文件、四书源、网页、音色、账号/设置；可收起侧栏 | 800×600 最小规划窗口到全屏均可完成核心操作；滚动位置和标注不因缩放丢失 |
| F03 菜单键盘与多窗口 | 文件打开、搜索、播放控制、字号、设置、前后导航；多文档窗口 | 焦点明确；输入框空格不抢播放；A 播放时浏览 B 不抢音频，显式播放 B 才切换 |
| F04 文件入口 | Finder 打开方式、拖放、多文件选择、粘贴文本/链接、最近打开 | 冷启动/热启动均可导入；有单项进度、取消和错误；导入副本不改原文件 |

规划快捷键：⌘O 打开文件、⌘F 当前内容搜索、⌘, 设置、⌘+/⌘− 字号；空格仅在阅读非编辑焦点播放/暂停。章/段跳转快捷键在 P2 做系统冲突检查后冻结。所有核心操作都有菜单或可访问按钮，不能只靠记忆快捷键。

关闭最后一个窗口时，已在播放的会话继续并可从 Dock/系统播放控制恢复窗口；未播放时无需保持任务活跃。⌘Q 明确结束播放、保存停止点并退出。睡眠不承诺继续播放，唤醒后恢复到暂停、可继续的状态；用户主动暂停不能被系统回调覆盖。

### 5.2 文件格式与云盘

| 编号 | 需要实现的功能 | 完成标准 |
| --- | --- | --- |
| F05 PDF | 原页显示、文本抽取、扫描 OCR、混合页、目录/页跳转、缩放、词高亮与解读标注 | 预设样本阅读顺序正确；页内和跨页不漏读/重读；无文本时有 OCR 或明确反馈 |
| F06 EPUB | OPF/spine、章节目录、内嵌图片、重排字体、章节和书末行为 | 不朗读封面占位；段落/图片身份稳定；大书后台解析，改字号后可恢复 |
| F07 Word | DOCX 正文、标题、列表、表格阅读顺序、图片、链接和可理解的脚注处理 | 使用审核过的样本文本对照；不承诺与 Word 分页完全一致；旧 DOC 和损坏包有准确反馈 |
| F08 文本图片 | TXT、Markdown、RTF 等既有文本扩展；编码/BOM；图片 OCR 和多页扫描导入 | 中文/英文/混合内容可读；格式噪声不误播；导入失败不会产生假成功记录 |
| F09 云盘与资源管理 | Google Drive/Dropbox/OneDrive 既有范围；下载进度、授权撤销、源版本改变、缓存清理 | 远端引用可重开；失败保留停止点；文件变更不会静默套用旧定位；清理缓存不删用户源文件 |

文件导入按“获准访问 → 检查格式和限制 → 解析/OCR → 写入本地索引 → 显示可读内容”执行；同步上传另起明确状态。首版优先把用户选定的本地文件复制到应用管理目录，持久化外部访问只在确有需要时使用安全作用域书签。

资源上限先继承所选发布基线，不因 Mac 内存较大直接放开。此次查看的旧工作区上限为 PDF 200 MiB、EPUB 120 MiB、DOCX 40 MiB、文本 20 MiB，另有 ZIP 条目、解压总量和压缩比限制；这些是待 P0 复核的代码值，不是新的对外容量承诺。测试必须覆盖限制前后和解压过程的真实字节量。

PDF 双栏、页眉页脚、脚注、表格和扫描页要有人工标注阅读顺序的样本。数学公式和复杂图表不以“解析成功”宣称语义正确；错误顺序和无法可靠抽取的页面要反馈，并提供原页查看/选择范围路径。

## 6 同步协议与迁移方案

本节是拟实现的数据合同，接口名和实体名为设计名称。P0 先对照现有后端，能扩展已有安全接口就扩展，不创建第二套权威目录和权益来源。

### 6.1 身份与数据结构

| 实体 | 至少包含 | 约束 |
| --- | --- | --- |
| AccountScope | 服务端 canonical user ID、区域、数据版本 | 从已认证 session 取得；客户端声明的 email/user ID 不能代替鉴权 |
| LibraryItem | 稳定 item ID、source type、source account reference、provider item ID、title、revision、deleted/archived | 书名和 URL 显示文本不是唯一键；同一书源的两个账号不能误合并 |
| ContentVersion | 文件校验值或来源版本、解析器版本、语言、结构摘要 | 同名不同内容保留版本；去重限同一授权账号范围 |
| SourceLocator | 类型、章节/页引用、文本前后锚、段内偏移、定位版本 | 像素位置和设备分页编号仅作辅助，不作跨设备权威定位 |
| ProgressRecord | item/version/mode、session ID、locator、明确 seek、播放状态、完成标记、base revision | 浏览位置与收听停止点分开；Read 和 Explain 分开 |
| ExplainVersion | 讲解语言、模型/提示版本、块文本与 marks 摘要、音频引用或可重建信息 | 更换讲解版本后不能沿用旧音频秒数；账号和内容权限必须一致 |
| SyncOperation | operation ID、主体、动作、base revision、设备/会话序号、待发/已确认状态 | 幂等，可重放；服务端修订为冲突依据，客户端墙上时钟只作展示 |
| Tombstone | 删除对象、服务端 revision、删除世代、保留截止 | 旧设备不能把删除条目复活；过期游标必须执行明确的重新同步 |

文件身份使用校验值结合账号和内容版本；云盘引用还记录 provider、文件 ID、版本标识和导出格式。原站书源身份采用 provider 的稳定书 ID 与账户作用域，换账号后不能沿用上一账号的授权或恢复结果。

### 6.2 推拉和失败恢复

1. 本地修改先写入同一事务下的内容/进度记录和持久待发队列；应用崩溃后可继续发送。
2. 批量推送携带 operation ID 与 base revision，服务器返回每项确认、当前 revision 或冲突；部分失败不能将整批重复应用。
3. 增量拉取使用服务端 cursor；完成本地事务后才推进 cursor。分页失败可重试，不丢中间页。
4. 前台播放建议每 5 秒保存本地 checkpoint；暂停、跳段、切模式、切内容、退出立即保存。远端进度建议每 10 秒合并发送，暂停/移交时立即发送。
5. 文件按现有受保护上传合同或经审计的新协议上传，先生成授权上传意图，校验最终内容和归属后才发布可下载引用。未完成上传不能显示“其他设备可用”。
6. 上传重试复用同一操作身份；允许底层上传方式按现有存储能力选择，不虚构已支持断点续传。下载完成核对校验值，再原子替换本地文件。
7. 超时/临时错误进行有上限退避；401 转重新登录，权限/额度错误不盲重试。后台任务被系统暂停时持久保留队列，不承诺持续运行。
8. 内容删除、账号退出和账号切换会取消对应在途任务。Mac 不提供区域切换。回调再次校验账号、区域和内容世代，禁止跨账号落盘。
9. 同步关闭不会阻断本机阅读。状态显示最后成功时间、待同步项和可操作错误，不把网络失败显示成空书架。

### 6.3 冲突处理规则

| 冲突 | 约定行为 |
| --- | --- |
| A 刚听到第十章，离线 B 上传第一章旧会话 | 保留 A 当前停止点，B 作为历史分支；不按上传到达时间直接覆盖 |
| 用户明确回退到较早章节并播放 | 这是新的有效意图，可以成为最新停止点；禁止简单取“最大进度” |
| 两台设备从同一修订开始各自播放 | 保留两个会话，界面显示位置与设备供选择；不能静默丢弃一个 |
| 只滚动/搜索查看了后文 | 只改变浏览位置，不改变收听停止点 |
| 删除条目与离线编辑冲突 | 已确认删除世代优先；恢复需新的显式恢复动作，不自动复活 |
| 一次书架抓取失败或只抓到部分页 | 不当作删除依据；只有来源确认或用户操作才移除 |
| 同一文件更名/重复导入 | 能确认同内容时复用内容身份；同名不同内容保留不同版本 |
| 原网页/云文档内容改变 | 尝试内容锚定；失败保留旧位置摘要，提示重新定位，不悄悄从头播放 |
| 私人声音在新设备无权限 | 保留用户偏好记录，明确提供可用声音，不能借同步绕过权限 |
| 旧客户端不识别新 locator/schema | 保持可读兼容字段，禁止覆盖其不理解的字段；必要时提示升级 |

Tombstone 的初始保留窗口建议 30 天，最终随存储成本在 P7 冻结。超过窗口重新上线的设备必须按 server reset epoch 重新同步目录，不能将历史本地全量当作新数据上传。

### 6.4 内容和进度可用性的区分

- 只同步了书架/进度但没有上传的本地文件：另一设备显示“需要原文件”，选择同一文件后可校验恢复。
- 第三方书源未登录：显示“连接该书源后继续”，登录完成后重新验证来源 ID 和可读性。
- Safari 没有匹配的网页或支持的阅读器：保留远端继续项，打开合适页面或主 App；不承诺扩展直接打开所有二进制文件。
- 四书源正文、Cookie 和 DRM 保护内容不进入文件同步对象存储。用户自有文件和主动保存的网页内容按实际授权处理。
- 不同步本地窗口大小、显示器坐标、绝对路径、系统音频设备和临时缓存任务。

### 6.5 兼容迁移与发布顺序

1. 盘点已有 web/extension/mobile 进度键和账号标识，定义旧→新映射与不可恢复情况。
2. 服务端先发布可兼容旧客户端的增量 schema 和接口；执行迁移 dry run、权限测试、索引和成本检查。
3. 客户端先以受控账号启用影子读取/比较，确认新旧内容 ID 和位置匹配。影子阶段不得重复上报扣费和播放时长。
4. 按服务端 → Mac → iPhone/iPad → Safari 支持版本顺序接入；每个依赖版本记录最低协议版本和开关。
5. 启用同步前创建可恢复的本地索引迁移备份；迁移可重复执行，磁盘不足/中断不得破坏旧索引。
6. 为新协议保留停用开关。停用只停止新同步写入，保留本地阅读、已有云文件和旧客户端的有效行为。

| P9 完整质量验收 | F30–F32；全矩阵、性能、长时、无障碍、本地化、安全、升级和安装 | P2–P8 各阶段通过 | 全部发布必需项通过，无未解决阻断缺陷 | 5–8 人日 |

本表是未跑 Catalyst 验证前的预算模型，合计 **37–65 个有效工程人日**，包含后端和各客户端工作；加入 25% 集成与未知问题准备量约 **47–82 人日**。它不是对实际开发速度的测量，也不把 AI 生成代码时长等同于工程工期。若现有同步后端与客户端已覆盖大部分合同，P7/P8 应按差距下调，禁止重复实现。

P0/P1 合计预算 3–6 人日；最迟在累计投入约 10 人日时复核技术和商业前提。超过该验证预算仍无法完成 V0 时，先记录具体阻塞与路线调整，避免继续扩大范围。完整范围按单人串行折算约 10–17 个工作周，另外计入至少两周 Beta 日历观察与商店外部等待；多人安排应按依赖重排，不能直接除以人数。

P2–P6 可以形成 R1；R1 的可用候选仍需执行 P9 中相关质量用例和 P10 的内部验收。同步需求不明确时先冻结协议草案，避免在 UI 里假设“所有数据已经云端存在”。

### 7.1 每项实施的记录格式

每条工作记录必须写：功能编号、用户行为、基线事实、实现文件/提交、依赖、测试输入、执行命令或手工步骤、实际结果、证据路径、未解决问题及下一动作。状态只能是 PLANNED、IN_PROGRESS、PASS、FAIL、BLOCKED、NOT_RUN、N/A；N/A 必须说明与已冻结范围的对应理由。

功能完成的顺序为“实现 → 有意义的自动检查 → 真实端到端 → 问题修复复验 → 验收记录”。编译通过、静态字符串命中、模拟音频或仅有界面截图，都不能单独作为阅读功能 PASS。

## 8 测试策略和量化门槛

### 8.1 测试层级

| 层级 | 重点 | 证据 |
| --- | --- | --- |
| 静态/构建 | SDK、target membership、资源、权限、签名、发布 fixture 排除、地区路由 | 构建日志、产物清单、签名检查、有效的阳性对照 |
| 单元/契约 | 导入、locator、内容身份、会话状态机、幂等、账号隔离、额度、冲突与迁移 | 有明确行为断言的用例及结果；不为简单样式重复写镜像测试 |
| 集成 | 真实 AVPlayer、WKWebView、PDFKit、文件系统、OAuth callback、后端事务 | 音频/事件记录、测试接口回执、文件校验值 |
| UI/端到端 | 干净安装到首次价值；四书源；登录/恢复购买；Mac→手机→Safari | 真实操作录像、关键截图、结构化事件及包身份 |
| 长时/性能 | 大文档、连续播放、切换内容、音频路由、网络中断和内存 | Instruments/系统指标、p50/p95、异常列表及可复现场景 |
| 用户验收 | 用户自己的文档和书籍能否完成任务 | 操作清单、实际问题、验收结果；不以自动测试代替主观体验 |

已有测试候选包括 `EpubNativeEngineTests`、`ReadingResumeTests`、`ReaderDropImportTests`、`DocumentImagePreservationTests`、`PDFImportMemoryTests`、`LocalDocumentCacheTests`、四书源契约测试、`CloudImportIntegrationTests` 和 `ProStatusSynchronizationTests`。实施时先检查所在主线的真实名称与适用平台，不能把路径存在当成可运行或已通过。

### 8.2 环境矩阵

- Mac：最低支持系统和发布时最新正式系统；Apple silicon 至少一台低内存设备与一台常用开发设备。Intel 只有纳入支持范围才增加构建和真机验收；未测不能写 PASS。
- 显示与输入：800×600、约 1280×800、全屏；外接显示器、Retina/非 Retina；鼠标、触控板、键盘和 VoiceOver。
- 客户端：Mac、iPhone、iPad、Mac Safari；已支持的 iPhone/iPad Safari 按其公开能力和本次受影响路径回归。纯 Web/其他扩展保持协议兼容。
- 区域：Mac 仅 Global，账号、session、端点与数据域固定国际版。测试 CHN storefront、中国时区、旧 CN 偏好和 CN 启动参数均不能切换区域；iOS 另跑既有区域回归以确认未受影响。
- 身份：游客、免费、有效 Pro、到期、取消但仍有效、退款/撤销、会话到期、A→B 切账号；克隆余额正数/零/扣费中/购买后。
- 声音：基础、社区、私人，中文与英文；其余现行支持语言做代表文本冒烟；Read/Explain 均覆盖。
- 网络：稳定、受控高延迟/丢包、断开、恢复、DNS/超时、401/403/429/5xx、流中断；冷生成和热缓存分别统计。
- 文件：每种核心格式至少普通/复杂/大体积各一个，另有损坏、限制边界、加密/不支持、Unicode 文件名、同名不同内容。

高风险路径做明确交叉矩阵：Global×Read/Explain×三类声音，以及账号切换×生成/同步在途、四书源×宽窄窗口×跨页/恢复。其余使用有记录的组合覆盖，避免没有依据地穷举全部排列。

### 8.3 性能测量与门槛

下列数字为本规划建议的验收目标，不是现有实测成绩。P1 用固定机器、文件、网络、账户与音色完成至少 20 次可比测量，冻结正式门槛；后续变更目标须记录理由和对用户的影响，不能到验收时只放宽数值。

| 指标 | 建议目标 | 测量方式 |
| --- | --- | --- |
| 冷启动可操作 | p95 ≤ 3 秒 | 干净启动到侧栏/打开文件可响应，剔除构建首次启动但单独记录 |
| 普通文件首次内容 | p95 ≤ 3 秒 | ≤10 MiB 可提取文本 PDF、普通 EPUB/DOCX；扫描 OCR 单独计时 |
| 大文件/OCR 可响应性 | 1 秒内显示任务反馈；取消后 2 秒内停止新增处理工作 | 测 UI 和任务事件，后台解析中不阻塞窗口操作 |
| 热缓存首音 | p95 ≤ 1 秒 | 从点击播放到真实输出，已具备有效本地音频 |
| 云端冷首音 | 同区同声同文基线 p95 不恶化超过 20% 或 1 秒中的较大值 | Mac 与已验证客户端对照；同时记录绝对值，用户明显等待不能因相对达标被忽略 |
| 词高亮显示时差 | 相对当前 segment timestamp p95 ≤ 250 ms | 输出时钟与屏幕帧对照；另有人耳检查，不能用此值宣称声学标注绝对准确 |
| 受控连续音频 | 已有可播下段时，应用引入的意外停顿 >500 ms 为失败 | 与用户暂停、站点动画、冷生成等待分别分类并全部记录 |
| 四书源真实翻页 | 完成每源长时窗口，0 次卡死、重复翻页或丢页；等待与已验证源基线比较 | 实际播放/页面事件及录像；不宣称音频零静音 |
| 停止点可靠性 | 正常暂停/退出保存到当前句；强制终止最多丢失 5 秒 checkpoint 窗口 | 固定文本与时间对照；不可提前跳过未听内容 |
| 前台同步 | 成功提交后另一在线前台端 p95 ≤ 10 秒可见 | 至少 30 次双向操作；后台受系统调度限制单列，不承诺实时 |
| 内存趋势 | 固定文本场景热身后 60 分钟无持续无界增长；重复开关 20 次后稳定值增加 ≤20% 或 100 MiB 中较大值 | 同时计入 WebKit 子进程，记录峰值与缓存策略；图像大书另外建基线 |
| CPU 与能耗 | 缓存播放/暂停不持续忙循环；同场景稳定 CPU/能耗不较 P1 基线恶化 >20% | 排除 OCR/合成下载阶段，记录热身和稳态窗口 |
| 同步/购买幂等 | 受控重复、重排、重试、崩溃恢复中 0 次重复记账/跨账号写入/静默丢失 | 用服务端账本和操作 ID 对照，不能只看余额 UI |

扫描 OCR 的文字准确率、双栏顺序和 marks 锚定使用有人工参考答案的样本；稳定夹具要求预期锚全部正确，真实复杂文档逐项列出无法处理的元素。不能把跳过所有标注视为解读成功。

### 8.4 长时与恢复测试

四书源按第 5 节各自跑长时；本地 EPUB/PDF 各 60 分钟，网页至少 30 分钟。另选一个高风险来源做 2 小时连续运行，包含音色切换、暂停、网络中断、恢复、窗口切换和重复打开。最终候选针对变更范围复验；前序有效结果必须有源码差异证据才能继承。

崩溃注入点至少包含：文件复制中、解析中、索引提交后未确认、上传完成未入库、同步事务中、购买成功未刷新、TTS 生成中和解读块切换中。恢复后检查内容身份、停止点、队列、账本和临时文件，不能仅确认“App 能启动”。

## 9 验收执行和证据要求

### 9.1 测试账号与资料

使用专门测试账号覆盖免费、Pro、额度和四书源授权；账号凭据只进入既有安全存储，报告只写不敏感的别名。用于功能和云同步的资料必须有测试使用授权。真实用户数据不用于破坏性迁移、删除、购买重试或权限攻击用例。

拟建立以下资料集合，文件名为规划名称，不代表文件已经生成：

- `mac-standard-documents`：中英文本 PDF、扫描 PDF、混合 PDF、EPUB2/3、图文 EPUB、DOCX、TXT、Markdown、图片。
- `mac-edge-documents`：双栏、脚注、表格、RTL、CJK/emoji/组合字符、长章、空章、错误编码、损坏 ZIP/PDF、资源限制边界。
- `mac-live-libraries`：四书源每源两本真实授权书及准确定位点，记录登录步骤、地区、页面形态和预期跨章位置。
- `mac-sync-fixtures`：同内容不同文件名、同名不同内容、修改版云文件、两个设备的离线分支、删除与恢复、旧 schema 数据。

每份样本记录校验值、来源/授权、语言、大小、结构特点和参考定位。音频测试记录真实输出，不用生成响应 200 替代“用户确实听见正确声音”。

### 9.2 缺陷级别与发布规则

| 级别 | 示例 | 处理 |
| --- | --- | --- |
| S0 | 跨账号读到文件/声音，凭据泄露，错误扣费，无法恢复的数据丢失 | 立即阻断发布；关闭受影响新功能，保全证据并修复复验 |
| S1 | 任一承诺书源无法登录/连续播放，核心文件无法打开，频繁崩溃，恢复到错误内容 | 修复后重跑相关端到端和受影响回归；不得用文案掩盖核心失败 |
| S2 | 非核心布局问题、明确可绕过的次要操作问题 | 有具体影响、复现、绕行和修复归属；只有不违背完整交付标准才可接受 |
| S3 | 不影响任务完成的细节和后续体验建议 | 登记后续迭代，不阻断已达标主路径 |

R2 发布必需用例全部 PASS；BLOCKED/NOT_RUN 不是通过。必须按已冻结支持范围解释 N/A，不能为赶进度把应测项改为 N/A。真实站点服务故障可记录外部阻塞，但不能据此把该来源标成已经验收。

### 9.4 用户验收脚本

由产品负责人使用 R2 最终签名候选执行，测试人员可以准备账号和资料，但不能代替用户判断阅读是否顺畅。

| 步骤 | 用户操作 | 应看到的结果 |
| --- | --- | --- |
| U01 | 在干净 Mac 安装，打开应用，查看主要入口 | 产品身份明确；无调试界面、空白壳或强制无关配置 |
| U02 | 拖入自己的一份 PDF、EPUB、DOCX | 进入正确文档，可看到导入状态和明确错误；原文件保持不变 |
| U03 | PDF 从指定段落朗读，滚动查看其他内容，再回到跟随 | 读到所选内容，声音与高亮一致，自动跟随控制可理解 |
| U04 | 同一文档切到解读，暂停、换声音、继续 | 听到讲解；原文圈线在对应内容；暂停和换声行为正确 |
| U05 | 缩小、放大、全屏、移动到另一显示器，打开第二文档 | 不丢标注/位置；浏览另一窗口不抢播 |
| U06 | 连接四个书源，各打开书并跨页/章；退出重开 | 书架完整度与样本一致；从之前听到的内容继续 |
| U07 | Safari 正在阅读一篇文章，点击在 Mac 中继续 | 正确条目和位置打开；明确移交后不双播；扩展仍正常工作 |
| U08 | 在 Mac 主动同步一个文件，在 iPhone/iPad 打开并继续 | 文件可用，位置一致；未上传的文件明确提示需要原文件 |
| U09 | 手机再听一段，Mac 回来继续；然后制造离线冲突 | 正常情况恢复新位置；冲突有可理解选择，不悄悄覆盖 |
| U10 | 现有 Pro 登录 Mac，恢复购买，查看克隆余额 | 权益一致；不要求重复购买；生成和缓存播放扣费正确 |
| U11 | 暂停后睡眠唤醒；拔耳机；断网再恢复；⌘Q 后重开 | 不意外出声，不丢停止点，不卡在无解状态 |
| U12 | 移除下载、移除书架、删除云副本、退出并切另一个账号 | 操作含义清楚；无误删源文件或账号数据串用 |

交付前提供一页“已支持范围、已知限制和版本要求”。核心验收有失败就回到对应工作包；用户明确接受的次要问题与测试通过分开记录。

## 10 打包发布和上线处置

### 10.1 发布准备

1. 冻结候选并核对所有仓库的源码与资源身份，确认集成门禁和必需用例完成。
2. 使用独立 DerivedData 做 Release 归档；核对 Mac 架构、最低系统、沙盒权限、Keychain/App Group、URL/document types、隐私资源和本地化。
3. 保留已有 iOS/Share/Widget/Safari 的构建与资源合同。Mac 不可构建的扩展要明确过滤或建立适配 target，不能把 SDK 错误通过误删移动端功能解决。
4. 商店渠道使用正式商店签名和上传流程；若采用官网包，单独验证 Developer ID、Hardened Runtime、公证、stapling、带下载隔离标记的安装及更新链路。
5. 在无开发环境依赖的普通用户环境测试首次安装、升级、卸载后按既定策略保留的数据和重新安装；升级不能更改用户源文件。
6. 盘点 Mac 与 Safari 宿主共存：名字/图标/帮助入口清楚，现有扩展注册唯一，安装顺序不同仍正常。

### 10.2 商店与 Beta

- 优先复用现有 App Store Connect 记录添加 macOS；在实际操作前核对 App ID、平台绑定和产品可用性。版本号和 Build 在发布时读取实际最大值，不预写死。
- 先做内部 Beta，再邀请具备实际 Mac 阅读需求的测试者。邀请发送属于后续明确执行安排，本次没有联系任何人。
- 准备 Mac 实际截图、所有当前目标语言的产品说明/更新说明、支持 URL 和完整可复现的审核步骤；标题、描述、关键词、审核备注统一审计。
- 审核演示使用可提供的测试内容，说明登录、文件、书源、音频和付费入口。无法提供第三方账号的部分应准备可验证的合法演示路线和准确说明。
- 现有 iOS 发布报告曾记录第三方平台名称相关元数据问题；Mac 文案需逐字段检查具体适用规则，不能把一次历史拒审推断为对所有名称的永久禁令。
- 对隐私/权限信息先核对新增数据流和声明是否一致；产品价格、地区、订阅、法律声明等按现有规则处理，所需实质变更单独形成具体决策。

### 10.3 上线和故障处置

服务端同步以测试账号→小范围→扩大覆盖逐步启用；开关必须按功能独立，不能通过关闭整个账号或 TTS 服务处理 Mac 专项问题。商店审核通过、可下载、用户实际拿到版本是不同状态，分别记录。

严重同步故障先停用新增同步写入，保留本地阅读和数据；必要时提供修复版本。支付错误停用有问题的新购买入口并保留合法已购权益，依据账本纠正，不能批量重置所有用户。

商店二进制不能假设即时回滚。准备服务端兼容开关、暂停扩大覆盖、紧急修复构建和支持说明；若采用站外分发，可保留上一签名版本，但必须验证其能安全读取新数据，不允许用旧包破坏迁移后的文件。

上线后 24 小时、72 小时和 7 天检查崩溃、首播失败、书源登录、同步失败、重复扣费和支持反馈；使用批准的监测方式执行，本次未创建自动化。

## 11 业务验证和 ROI

记录每个工作包的实际工程投入和新增维护时间，将共享同步建设中属于其他客户端的收益/成本单列。不能把所有基础设施成本都归到 Mac，也不能把所有现有 Pro 用户的收入都归功于 Mac。

| 指标 | 口径 | 用途 |
| --- | --- | --- |
| 首次有效使用 | 安装/首次打开后完成至少 60 秒真实播放，或完成一个可听且有正确标注的解读块 | 判断导入、绑定和首次价值是否顺畅 |
| 核心任务完成率 | 开始任务的用户中，成功完成文件阅读、书源阅读、移交/同步继续的人数比例 | 找出具体入口阻力，失败用户不能从分母剔除 |
| 第二周重复使用 | 第一周有效用户中，第二周至少两个不同日期有效使用的比例 | 观察持续价值，剔除仅由测试要求造成的使用时另行展示 |
| 新增付费 | 因 Mac 首次进入或明确推动升级的新增付费，按账号去重 | 估算收入增量，已有订阅安装不计新增收入 |
| 续费改善 | 可比用户队列的续费差异，控制原本就高活跃用户自选择偏差 | 形成假设，样本不足时不作因果结论 |
| 平台迁移 | 从 Safari/iPad 转为 Mac 的既有用户及实际总使用变化 | 识别便利提升与纯使用搬迁 |
| 增量成本 | TTS/LLM、存储/流量、免费用户用量、退款/渠道、客服和维护 | 计算贡献毛利和长期负担 |

建议 Beta 为 20–30 名有真实需求的用户，连续两周，优先覆盖文件阅读者和四书源使用者。规划的方向性目标为：核心任务成功率至少 90%，至少 40% 在第二周重复使用；小样本只用于决定下一轮改进，不证明市场规模或盈利。

30 天回顾使用来源与首播/导入问题；60 天回顾转化、维护负担和早期续费信号。商业门槛以真实收入/成本更新：

`首年增量利润 = 新增付费贡献 + 额外续费贡献 − 一次性工程投入 − 持续维护 − 额外免费用量成本`

贡献口径先扣渠道、退款和相应付费服务变动成本，避免重复扣除。上一轮“2 万元投入、200 元/用户年贡献、约 100 个用户年回本”只是演算示例，不能当作预算事实或本次完整范围的报价。

若 Mac 使用主要是既有用户迁移，但支持负担低、总活跃和满意度提高，可维持轻量版本；若新增长期不足且每次上游变更需要独立大量维护，应缩减扩展范围和重复实现。技术验收和商业效果分别报告。

# 中国区生成服务慢:全链路归因与扩容决策

> 2026-08-15 晚,全部数据为当晚现场实测。结论已闭环,扩容方案待观察一两天后决策。
> 相关文档:《智能路由与生成服务解耦-跨端合同》《中国区适配-产品需求技术架构与Android交接规范》。

## 0. TL;DR

- **朗读卡 = AutoDL 共享边缘代理晚高峰拥堵**。那台 4090 与 Kokoro 服务完全健康(90 字合成 0.52s,三连稳定);同一句话走公网边缘 0.8–17 秒随机跳,抖动全在响应传输段。机器不用动,**出口是死穴**。
- **解读慢已修掉客户端大头**:快道在中国线路被 `key != null` 锁死(从未启用)+ WeRead 全量预取块,修复后同文章首声 **26s → 3.5s**。剩余波动来自 worker 全局串行队列、v4-pro 吞吐、TTS 节点抖动三个服务端因素。
- **待决**:腾讯云同 VPC GPU(T4 包月约 ¥1.8–3k/月)内网直挂,根治出口;worker 并发 1→3;每块输出压缩。观察期后拍板。

## 1. 朗读(TTS)链路

### 1.1 实测拓扑(逐跳核实过,非推测)

```
手机(上海电信) --HTTPS--> api.castreader.cn(腾讯云上海五区 BF1.MEDIUM4, 172.17.0.5)
  nginx: location = /api/captioned_speech_partly
    --proxy(境内,连接 7ms)--> uu122431-80b4-9c6a8f65.bjb1.seetacloud.com:8443   ← AutoDL 共享边缘(TLS)
        --> 实例内 proxy --> gunicorn:6008(reader-service-lite, Flask 4w×4t, 改路径转发)
            --> uvicorn:8880(Kokoro-FastAPI, /dev/captioned_speech, GPU 推理)
```

- 实例:AutoDL bjb1 机房,RTX 4090 24G(VRAM 占 7.3G),容器配额 16 核(宿主 128 核)。
- 运行目录:`/root/autodl-tmp/castreader-runtime/releases/20260724-kokoro-ja-vn28-delisted-clean-cn-r129`。
- SSH:`ssh -p 12085 root@connect.bjb1.seetacloud.com`。

### 1.2 逐层数据(2026-08-15)

| 层 | 测量 | 结论 |
|---|---|---|
| GPU | 空闲 29°C/15W;合成时功耗 62W | 推理在卡上,健康 |
| Kokoro(实例内网直打 :6008) | 90 字 **0.52 / 0.55 / 0.52s** | **服务本身快且稳** |
| 容器 CPU | 配额 16 核;限流占比 0.015% | 无伤 |
| 宿主机 | 128 核,PSI cpu some=59% | 超售,但未伤到本容器 |
| AutoDL 边缘(同一句话,同一分钟,从网关盒子测) | 0.80 / **3.00** / 0.83s;TTFB 稳定 0.65s,抖在传输段(260KB 快时 0.15s、慢时 2.35s ≈110KB/s) | **抖动全在边缘/共享出口** |
| 晚高峰(20:30–21:35) | 同路径 2 字排队 7.7s;90 字 12–14s;173 字最快 3.2s/最慢 17.4s | 拥堵时段生成赶不上播放 → 卡 |

## 2. 解读(QuickRead)链路

### 2.1 实测拓扑

```
手机 --HTTPS--> quickread.castreader.cn(同一台网关盒子)
  nginx(access_log off, proxy_buffering off) --> 127.0.0.1:3000 Next.js 网关
    ├─ 会话校验 --> Supabase 美东共享库(TCP 握手 226ms;伪 token 401 实测 0.43–1.29s/次)
    ├─ 续传操作再查 job 绑定 --> 美东(每次续传多付一轮)
    └─ --> 127.0.0.1:7777 worker(回环)
         └─ 全局串行队列(activeJob 同时只跑 1 个) --> DeepSeek v4-pro(境内 211.95.70.108, 49 tok/s)
旁白 TTS 复用 §1 链路。
```

- nginx 不缓冲 SSE,网关按行透传(block0 可早到)。链路本身无结构性缺陷。
- 唯一跨境残留 = 美东会话/作业库,每调用 0.3–1.3s,是税不是墙。

### 2.2 两场对照实验(同文章、同手机、CN 线路)

| 场次 | 首声 | 分解 |
|---|---|---|
| 22:26(竞速超时 12s,队列有残留) | **26s** | 快道 12s 被判负(差 2s 就赢)+ 兜底 plan 排在被弃快道后 8.6s + TTS 5s |
| 22:34(超时 25s,队列干净) | **3.5s** | 快道 LLM 2.4s + 旁白 TTS 1.0s |

后续块节奏(v4-pro):每块 ~3000 token ÷ 49 tok/s ≈ 40–60s 生成 + compose 8–27s(也占串行队列)——块间可能断流。
已知 bug:v4-pro 下 `extract-plan error: invalid QuickRead plan: substantive paragraph 0 skipped inside streamed block boundary` 当晚两次复现,触发静默重试(修复需 worker 源码仓库,本机只有部署产物)。

### 2.3 已落地修复(Android `feat/china-region`)

- `789a8d8`:快道全线路解锁(拆 `key != null` 门控——CN 会话鉴权下 key 恒 null,快道从未在中国启用过);WeRead 懒取块(只等 block0 开口,边播边取)+ 补齐快道竞速与开头段兜底。
- `49d74cb`:CN 竞速超时 12s→25s(串行队列下兜底必然更慢,宽超时纯收益)。
- 华为真机已装,fastlane outcome=fast 实证,首声 3.5s。

## 3. 待决事项(按见效排序)

### 3.1 TTS 出口:腾讯云同 VPC GPU 内网直挂(根治朗读卡)

```
手机 → api.castreader.cn(BGP 带宽) → nginx upstream 172.17.x.x:6008(同 VPC 内网,免费)
                                        └─ backup: AutoDL 4090(自动回退)
```

步骤:①控制台购 CVM **GN7(1×T4 16G, 8核32G)**,地域上海、**VPC 选网关同一个**(172.17.0.0/20),GPU 优化镜像,先按量;②rsync AutoDL 的 runtime+权重过来重建;③验收 90 字 <1.5s 三连稳(T4≈4090 算力 1/4,82M 模型预计 1s 上下,不达标升 A10);④nginx 原子切换,AutoDL 降 backup;⑤过一个晚高峰达标后决定 AutoDL 去留。客户端零改动。

| 项目 | 费用(以控制台为准) |
|---|---|
| 验证期 T4 按量 | ¥2–3/时,半天 ≈ ¥15–40 |
| **T4 包月** | **≈ ¥1,800–3,000/月** |
| 升档 A10 24G | ≈ ¥4,000–6,000/月(仅 T4 压不住时) |
| 系统盘 100G | ¥30–100/月 |
| 内网流量 | 0 |

### 3.2 worker 串行队列 1→3(消解读波动第一放大器)

DeepSeek 是远程 API,并发 3 安全;26s vs 3.5s 的对照就是队列放大的。改部署 `server.mjs` drain + 重启(数秒中断),或等 worker 源码仓库正式改。**当晚已提议,用户选择暂不改。**

### 3.3 国际线解读:撤掉东京绕路,并回美东(2026-08-15 深夜补充)

现状 `Vercel 网关(美东) → ty-proxy(东京 Vultr, qr.castreader.ai, Caddy→worker:7777) → Gemini`。
实测美东→东京 200–210ms/往返,一场解读 8–15 次调用白付 ~5–10s;而美东连 Gemini 边缘仅 9–26ms。
东京中转的历史使命(中国用户够 Gemini)已被 CN 线 DeepSeek 取代,纯负资产。

- **为什么不能直接放 Vercel**:worker 是有状态常驻进程——作业内存态(job map、跨块滚动摘要、
  串行队列)+ 作业资源文件(截图/GIF/音频),续传调用必须回到同一进程;且单作业分钟级、网关超时
  设到 900s。Vercel 函数无实例亲和、无共享内存、有时长上限——迁入=把状态全部外置的重构(数天),
  不是搬家。网关留在 Vercel,worker 需要一台真机。
- **推荐**:Vultr 美东小机($6–12/月,worker 仅占 238MB 内存)整体承接;切流用 Vercel 环境变量
  `QUICKREAD_UPSTREAM`(秒切秒回滚),稳定后挪 `qr.castreader.ai` DNS,退租东京(净成本≈0)。
  不建议并到 us4090(Vast.ai 可回收清盘,且职责已约束为 TTS 生产)。
- **源码情报**:东京 `/root/castreader/video-pipeline` 为全球 worker 源码树(非 git);
  **CN 部署副本比它新**——plan 严格校验器(`substantive paragraph … skipped`)只存在于 CN 版,
  这正是校验失败只在中国区出现的原因。修 bug/合流以 CN 版为基。本地工作副本已拉到会话 scratchpad。
- 顺带:清单里 `sg-proxy`(新加坡,7 月起失联)同类遗留,一并清理。

### 3.4 其他

- **每块输出压缩**(worker,compose 只回短引文):单块 40–60s → 8–12s,进秒级的唯一杠杆;需源码仓库。
- **iOS 改走 .cn 网关**:现硬编码 AutoDL 边缘域名,不切则永远吃抖动且节点无法轮换(已写进跨端合同待办)。
- **CN 会话近端化**(短 TTL 缓存或区域读副本):省每调用 0.3–1.3s 的美东税,次要。
- 模型档位:用户定为 **v4-pro 不动**(质量优先)。

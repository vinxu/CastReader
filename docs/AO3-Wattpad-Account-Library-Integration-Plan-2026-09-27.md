# AO3 / Wattpad 账户绑定、书架同步与阅读接入

日期：2026-09-27。状态：实施规划；尚未实现新来源、完成真实账户验收或发布。

## 目标与范围

按用户要求，将 AO3 与 Wattpad 纳入与 Kindle 同一套书架交互：**书架来源 → 原站登录 → 同步作品 → 首页展示 → 打开作品 → 朗读或解读 → 退出后继续**。这成为近期第一优先级，前期讨论的人名纠音、离线准备与分享属于后续迭代。

本轮客户端范围为当前仓库的 iOS App，包含现有 iPhone / iPad 布局；“两个平台”指 AO3 和 Wattpad。Android、桌面扩展和 Safari 扩展新增书架同步不在本轮默认范围内，数据契约保留未来复用空间。

用户无需反复复制章节链接，也无需先下载整部作品。可访问作品的元数据先进入书架，正文按实际打开章节读取，复用朗读、高亮、滚动、讲解与原文标注能力。

## 统一用户流程

| 环节 | 用户交互 | 完成条件 |
|---|---|---|
| 入口 | “书架来源”新增 AO3、Wattpad，与 Kindle 并列 | 首页和来源页都能进入 |
| 绑定 | App 内打开原站登录页 | 验证真实登录账户及本人书架；看到公开作品不算登录成功 |
| 同步 | 显示“正在同步，已找到 N 部作品”，允许取消 | 区分完整、部分、空书架和失败 |
| 完成 | 账户标识、作品数量、查看作品／返回首页 | 状态和作品持久化，重启后仍在 |
| 首页 | 平台作品横排、“查看全部”、最近打开优先 | 沿用 Kindle 的卡片尺寸、点击方式和布局组件 |
| 打开 | 回到有效章节，同一阅读器切换朗读／解读 | 复用绑定登录态，不重复要求登录 |
| 退出 | 迷你播放器、首页继续、关闭重开 | 章节、位置及播放意图一致，暂停后不自行播放 |
| 维护 | 重同步、重新登录、解除绑定 | 不改原站书架；失败不误清空；换账号不串数据 |

首次绑定完成后进入该平台书架；选择作品后进入现有阅读器，不随机打开一本书。已有自动播放设置按当前规则执行。

绑定成功但书架为空仍是有效连接：来源管理显示“已绑定，暂无作品”，首页可显示简洁空态与同步入口。“暂时无法读取书架”必须单独显示，不能记成 0 本成功。

## 平台数据语义

### AO3

官方 FAQ 明确，History 是登录期间访问过的作品，按最近访问排序，可显示更新信息；Mark for Later 是待读标记，与历史设置有关。**访问过不等于正在读，作品记录也不等于准确章节位置。**

- 默认优先“最近阅读”，符合把原站在看的作品带到首页的目标。
- “稍后阅读”和收藏可选择同步，保留各自来源标记。
- 同一 work 在多列表出现只显示一部作品；系列与单部作品分开。
- 私人收藏备注、自由文本“读到第几章”不当作可靠进度，也不为同步书架额外采集。
- 历史关闭时显示真实原因，并提供收藏／加入作品等可用路径，不自动修改原站设置。
- 首版更新信息以用户请求同步时取得的结果为准，不承诺实时后台提醒。

来源：[AO3 官方 History / Mark for Later FAQ](https://archive.transformativeworks.org/faq/history-and-mark-for-later?language_id=en)。本轮未取得登录后的实际 DOM，字段和分页须验证后实现。

### Wattpad

- 优先验证个人 Library 中 Current Reads 的实际页面，承接正在看的作品。
- Reading Lists、Archive 为可选范围，不把列表归属直接等同于已读状态。
- story ID 表示作品，part ID 表示章节，不能混用。
- 原站提供可信的继续章节时可作为首次打开入口；只有作品、没有位置时，打开目录或让用户选择章节。
- 此后由 CastReader 保存确认过的朗读／解读位置，不声称自动恢复在原站读到的每一句。
- 需要登录、解锁或暂不可访问的内容仍遵循原站流程。

Wattpad 登录态 DOM、书架字段、分页／懒加载和原站进度未验证，不能凭其他平台实现猜定 selector、Cookie 或内部 API。

## 首页与进度

首页沿用 Kindle 的平台区块。卡片显示作品名、作者、来源、封面或标题占位、可确认的继续位置。AO3 没有封面时用标题卡，不虚构封面。

优先显示在 CastReader 最近打开的作品，其次使用可信原站最近阅读顺序。待读收藏进入完整书架，不自动将全部收藏铺满首页。

进度分三层保存：

1. 作品：原站稳定作品 ID、平台与账户归属。
2. 章节：章节 ID、阅读 URL、目录顺序。
3. 位置：CastReader 确认的段落／句子锚点及正文版本。

首次打开使用原站有效入口；已有精确位置时不被旧书架百分比覆盖。用户在原站跳到另一章或原文大幅改动时，保留来源、时间和精度，必要时提供选择；不能永远取“更大百分比”，因为用户可能重读。

更新、删除和同名作品不能导致错误合并。无法匹配时返回章节选择，不静默跳到猜测位置。

### 必须补的会话接点

最新主线 WebReaderView.makeUIView 中，专用 livePlatform 和 WeRead 使用共享会话；普通 .web 路径没有自动选择相同 profile。只增加登录和书架 UI，再把作品当普通链接打开，会有重复登录的风险。

新来源必须将绑定会话接到阅读器，限制在正确来源、账户和域范围。无需导出外部浏览器 Cookie，也不应把原站凭据发给后端或写进日志。

### 建议数据契约

- PlatformAccount：平台、稳定身份摘要、显示名、会话状态、同步时间。
- PlatformWork：work/story ID、账户归属、标题、作者、封面、链接、列表归属、最近访问证据、可选章节数。
- PlatformChapter：父作品 ID、chapter/part ID、标题、链接、顺序、可访问状态。
- PlatformCheckpoint：作品、章节、内容指纹、锚点、来源、时间、精度、模式。
- ShelfSnapshot：账户身份、同步代次、来源列表、加载范围、完整／部分／空／失败状态。

只同步用户可访问范围，不在绑定时生成整本音频。部分结果允许增量合并，不可用于删除旧书；网络失败、登录过期、取消均保留有效缓存。解绑、换账号或新同步启动后，旧请求不得写回。

解除绑定默认只移除 CastReader 中对应来源的关联与缓存，不改原站作品和书架。是否同时退出原站由明确的独立操作表达，不顺带清除其他平台共享 profile。

## 两条阅读管线必须同时验收

| 操作 | 朗读 | 解读 |
|---|---|---|
| 首页打开 | 正确章节正文、出声、跳读、高亮和滚动 | 当前章节原文、真实讲解音频、原文标注 |
| 手动换章 | 停旧请求，重新绑定新章 | 取消旧讲解与标注，不画到下一章 |
| 模式切换 | 交接播放器和暂停状态 | 只有用户请求才开始讲解 |
| 自动下一章 | 本章自然读完，同作品且可访问时推进 | 当前讲解与标注完成后，按既有推进规则处理 |
| 退出／返回 | 恢复内容、位置、播放意图 | 不重复生成任务或误重放旧标注 |
| 登录失效／锁定 | 提供原站处理入口，不读错误页 | 不把登录页／解锁提示当正文发送 |

下一作品、推荐、评论分页不能作为下一章。Wattpad 既有扩展实现因缺少可信父作品身份禁用了自动跳章，iOS 同样须先证明关系，不能简单放开保护。

“与 Kindle 类似”是上述操作一致，不代表自动获得 Kindle 专用离线下载、原站全部功能或跨设备精确位置。

## 实施阶段

1. **真实账户与数据验证。** 每个平台以一个用户授权测试账户验证登录、本人书架、分页、作品详情、目录和正文；产出字段契约与脱敏夹具。没有真实页面证据时不把猜测适配器固化。
2. **绑定、同步、首页。** 完成统一入口、账户隔离、快照、首页卡片、空态、失败、解绑重绑；作品打开复用登录。仅这一阶段完成不叫“全面支持”。
3. **完整阅读。** AO3 复用专用提取，Wattpad 补对应适配；完成朗读、解读、章节切换与退出恢复。
4. **最终验收。** 两个平台分别用真实多章作品跑完整流程，再进入发布准备。未收到发布请求前不改商店版本或提交审核。

### 完成标准

- 两平台 App 内真实登录与正确账户身份；取消不产生假绑定。
- 同步结果可回读，部分或失败不会清空书架。
- 首页立即展示，重启仍在，空书架状态准确。
- 首页打开复用登录态，受限内容仍走原站流程。
- 两平台真实多章作品分别通过朗读和解读：声音、高亮／原文标注、滚动、跳读、暂停、换声、模式切换。
- 连续换章不误跳、不漏正文；用户停止后旧回调无效。
- 退出、迷你播放器、重启、正文更新后的定位正确；未知位置不伪装精确恢复。
- CastReader 账号 A → B → A、平台换账号、解绑后旧请求，不串书架和进度。
- iPhone / iPad 的来源页、原站登录、书架、阅读器和大字号布局通过。
- 现有 Kindle、EPUB、AO3 网页及权益／播放所有权相关回归通过。

自动化验证覆盖边界与状态转换；真实登录、音频、高亮和标注另留实际证据，不用夹具数量替代。

## 当前事实与未决项

已完成架构核对、最新基线选择、隔离分支准备和本规划。两平台未登录的直接请求本轮均返回 HTTP 403；内置浏览器导航超时，未取得已登录书架。该现象不能证明无法接入，但也不能把真实登录与同步记为已验证。

后续需要测试账户在原站完成登录后的页面验证，无需在聊天中提供密码。当前没有新建账户、接受条款、读取或导出其他浏览器凭据。

准确工期要在第一阶段确认 Wattpad 登录、动态书架和正文结构后估算。两平台独立验收，不能把“两入口已显示”当成“两平台全面支持”。

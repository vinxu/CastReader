# iOS ASO 结构性工作框架（2026-07-29 起）

> 一句话：ASO 不是「改一次关键词」，是**六层系统 + 固定节奏的迭代回路**。
> App Store 排名 ≈ f(关键词相关性, 分词下载速度, 转化率, 评分, 市场竞争度)——五个输入各有一层结构性工作，外加节奏层把它们串成回路。

## 第 1 层 · 测量（一切的地基）✅ 已建

- `scripts/aso_rank_snapshot.py`：8 市场 × 39 词排名时间序列 → `docs/aso/rank-history.jsonl`，**每周一跑**，自动对比上次
- 07-29 基线的关键发现：**美区全灭但小市场已有滩头**（GB read aloud #50 / IT #62 / ES #64 / BR #82 / JP #86）——结构性含义：先在低竞争市场把「词→速度→排名」回路跑通，再攻美区
- 缺口：ASC Analytics（impressions/PPV/CVR）暂靠后台人工；订阅报表等 Vendor Number

## 第 2 层 · 词库（活资产，不是一次性清单）✅ 已建种子

- `docs/aso/keyword-corpus.md`：词 × 意图簇（大词/场景/人群/自有）× 排名 × ASA 数据 × 字段分配 × 决策
- **数据飞轮**：ASA 搜索词报表是唯一的真实 query + 转化率来源 → 每周回填 → 验证过转化的词才升仓（关键词字段 → 副标题 → 名称）
- 分配纪律：token 不跨字段重复；美区三索引位（en-US + es-MX + zh-Hans）统一调度（v2 已铺）

## 第 3 层 · 转化（排名的隐形输入：CVR 差的词爬不动）

- **评分引擎**：1 条评分是当前最大转化拖累。review prompt 随 1.2.14 上线；目标 8 周美区 50+。每周快照盯每个 storefront 的条数
- **PPO（Product Page Optimization）**：1.2.15 上线后开第一组 Apple 原生 A/B——首屏截图「词级高亮」vs「7 天试用」，跑满 90 天或显著即换下一组；PPO 是常驻实验位，不许空转
- 素材本地化：采集管线已固化（AppStoreCaptureUITests），按市场滚动补 9 语截图

## 第 4 层 · 版位（能被索引的面全部占满）

- 语言版位：v2 新增 de-DE（德区目前**没有德语页**，排名为零是应然）/ zh-Hant / es-MX；下一批评估 en-GB（解锁 GB/AU 独立关键词字段——GB 已有 #50 滩头，值得）
- **IAP 名称被索引**：订阅显示名从 "Pro Monthly" 改为带关键词（如 "Pro — Unlimited Read Aloud"），随 1.2.15
- **In-App Events**：事件卡出现在搜索结果里 = 额外索引面。第一个事件绑 Back to School（8 月中提交）
- 中国区：ICP 落地即上 zh-Hans 全套（词库另建，竞争烈度完全不同）

## 第 5 层 · 速度注入（排名的主权重是分词下载速度）

- **ASA 定向脉冲**：从 corpus 挑 2–3 个「ASA 已验证转化 + 自然排名 50–100」的词，Exact 集中预算打 2 周 → 自然排名上来后撤火移到下一组。这是用钱直接买排名权重的唯一合规路径
- 免费速度源：Featuring（已提名 ×2）、博客 SEO（castreader.ai 已有排名文章导流）、Chrome 扩展互导
- **纪律：ASA 提价/换词决策只在 1.2.15 上线后做**——竞价入场 = 出价 × 页面相关性，旧页面上的调价数据全是噪声

## 第 6 层 · 节奏（把上面五层串成回路）

| 频率 | 动作 |
|---|---|
| 每周一 | 跑排名快照 + 捞 ASA 搜索词 → 回填 corpus → 值得动的记入下版发版清单 |
| 每次发版 | 必带一轮关键词字段迭代（关键词是版本锁定字段，**版本节奏 = ASO 迭代节奏**，建议双周版）|
| 每版上线后 | PPO 换组实验；检查 featuring 提名窗口 |
| 每月 | corpus 大盘重排：字段升降仓、滩头市场战报、ASA 脉冲换目标 |

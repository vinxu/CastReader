# 朗读滚动抖动修复

日期：2026-09-14。工作树：`CastReader-epub-toc-20260914`，保留本轮 EPUB TOC 实现和已验证 iOS 1.2.39 发布祖先。

Android 对齐见[实施规范](EPUB-TOC与朗读滚动-Android对齐实施规范-20260914.md)：Compose 单一滚动所有者、88% 触发/25% 落点、动画合并、PDF 坐标换算与逐模式验收。

## 原因

原生文本的 `TextReaderView` 在段落变化、高亮变化、流式文本变化时执行段落定位；如果当前 `ReaderUITextView` 还没有高亮范围，则无条件 `scrollTo(paragraph, anchor: .top)`。与此同时，`ReaderUITextView` 在布局后按词位置把目标放到阅读区域。预取音频转正时会先清空高亮，下一次播放 tick 才提供新词，因此同一次切段先顶到顶部、再返回阅读区。重排 PDF 与 EPUB 共用此组件。

真实 SwiftUI/UITextView 宿主回归在修复前记录到滚动偏移 `[-62, 92, 92, -62]`，即本来可见的下一段无故移动154点再返回。EPUB 与重排 PDF 均复现；日志 `reader-viewport-reproduce.log`，结果包 `/tmp/CastReaderViewport-reproduce.xcresult`。

PDF 原稿模式另有两条滚动路径：切句直接 `PDFView.go(to: fullSentenceSelection)`，词级/续读定位又执行另一套可见性与定位规则。长句选区与当前词不是同一目标，存在二次校正。同步移除整句强制导航，注释高亮仍保留。

## 修复

- 统一阅读区域规则（按用户最终澄清）：目标仍在18%–88%的可读区内就保持原位；接近下缘时平滑移动到正文可见区域距顶部25%处，即离底部75%的位置，受文档首尾边界限制。落点与88%触发线分开，避免刚滚完就重触发。采用 UIKit 连续滚动动画，避免瞬间修改偏移。远距离恢复或跳转不飞越多页；系统“减弱动态效果”开启时尊重该设置。
- 新段尚未收到词时间戳时，以首字或恢复位置为目标；首词到达后沿用同一条路径。SwiftUI 等原生视图更新后再定位，不读取上一帧的高亮状态。
- 词变化由布局完成后的词定位负责，合并重复排队的布局跟随；暂缺字形不再被当作滚到段落顶部的命令。
- 远距离懒加载使用段首点锚，直接落入阅读区；目录显式跳转继续使用目录目标顶部，保持 TOC 精度。
- PDF 原稿按首字/恢复词/当前词统一跟随，不先滚整句选区；忽略属于旧段落的排队词指令。拖动和惯性滚动期间不争抢滚动。
- 动画期间按计划落点判断可见性，不用每一帧的中间位置重启滚动；相同目标（包括文末钳位）合并为一次动画。

2. 重排 PDF 同样不发生顶部往返。

5. PDF 原稿可见句子保持原位；屏幕外句子直接进入阅读区，首词到达不引发第二次校正，保留高亮 annotation。

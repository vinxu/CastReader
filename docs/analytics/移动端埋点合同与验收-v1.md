# CastReader 移动端埋点合同与验收 v1

> 生效范围：iOS、Android 与 `castreader.ai/api/events`。机器可读真源为 `mobile-events-v1.json`。

## 1. 实施原则

- 只记录用户意图、实际体验结果和结构化失败，不记录正文、OCR、书名、文件名、完整 URL、邮箱或原始错误。
- `read_start` 与 `read_first_audio` 分开；`explain_start` 与 `explain_first_block` 分开。点击不等于成功。
- 所有重试复用原 `eventId`；服务端按 `event_id` 幂等。每次朗读、解读和购买尝试使用独立会话 ID。
- iOS 与 Android 共用事件名称、结果枚举、属性类型和阈值，端内 `surface`、`entryPoint` 保留产品差异。
- 当前客户端采用双格式兼容：同时发送 v2 字段和旧 `/api/events` 所需的 `event/deviceId/timestamp/version`。旧后端可接收，升级后的后端以 v2 字段校验和分析。

## 2. 核心漏斗

```text
app_session_start
→ content_intent
→ content_ready | content_failed
→ read_start → read_first_audio → read_milestone → read_end
                     或
→ explain_start → explain_first_block → explain_milestone → explain_end
→ paywall_shown → purchase_start → purchase_result
```

## 3. 固定枚举

- `environment`：`production / development / test`
- `clientPlatform`：`ios / android`
- `result`：`success / cancelled / blocked / failed`
- `contentSource`：`camera / photo_library / file / url / text / clipboard / history / kindle / unknown`
- `contentFormat`：`photo / pdf / epub / docx / text / web / kindle / unknown`
- `intendedMode`：`read / explain`
- `completionBucket`：`none / lt_25 / 25_49 / 50_79 / 80_99 / complete / unknown`
- `read_milestone.milestoneSeconds`：`30 / 180 / 300 / 600 / 1800`
- `explain_milestone.milestone`：`first_block_completed / second_block_started`
- `purchase_result.result`：`success / cancelled / pending / blocked / failed`
- `purchase_result` 的兼容事件按结果映射：`success → checkout_completed`、`cancelled → checkout_return_cancel`、其余结果 → `checkout_error`；不能把取消或失败伪装成购买成功。

错误只允许 `errorStage + errorCode`。`errorCode` 必须来自端内受控映射，例如 `permission_denied`、`empty_content`、`network`、`http_401`，不能直接使用 `localizedDescription`。

## 4. 会话和身份

- `anonymousId` 是独立的第一方分析 UUID，不复用额度、风控或第三方 provider ID。
- `backendUserId` 仅在登录且已经归一化到后端用户 ID 时发送。
- App 冷启动创建 `appSessionId`；后台超过 30 分钟再回前台创建新会话。
- 每次内容处理创建 `contentSessionId`；进入阅读器但没有前置处理上下文时，由协调器补建。
- 每次真实朗读开始创建 `readSessionId`，从发起到完成、失败、切换模式或关闭为止。
- 每次解读开始创建 `explainSessionId`。
- 每次 StoreKit / Play Billing 调用创建 `purchaseAttemptId`。

## 5. 有效价值阈值

- 朗读：实际播放达到 300 秒，或短内容完成度达到 80%。
- 恢复阅读：从历史或恢复入口继续实际播放达到 180 秒。
- 解读：首块播放完成度达到 80%；第一版以 `first_block_completed` 里程碑表示。
- 客户端只上报里程碑事实；WMRU、留存和购买前价值由服务端派生，客户端不得上报 `isRetained`。

## 6. 六层验收

每个事件必须留下同一个 `eventId` 的六层证据：

1. **触发层**：真实 UI / ViewModel 路径只触发一次，失败、取消、阻断分别可复现。
2. **合同层**：事件名、必填属性、类型和隐私禁键通过本地 schema 测试。
3. **队列层**：断网后事件仍在持久队列；恢复网络后使用原 `eventId` 重发。
4. **接收层**：`/api/events` 返回 `code=0`，且不是 `degraded drop`；未知事件和未知属性有明确拒绝结果。
5. **落库层**：PostgreSQL 能按 `event_id` 查询；重复发送两次只有一条；`occurred_at` 与接收时间均可见。
6. **分析层**：同一 `contentSessionId/readSessionId/explainSessionId/purchaseAttemptId` 能按顺序闭环，iOS/Android 可拆分也可统一汇总。

仅看到 HTTP 200、客户端日志或代码中的 `track()` 都不算验收完成。

## 7. 发布门禁矩阵

| 场景 | 必须出现 | 必须不出现 |
| --- | --- | --- |
| 首次启动 | 1 个 `app_session_start` | 重复 session start |
| 成功导入 PDF | `content_intent → content_ready` | `content_failed` |
| OCR 无文字 | `content_intent → content_failed(empty_content)` | `content_ready` |
| 朗读成功 5 分钟 | start、first audio、30/180/300 milestone、end | 首音前 milestone |
| TTS 首段失败 | start、end(failed) | first audio |
| 解读首块完成 | start、first block、first-block-completed、end | 重复 first block |
| 解读 402 | start、end(blocked)、paywall | success end |
| 购买取消 | paywall、purchase start、purchase result(cancelled) | success result |
| 购买成功 | paywall、purchase start、purchase result(success) | 客户端续订/退款事实 |
| 断网重试 | 队列保留、恢复后落库 1 条 | 新 eventId、重复落库 |

App Store / Play 提交前必须分别完成以上矩阵，并运行跨端合同一致性检查与后端落库验收脚本。

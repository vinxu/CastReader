## 2. 合同范围

统一 15 个 canonical event：

```text
app_session_start
content_intent / content_ready / content_failed
read_start / read_first_audio / read_milestone / read_end
explain_start / explain_first_block / explain_milestone / explain_end
paywall_shown / purchase_start / purchase_result
```

iOS、Android 使用同一个事件名、必填/可选属性、结果枚举、隐私禁键与里程碑。`surface` 和 `entryPoint` 保留端内差异，后端统一存储 `client_platform` 以支持合并或分端分析。

## 3. 真实触发点

| 事件 | iOS 事实层 | Android 事实层 |
| --- | --- | --- |
| `app_session_start` | App 启动与后台超过 30 分钟再激活 | `MainActivity` 生命周期与 30 分钟会话状态机 |
| `content_intent` | 用户确认相机、文件、URL、文本、剪贴板、历史或 Kindle 入口 | Import/Capture/Kindle 的用户确认入口 |
| `content_ready` | `ReadingDocument` 构建成功或 Kindle 首页正文可读 | OCR、PDF、EPUB、Web、文本或 Kindle 解析为可读内容 |
| `content_failed` | 空内容、无效 URL、OCR、读取或解析的结构化失败 | OCR、读取、解析和输入校验的结构化失败 |
| `read_start` | 额度检查通过并开始朗读编排 | `PlaybackController` 接受真实朗读请求 |
| `read_first_audio` | `AudioPlayerService.isPlaying == true` 且存在当前 segment | ExoPlayer 实际回调 `isPlaying == true` |
| `read_milestone` | 实际媒体时间增量累计，跳转单次最多计 2 秒 | 单调时钟只在实际播放状态累计，单次最多计 2 秒 |
| `read_end` | 完成、关闭、切模式、额度阻断或 TTS 失败 | 完成、关闭、切内容/模式或 TTS 失败 |
| `explain_start` | 解读请求通过本地内容与额度预检 | 各 Reader/QuickRead 接受解读运行 |
| `explain_first_block` | 讲解音频实际开始播放 | MediaPlayer `start()` 或 Kindle ExoPlayer 实际播放 |
| `explain_milestone` | 首块达到 80% 有效阈值；第二块实际开始 | 首块达到 80% 有效阈值；第二块实际开始 |
| `explain_end` | 完成、关闭、切模式、402 或管线失败 | 完成、关闭、切模式、额度/402 或管线失败 |
| `paywall_shown` | Paywall 真正 `onAppear`，同一次展示只记一次 | `PaywallDialog` 真正进入 Composition |
| `purchase_start` | 调用 StoreKit 前创建 `purchaseAttemptId` | 调用 Play Billing 前创建 `purchaseAttemptId` |
| `purchase_result` | StoreKit 的 success/cancelled/pending/blocked/failed | Play Billing 的 success/cancelled/pending/blocked/failed |

购买兼容事件按结果动态映射：成功才是 `checkout_completed`；取消为 `checkout_return_cancel`；pending、blocked、failed 均为 `checkout_error`。

## 6. 审计中发现并修复的问题

1. Android `content_intent` 曾使用 Kotlin 位置参数，导致 `contentSource/contentFormat` 错位并会被严格合同拒绝；已改为命名字段并新增回归测试。
2. Android 原先每个事件立即发请求，不能形成有效批量；已改为 2 秒防抖，后台时立即 flush。
3. 购买结果曾可能固定兼容成 `checkout_completed`；两端和后端现均按五类结果严格映射。
4. iOS 解读有效阈值原先只在整块完成时触发，与 v1 的 80% 定义不一致；已对齐并测试边界。
5. 初版数据库 E2E 的 `SET search_path` 可能因连接池切换而失去隔离；已改为连接参数固定 schema，并验证自动清理。

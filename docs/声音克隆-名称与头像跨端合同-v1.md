# 声音克隆名称与头像跨端合同 V1

> 文档状态：跨端实现基线（2026-08-31）
> 适用端：iOS、Android、Chrome 扩展、Web，以及全球区/中国区声音克隆控制面
> 上位规范：[声音克隆跨端权限与技术架构统一规范](./声音克隆-跨端权限与技术架构统一规范.md)
> 后端生产基线：`readout-web` `origin/beta` `3f1ded7afdf027461dc00b09adbc01d9be0c5892`（identity 引入提交 `74c48ceac76e7001304b2e178cdd09e3e96fb952`）
> iOS 发布基线：`CastReader` 1.2.31 Build 51 `0120f4c2181d0243cd6e903462250e25a9e4516f`（identity 引入提交 `a4438e0dfa2d8f06763018dc7a7ef47fe357fe48`；编辑入口健壮性修复 `d497686d4b692675a7690aa78271399027bbc205`）

本文只定义“一个已创建声音如何在不同端被稳定识别”：默认名称、自定义名称、头像、缓存、重命名和旧数据兼容。创建质量、试听、朗读、额度和部署仍以上位规范为准。

名称和头像是**呈现元数据**，不是声音本身。任何名称、头像或 identity 服务异常，都不得让一个已经可用的声音创建失败、消失、无法试听或无法朗读。

---

## 1. 产品结论

所有端统一遵守以下规则：

1. **先创建，后命名。** 创建前不要求用户填写名称；创建成功页展示服务端分配的默认名称和头像，并提供可选“修改名称”。
2. **默认名称由服务端序号、客户端语言共同组成。** 服务端只保存 `autoNameIndex`，客户端显示本地化的“我的声音 N / My Voice N”；不得把某一种语言的默认名称写入数据库。
3. **用户可随时修改名称或恢复默认名称。** 自定义名称跨端同步；恢复默认名称发送 `name: null`，不是发送空字符串或“我的声音 N”。
4. **头像由服务端分配并解析。** 客户端直接渲染响应中的 `avatar`；不得各自根据 `voiceId`、名称或 `avatarToken` 发明颜色和图形算法。
5. **同一个 `voiceId` 的头像稳定不变。** 重命名、切换语言、切换深浅色、退出重登、列表排序、跨设备使用，都不能改变头像。
6. **名称是主要识别信息，头像是辅助识别信息。** 头像样式组合可能重复，任何业务逻辑、无障碍信息或测试都不得只靠颜色/图形区分声音。
7. **identity 可以暂时为空，但声音仍然有效。** 客户端展示安全占位并后台刷新；不得删除声音、清空列表、取消选择或阻止 TTS。
8. **服务端是名称和头像的唯一权威。** 本地缓存只能改善冷启动显示，不能覆盖更高 `revision` 的服务端值。

### 1.1 稳定规则编号

| 编号 | 不可变规则 |
| --- | --- |
| `VC-I01` | 创建请求不要求名称；创建成功后再允许重命名 |
| `VC-I02` | 默认显示名 = 本地化模板 + 服务端 `autoNameIndex` |
| `VC-I03` | 列表顺序、创建时间和本地计数不得代替 `autoNameIndex` |
| `VC-I04` | `customName` 非空时优先于默认名称 |
| `VC-I05` | `name: null` 恢复默认名称，空字符串是非法输入 |
| `VC-I06` | 客户端渲染服务端返回的 `avatar`，不得自行解析 `avatarToken` |
| `VC-I07` | 名称修改只增加 `revision`，不得改变 `voiceId` 或头像 |
| `VC-I08` | identity 缺失或失败只降级呈现，不影响创建、试听、选择和 TTS |
| `VC-I09` | 本地缓存必须按账号和服务区域隔离，并保留最高 revision |
| `VC-I10` | 所有显示克隆声音的入口必须使用同一名称与头像投影 |

## 2. 创建后的用户流程

### 2.1 创建前

- 用户只需要选择录音语言、录音并确认本人声音授权。
- 示例文本是可选提示，名称也是可选的创建后操作。
- 不得在录音页增加“必须先起名”门槛。
- 不得把名称或头像字段加入创建接口的必填参数。

### 2.2 创建成功

创建接口返回 `voiceId` 后，成功页立即展示：

- 服务端 identity 可用：稳定头像 + 本地化默认名称。
- identity 暂不可用：安全占位头像 + 临时默认文案，同时后台刷新列表。
- “修改名称”：可跳过，不阻塞“完成”“试听”或“立即使用”。

创建成功后不得自动把声音应用到所有语言。用户仍需在声音选择器中明确选择；名称/头像逻辑与应用权限互不耦合。

### 2.3 已创建列表

每一行至少包含：

- 头像；
- 最终显示名称；
- 录音语言/可用语言等辅助信息；
- 固定试听；
- 当前选中状态；
- 管理菜单：修改名称、删除。

“修改名称”不能只存在于创建完成页。历史声音和其他端创建的声音也必须可编辑。

### 2.4 其他显示入口

以下入口必须使用同一套 `displayName(identity)` 与 `avatar(identity)`：

- 创建完成页；
- Created / My Voices 列表；
- 声音选择器；
- 阅读器当前音色按钮及面板；
- 解读音色选择；
- 固定试听状态；
- 删除确认和重命名页面；
- Web 与扩展的声音管理页。

不得在某个入口显示自定义名称，另一个入口仍显示 `vc_...`、固定“Cloned Voice”或列表序号。

## 3. 服务端 identity V1

`GET /api/voice-clone/voices` 的每个声音，以及 `POST /api/voice-clone/voices` 的成功响应，都可以携带：

```json
{
  "identity": {
    "schemaVersion": "v1",
    "nameMode": "auto",
    "autoNameIndex": 3,
    "customName": null,
    "avatarToken": "v1:012345abcdef",
    "avatar": {
      "styleVersion": "v1",
      "backgroundStart": "#6879E8",
      "backgroundEnd": "#5138B8",
      "foreground": "#FFFFFF",
      "glyph": "wave-ripple"
    },
    "revision": 1
  }
}
```

`identity` 整体允许为 `null`，便于旧数据迁移和局部故障降级。只要核心声音记录仍为 active，客户端就必须保留声音。

### 3.1 字段语义

| 字段 | 规则 |
| --- | --- |
| `schemaVersion` | 当前只接受 `v1`；未知版本按 identity 暂不可用降级，不能判声音失效 |
| `nameMode` | `auto` 或 `custom`；必须与 `customName` 状态一致 |
| `autoNameIndex` | 账号内稳定正整数；创建时服务端分配；客户端不得重算 |
| `customName` | `custom` 时为规范化后的名称；`auto` 时必须为 `null` |
| `avatarToken` | `v1:` + 12 位小写十六进制；是服务端内部稳定 token，客户端视为不透明值 |
| `avatar` | 服务端已解析的跨端视觉参数，客户端直接渲染 |
| `revision` | identity 乐观锁版本；正整数；每次有效名称变更递增 |

`voiceId` 仍是选择、试听、删除、朗读和额度结算的唯一业务主键。名称、头像、列表位置均不能替代它。

### 3.2 默认名称

统一投影：

```text
if identity.customName != null:
    displayName = identity.customName
else if identity.autoNameIndex > 0:
    displayName = localize("My Voice {N}", identity.autoNameIndex)
else:
    displayName = localized distinguishable temporary fallback
```

要求：

- 中文示例：“我的声音 3”；英文示例：“My Voice 3”。
- 其他语言使用本端现有 i18n 资源，不把英文或中文硬编码进模型层。
- `autoNameIndex` 不随删除、重排、分页、跨端刷新而改变。
- 绝不能用“当前列表第几行”作为 N。服务端通常按创建时间倒序返回，因此列表第一项可能叫“我的声音 4”，这是正确行为。
- 自定义名称可以重复；名称不是唯一键。重复名称仍由头像和其他辅助信息帮助识别。
- identity 缺失时的临时名称在同一列表内也必须可区分，例如账号内临时序号或 `voiceId` 短后缀；不得让所有声音都只显示同一个 “My Voice”。该临时值不能写回 customName。

### 3.3 名称校验

客户端与服务端必须保持相同语义：

- 输入类型：字符串或 `null`。
- 字符串先做 Unicode NFC，再按 ECMAScript `String.prototype.trim()` 去除首尾空白。
- 空字符串非法；恢复默认名称必须发送 `null`。
- 最大 40 个 grapheme cluster，同时最大 1024 个 Unicode code point。
- 禁止 C0/C1 控制字符及 `U+2028/U+2029`。
- 支持任意语言、普通标点和 emoji；这是私有名称，不套用公共音色库的内容审核规则。

字数提示必须按 grapheme 口径展示，不能简单以 UTF-8 字节数代替。

## 4. 头像呈现合同

### 4.1 为什么返回 token 和解析结果

`avatarToken` 用于服务端稳定分配；`avatar` 是所有客户端的最终渲染输入。后端同时返回两者，是为了防止 Swift、Kotlin、JavaScript 的哈希或 Unicode 实现差异导致同一个声音在不同端显示不同头像。

客户端必须：

- 保存 token 以完整缓存 identity；
- **只使用 `avatar` 里的颜色和 glyph 渲染**；
- 不根据 token、voiceId、customName 或 autoNameIndex重新计算正式头像。

### 4.2 V1 视觉规范

- 外形：圆形。
- 背景：`backgroundStart` 到 `backgroundEnd` 的左上至右下线性渐变。
- 前景：使用 `foreground`；V1 当前为 `#FFFFFF`。
- 主图形：居中，占圆形直径约 40%～45%。
- 可选描边：1 px 白色、约 24% 透明度；深浅色模式均保持服务端主色，不反转渐变。

`glyph` 的概念映射：

| 服务端值 | 含义 | iOS 参考 | Android / Web 建议 |
| --- | --- | --- | --- |
| `wave-bars` | 音频条形波 | `waveform` | 等宽竖条波形 |
| `wave-pulse` | 脉冲波形 | `waveform.path.ecg` | 连续折线/脉冲 |
| `wave-orbit` | 向外广播 | `dot.radiowaves.left.and.right` | 中点 + 双侧弧线 |
| `wave-ripple` | 单侧涟漪 | `wave.3.right` | 三层向右波纹 |

平台图标可以有轻微形态差异，但不能把四种值都画成同一个“人像”或同一个麦克风。

### 4.3 状态叠加

播放、加载、当前选择、Pro 锁定和删除中是 UI 状态，不属于 identity：

- 试听播放时可以临时显示动态 waveform；停止后恢复 identity glyph。
- 播放按钮、勾选、锁、loading 应作为角标或独立控件，不修改头像颜色/token。
- 重命名不得触发头像刷新或重新随机。

### 4.4 identity 缺失时的占位

identity 为 `null` 或版本不支持时：

- 使用本端安全的通用人声/波形占位；可以基于 `voiceId` 做**仅本地临时稳定**配色。
- 同一列表内的临时名称或头像必须至少有一项可区分多个声音，不能全部退化为相同名称、相同人像。
- 占位不是正式跨端身份，不得写回服务端或覆盖随后返回的 identity。
- 名称和头像缺失不能隐藏试听、应用或删除入口。
- 打开编辑时可先刷新一次；仍无 identity 则提示“名称同步暂不可用，声音仍可正常使用”，不能报“声音不存在”。

## 5. 重命名 API 与并发

### 5.1 请求

```http
PATCH /api/voice-clone/voices/{voiceId}
Content-Type: application/json

{"name":"Bedtime","expectedRevision":1}
```

恢复默认名称：

```json
{"name":null,"expectedRevision":2}
```

`expectedRevision` 必须取当前显示 identity 的 revision，不能固定传 1；合法范围是整数 `1...2,147,483,646`。

### 5.2 成功响应

```json
{
  "code": 0,
  "data": {
    "voiceId": "vc_...",
    "identity": {
      "schemaVersion": "v1",
      "nameMode": "custom",
      "autoNameIndex": 3,
      "customName": "Bedtime",
      "avatarToken": "v1:012345abcdef",
      "avatar": {
        "styleVersion": "v1",
        "backgroundStart": "#6879E8",
        "backgroundEnd": "#5138B8",
        "foreground": "#FFFFFF",
        "glyph": "wave-ripple"
      },
      "revision": 2
    }
  }
}
```

客户端必须验证：

- 返回 `voiceId` 与请求一致；
- revision 严格大于请求的 expectedRevision；
- 返回名称等于规范化后的目标状态；
- identity V1 所有字段合法。

只有验证通过才更新 UI 和缓存。

### 5.3 幂等与冲突

- 如果第一次 PATCH 已提交但 200 响应丢失，使用旧 revision 重试同一目标名称时，服务端把“更高 revision 且名称已相同”视为成功。
- 真正跨设备冲突返回 HTTP 409、`VOICE_IDENTITY_CONFLICT`，并在响应根部携带最新 `identity`。
- 客户端先采用更高 revision 的最新 identity，再提示用户名称已在其他设备修改；不得用旧值静默覆盖。
- 用户再次确认时，使用最新 revision 发起新请求。

### 5.4 错误处理

| HTTP / code | 客户端动作 | 不得做的事 |
| --- | --- | --- |
| 404 `VOICE_NOT_FOUND` | 先刷新；仅在权威 GET 确认该 voiceId 不再存在后移除 | 仅凭一次 PATCH 404 就删除本地声音；清空整个列表 |
| 409 `VOICE_IDENTITY_CONFLICT` | 采用最新 identity，按上节处理 | 静默覆盖另一设备 |
| 422 `VOICE_IDENTITY_INVALID` | 保留声音，显示字段级校验信息 | 报创建失败或删除声音 |
| 503 `VOICE_IDENTITY_UNAVAILABLE` | 保留声音和旧缓存，允许稍后重试 | 阻止试听/朗读、清空名称 |
| 网络超时/取消 | 保留编辑内容；刷新确认是否已提交 | 盲目回滚到更低 revision |

## 6. 缓存与跨端一致性

### 6.1 缓存作用域

identity 缓存必须至少按以下三元组隔离：

```text
serviceRoute + canonicalAccountId + voiceId
```

- 退出登录、切换账号或切换区域时清空当前内存投影。
- 不得把 A 用户的名称/头像短暂显示给 B 用户。
- iOS/Android 的中国区和全球区缓存必须分开。
- Web 与扩展只有全球区，不得尝试读取中国区账号或声音。

### 6.2 合并规则

列表刷新时：

1. 同一 voiceId 优先保留 revision 更高的有效 identity。
2. 服务端暂时返回 `identity:null` 时，可保留同账号同区域的最近有效缓存。
3. 更低 revision 的迟到请求不得覆盖更高 revision。
4. GET 明确确认 voiceId 已不存在时才清理该声音缓存；网络失败不能当作空列表。
5. 创建 POST 返回的新声音在 GET 列表尚未观察到前要保留，避免最终一致性窗口让新声音闪退消失。

缓存从不参与服务端授权、TTS voiceId、额度或删除判断。

### 6.3 区域边界

- iOS 与 Android 才有中国区/全球区线路选择。
- Web 与 Chrome 扩展只接入全球区。
- 同一全球账号下，移动端全球区、Web 和扩展应看到相同 voiceId、名称、头像和 revision。
- 中国区移动账号与全球账号是隔离数据域；不承诺在 Web/扩展看到中国区声音，也不得跨区复制 identity。

## 7. 服务端数据与迁移原则

identity 存在独立的 `voice_clone_identity` 表，不写进核心声音资产表，目的是让呈现服务可以独立失败：

- 主键：`voice_id`；随声音物理删除级联清理。
- 归属：`user_id`。
- 默认名称：`auto_name_index`，账号内唯一。
- 用户名称：`custom_name`，允许 null。
- 头像：`avatar_token`。
- 并发：`revision`。

新声音激活后 best-effort 分配 identity；分配失败不能撤销已成功创建的声音。GET 会对缺失 identity 做 best-effort 回填。

历史声音迁移规则：

- 按 `created_at ASC, voice_id ASC` 分配稳定的 autoNameIndex。
- 历史头像 token 可由 voiceId 确定性生成；新创建声音由服务端生成随机 token。
- 迁移、双区域发布或 identity 表短暂不可用时允许 `identity:null`。

identity 是手动数据库迁移，全球区和中国区数据库必须分别执行、审计和记录迁移 SHA；只部署接口代码而未迁移某一区域时，该区域只能安全降级为 `identity:null`，不能让核心声音接口报错。

头像组合不是数据库唯一键；真正唯一标识仍是 voiceId，默认名称序号提供人类可读区分。

## 8. Android 落地清单

Android 实现必须完成：

- DTO 解码完整 identity V1，未知/非法 identity 降级为 null，不丢弃 ClonedVoice。
- Repository 保存账号+线路作用域的最近有效 identity，并按 revision 合并。
- 创建完成页展示服务端 identity，提供可选修改名称。
- Created 列表、音色选择器、当前播放音色统一显示相同名称和头像。
- 每个历史声音菜单同时提供“修改名称”和“删除”。
- PATCH rename 支持自定义名称、恢复默认、409 收敛、503 非阻断。
- 使用 Android string resource 本地化 “My Voice %1$d”。
- Compose/View 头像直接渲染服务端颜色和四种 glyph，不自行 hash 正式头像。
- 中国区/全球区缓存严格隔离。

最低测试：DTO 完整/null/非法、默认名称不受排序影响、重命名成功/恢复默认/409/503、缓存 revision 竞争、切账号/切区域、四种 glyph 快照或语义测试、创建后 GET 延迟不丢声音。

## 9. Chrome 扩展与 Web 落地清单

扩展与 Web 实现必须完成：

- 共用或逐字段等价的 TypeScript `VoiceCloneIdentity` 类型和运行时校验。
- Created 管理页、正文音色选择器、播放器当前音色统一使用 identity 投影。
- 创建成功后显示自动名称与头像；不在创建前要求名称。
- 提供修改名称、恢复默认和删除；不只显示固定“Cloned Voice”。
- 使用扩展 i18n/Web locale 本地化默认名称；不得把已本地化名称持久化到服务端。
- SVG/CSS 根据服务端 avatar 画四种可辨识 glyph；深色模式不冲掉渐变与白色前景。
- session/local storage 缓存必须包含账号作用域；退出登录立刻清理当前投影。
- 扩展与 Web 固定走全球控制面，不增加中国区选择或中国区缓存。

最低测试：TypeScript 合同解析、两个声音不同 autoNameIndex、列表重排、创建完成、重命名/恢复默认、409/503、四 glyph DOM、暗色模式、退出/换账号缓存、管理页与正文选择器显示一致。

## 10. 跨端验收矩阵

| 场景 | 预期 |
| --- | --- |
| 连续创建两个声音 | 创建前不填名称；完成后分别显示服务端 N 和稳定头像 |
| 列表按最新优先 | 名称序号不随行号改变 |
| iOS 改名后 Android/扩展刷新 | customName、头像、revision 一致 |
| Android 改名后 iOS/Web 刷新 | 同上 |
| 扩展恢复默认名称 | 所有全球端恢复各自语言的 “My Voice N” |
| 改 App/浏览器语言 | 自动名称随语言本地化；customName 与头像不变 |
| 深浅色切换 | 头像主渐变、glyph 不变且可读 |
| identity 接口 503 | 声音仍可试听、选择和朗读，保留旧呈现 |
| GET 暂时返回 identity null | 保留最高 revision 的账号内缓存 |
| 两端同时改名 | stale 端采用 409 最新值，不静默覆盖 |
| PATCH 200 丢失后重试 | 同一目标状态幂等收敛成功 |
| 退出 A 登录 B | 不显示 A 的名称、头像或声音 |
| 移动端切中国/全球线路 | 两个数据域和缓存完全隔离 |
| Web/扩展登录全球账号 | 只展示全球区声音，不探测中国区 |
| 删除一个声音 | 只清理该 voiceId；其他名称序号不重排 |

## 11. 禁止实现

- 创建前强制用户填写名称。
- 把 `voiceId`、`vc_...`、固定“Cloned Voice”作为正常最终显示名。
- 按当前数组 index 生成“我的声音 N”。
- 将已本地化默认名称写回 customName。
- Android、iOS、扩展分别从 avatarToken 自行哈希颜色。
- 根据 customName 首字母重新生成正式头像。
- 重命名时生成新 voiceId 或新 avatarToken。
- identity 解析失败时丢弃整个声音对象。
- identity 503/超时后清空列表、取消选择或报“声音不存在”。
- 用低 revision 的缓存覆盖新服务端值。
- 用头像颜色作为选择、删除或额度结算的主键。
- Web/扩展引入中国区账号或线路概念。

## 13. 完成定义

单端只有同时满足以下条件才算完成：

1. 创建后、列表、选择器和播放器四处名称/头像一致。
2. 可以修改名称和恢复默认名称。
3. 默认名称来自 autoNameIndex，不受排序和删除影响。
4. 正式头像直接来自服务端 avatar，跨端稳定。
5. identity null、503、409、超时均不影响核心声音使用。
6. 账号与区域缓存隔离，revision 合并正确。
7. 完成本文对应平台最低测试并提交准确 Commit SHA。

# 中国区后端（api.castreader.cn）服务器规格与上线清单

> 目标：在不改变旧版 iOS 线上合同的前提下，为新测试包增加
> `api.castreader.cn` 境内入口，并让手机号登录、短信验证与中国线路业务可严格验收。
>
> 铁律：**与 Same 业务完全隔离**，但 CastReader 中国/全球两入口必须共享同一个
> canonical 账号与 Apple 账单权威。网络入口可以独立，账号、订阅与订单事实不能分叉。

---

## 0. 为什么必须是新服务器

现有可访问的腾讯云资源是 **Same 的生产环境**（`blog.same02.com` 入口机
`49.234.54.42` → 内网 `devops 10.0.7.73` → `same-api` 集群）。那台 `devops`
同时跑着 Nginx / Apache / Redis / MQTT / Sendmail，运维文档明确写着
「不是空跳板，不要随意重启」。

把 CastReader 的登录与支付放上去会带来三个不可接受的后果：

1. 任何一次 CastReader 的部署重启都可能影响 Same 的线上服务；
2. 两套业务共用安全组与端口，攻击面互相叠加；
3. ICP 备案主体与网站信息会混在一起，日后任一方变更都要动另一方。

结论：境内入口应使用 CastReader 独立服务器和安全边界，不复用 Same 生产资源；
但它应通过共享数据库或服务器端代理访问 CastReader 唯一的账号/支付账本。

## 1. 要买的东西

### 1.1 云服务器 CVM（必买）

| 项 | 取值 | 为什么 |
|---|---|---|
| 地域 | **上海** 或 **广州** | 必须是**中国大陆**地域，境外地域无法承载已备案域名。短信服务在 `ap-guangzhou`，选广州可省一点内网延迟；上海对全国用户平均延迟更好。二选一即可 |
| 可用区 | 任意（随机可用区最便宜） | 单机部署，暂不需要跨可用区 |
| 机型 | **标准型 S5 / SA5** | 通用型即可，不需要 GPU/高主频/大内存机型 |
| 配置 | **4 核 8 GB** | Next.js 16 构建峰值内存约 4 GB（`build:fast` 显式给了 `--max-old-space-size=4096`）。8 GB 才能**在服务器上直接构建**，省掉一套 CI 产物分发。若坚持在本地构建再上传产物，2 核 4 GB 够用 |
| 系统盘 | **50 GB 高性能云硬盘** | 系统 + Node + 应用 + 日志。50 GB 有充足余量 |
| 镜像 | **Ubuntu Server 22.04 LTS** | Node 20/22 官方源支持最完整 |
| 公网带宽 | **5 Mbps 固定带宽** | 本服务只跑 JSON API（登录、支付回调、Pro 状态、埋点），不承载 TTS 音频。固定带宽比按流量计费在被刷时更可控 |
| **购买时长** | **至少 1 年** | ⚠️ **备案硬性要求**：腾讯云备案要求云服务器剩余有效期 **≥ 3 个月**，按量计费实例**不能用于备案**。买 1 年既满足备案又便宜 |

> ⚠️ **不要买按量计费**。备案系统不认，买完还要重买。

### 1.2 数据库（账号与支付必须共享权威）

不得新建一套会生成不同 `user.id` 或独立认领 Apple
`originalTransactionId` 的中国区账号库。手机号账号、Better Auth session、Pro、
Apple subscription/order/payment 与 notification shadow 必须落到 CastReader
唯一权威账本，或由中国网关服务器端代理到该权威服务。

| 项 | 取值 |
|---|---|
| 产品 | **云数据库 PostgreSQL**（不是 MySQL —— 本项目 schema 是 `pgTable`，用的是 Postgres 方言） |
| 版本 | PostgreSQL 15 或 16 |
| 规格 | **2 核 4 GB / 50 GB 存储**（最小可用档即可，登录+订阅的数据量极小） |
| 地域可用区 | 以唯一账本实际部署位置为准；不能为了同可用区而复制一套账号/支付数据 |
| 网络 | 使用私网、受控隧道或权威服务代理；数据库本身不对公网开放 |

境内 CVM 可以使用本机 PostgreSQL 保存线路配置等非权威运行数据，但不能在这里
建立第二套账号或支付账本。共享账单权威合同见 readout-web 的
`docs/contracts/ios-cn-shared-billing-authority.md`。

### 1.3 已有、不需要再买

- 域名 `castreader.cn` —— 已在该账号，备案中/已备案
- 短信签名「上海包子信息科技」与模板 `2397344` —— 已审核通过
- 支付宝应用 `2021006181645360` —— 已上线，密钥已配好

## 3. 备案这一关（决定了能不能现在就上线）

当前 App 备案已通过，备案号为 `沪ICP备14008512号-12A`；App Store Connect
中的备案号也已由账号持有人绑定。备案时关联的腾讯云资源 IP 是
`49.234.54.42`，实际 `api.castreader.cn` 服务 IP 是 `106.54.47.163`。

```
域名已备案？
├── 否 / 备案中  →  DNS 暂不能指向境内 IP。
│                   境内服务器可以先部署、先用 IP 自测，
│                   但公网域名访问会被接入商拦截。
└── 是（已下备案号）
    ├── 实际服务器仍是腾讯云 IP
    │   ├── 非经营性 ICP 备案 → 同一接入商换 IP 不强制单独变更，可随下次信息变更一并更新
    │   └── 需要经营性 ICP 许可 → 需变更登记 IP，确保许可信息一致
    ├── 实际服务器换到其他接入商 → 在新接入商办理接入备案
    └── 公安备案（备案号下来后 30 日内）—— 按主管部门要求继续办理
```

不能只因为两个地址属于同一主体或同一云厂商就推定接入一定合规。正式切流前应以
腾讯云备案控制台显示的接入状态和官方工单结论为准，并持续核对主体、App 名称、
域名、实际服务内容及服务器接入信息一致。本轮只做本地代码与模拟器测试，不以这段
说明作为部署授权。

**另外两件容易漏的**：

- 备案通过后，网站底部必须展示备案号并链接到 `beian.miit.gov.cn`。
  App 内的「关于」页也建议放一处。
- `api.` 这种纯接口子域名，通常随主域名备案一并覆盖，无需单独备案，
  但**主体与主域名必须已备案**。

## 4. 上线后的架构

```
iOS / Android 中国区版
        │  HTTPS（按业务固定入口）
        ├───────────────► api.castreader.cn
        │                    账号 / 手机号 / Pro / 埋点
        │                    TTS / 文档 / STS / 上传
        │
        └───────────────► quickread.castreader.cn
                             QuickRead SSE / JSON（cms_ 鉴权）

  ┌──────────────────────────────────────────────┐
  │ CVM（Ubuntu 22.04，106.54.47.163）            │
  │  Nginx :443（两个备案域名的精确虚拟主机）       │
  │    ├─ 账号 / 手机号 / Pro / 埋点 → Node :3000 │
  │    ├─ TTS 生成 → 北京 SeetaCloud GPU（无境外回退）│
  │    ├─ 音色目录 / 头像 / 试听 → 本机静态镜像    │
  │    ├─ 新版 STS / 上传入口 → Node :3000 + COS  │
  │    ├─ 旧版文档 / 上传兼容 → 全球服务（待迁移） │
  │    └─ QuickRead 公共入口 → 显式 allowlist 的   │
  │       CN 私有 origin（禁止 `.ai` 与公开自环）  │
  └─────┬─────────────────────────────────────────┘
        │
        ▼
  唯一 canonical 账号/Apple 账本 + 既有全球计算上游
```

客户端侧的硬边界是：`ServiceRoute == .cn` 时，通用自有 API 只使用
`https://api.castreader.cn`，QuickRead 只使用 `https://quickread.castreader.cn`；两者都
发送同一 CN namespace 的 `cms_` session，且绝不跨线回退。全球新版仍使用
`api.castreader.ai`。Kindle、微信读书、YouTube、Google Play 图书、Kobo、O’Reilly 属于
用户主动连接的第三方平台，继续直接访问各平台原有域名。

网关配置的代码源位于 readout-web：`scripts/nginx-api-castreader-cn.conf`。
`scripts/deploy-cn.sh` 当前只是待验收的本地部署实现；没有用户明确授权不得执行。
部署前还必须通过共享 billing-authority fingerprint 的 fail-closed 预检。

**对外只开三个端口**：22（SSH，限来源 IP）、80（仅用于 ACME 续证与跳转 443）、443。

**外部依赖**：
- `sms.tencentcloudapi.com` —— 发验证码
- `openapi.alipay.com` —— 支付宝下单与扣款
- 支付宝异步通知回调本服务 `/api/pro/alipay/notify`（**必须公网可达，且必须是备案后的域名**）

## 6. 上线前硬门禁（别忘）

1. **关掉直通登录**：生产环境移除 `PHONE_AUTH_DEV_CODE`，或只保留
   `PHONE_AUTH_REVIEW_PHONES` 白名单（给应用商店审核员用）。
   代码里已有硬护栏：生产环境下没有白名单时，直通自动失效。
2. **iOS / Android 客户端的本地兜底也要关**：
   `PhoneAuthService.LocalFallback.isEnabled = false`、
   `PhoneLocalFallback.ENABLED = false`。
3. **`PHONE_AUTH_CODE_SECRET` 一旦定下就不能改** —— 它是手机号哈希的盐，
   换了等于所有存量账号失联。生成后写进服务器的 systemd 环境文件并备份。
4. **验证共享账单权威**：中国/全球入口的脱敏 billing-authority fingerprint 与
   canonical `user.id` 必须一致；缺失或错配直接 No-Go。
5. **保留旧版合同**：不得修改 `.ai` 旧入口或旧客户端依赖的路径；新版中国线路
   只按受限 Build 灰度，配置缺失/超时/异常必须回到 `legacy`。
6. **先测试后上线**：完成旧版、新版 legacy、新版 cn 的真机抓包、真实短信与
   Sandbox StoreKit 跨线路恢复后，由用户再次明确授权部署；部署与 App Store 送审
   是两个独立授权动作。

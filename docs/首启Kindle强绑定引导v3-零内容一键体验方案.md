# 首启 Kindle 强绑定引导 v3 · 零内容一键体验方案

日期：2026-08-03

状态：第 0、1 屏已于 2026-08-04 被产品明确撤回；仅保留登录、扫描、首听的稳定性实现参考

基于：`首启Kindle强绑定引导v2-设计方案.md` 的五屏骨架

## 0. 最终决策

> 修正：以下“本地试听首屏”和“单卡站点确认”不再是当前产品决策。当前第 0、1 屏严格执行 [v2](./首启Kindle强绑定引导v2-设计方案.md)：Kindle 价值页 → 三站点直接选择页。第 4 屏的系统推荐首本以及本方案中的竞态、恢复和真实播放激活约束继续有效。

保留 v2 的五阶段线性结构，但不照搬三个关键交互：

1. 第 0 屏从“解释 Kindle 价值”改为**直接播放一段已准备好的真实内容**；
2. 第 1 屏从“让用户选择 Amazon 站点”改为**让用户确认系统给出的默认答案**；
3. 第 4 屏从“展示整面书架让用户选书”改为**系统先选好一本，用户只点开始**。

这版强绑定的是一条清晰路径，不是第三方登录门槛。用户第一次打开 App 时，Happy Path 只需要做三件事：

1. 点一次，立即听到预置内容；
2. 点一次，同意连接 Kindle；
3. 点一次，开始听系统已经选好的真实 Kindle 书。

Amazon 账号、密码和 2FA 是无法替用户完成的外部动作；除此之外，站点、扫描、选书、起读位置、朗读模式、基础音色与速度全部由系统先给默认答案。

一句话原则：**先让用户一键听见价值，再只征求一次连接同意；其余决定尽量由产品承担。**

## 1. 用户看到的不是“五步重任务”

虽然内部仍是五个页面状态，但界面上拆成：

- 第 0 屏：一次独立的 30 秒体验，不显示步骤点；
- 第 1～3 屏：显示“连接 Kindle · 1/3～3/3”；
- 第 4 屏：连接结果与真实首听，不显示步骤点。

这会让用户感知为“先体验一下，再用三步接入 Kindle”，而不是刚打开 App 就被告知还要完成五步。

## 2. 五屏最终流程与精确文案

## 3. 各屏画面与交互纪律

### 3.1 第 0 屏：不是宣传页，而是可操作的产品本体

页面中部直接展示一张真实的示例阅读卡，而不是 3 秒循环动画：

- 标题：`为什么读完一页，却什么都没记住？`
- 元信息：`本地示例 · 约 30 秒`
- 正文区域：显示 3～5 行真实文字；播放后逐词高亮；
- 底部只保留一个黑色主按钮：`开始边听边看`；
- 主按钮下只放一句信任说明：`无需登录 · 不消耗免费额度`；
- 右上角保留 `跳过`，进入正常首页，不反复强弹。

建议使用这段原创示例正文：

> 你以为自己一直在阅读，注意力却可能每隔几秒离开一次。让声音带着文字逐词亮起，就像有人用手指带着你读。眼睛和耳朵落在同一个位置，长句不再容易看丢，思路也更容易跟住。现在，不用设置任何东西，只要继续跟着亮起的词往下读。

实现约束：

- 文本、音频和词级时间戳全部随包提供；
- 不请求 TTS、QuickRead、账号、额度或内容服务；
- 不扣免费额度、不进入普通历史、不计真实激活；
- 示例播放结束才自动进入第 1 屏，不在播放中途把用户强行切走；
- 中途跳过时立即停止示例音频并清理播放所有权。

### 3.2 第 1 屏：站点是纠错题，不是选择题

首屏只显示一个已经选中的站点卡：

```text
Amazon.com
按地区推荐                                      ✓
```

主按钮写完整结果：`继续到 Amazon 登录`。不要再使用“就是这个”这类依赖上下文的文案。

完整 13 站点列表只有在用户点 `不是这个站点？更换` 后才以底部表单出现。默认顺序：

1. 已有绑定或历史书籍推断出的站点；
2. 设备地区对应站点；
3. App 语言对应候选；
4. Amazon.com 兜底。

如果已有可验证的 Kindle 绑定，则第 1～3 屏可整体跳过，直接进入第 4 屏。

### 3.3 第 2 屏：把信任说清楚，不增加产品说明

顶部只保留一张浅色安全提示条：

> 这是 Amazon 官方页面。CastReader 看不到，也不会保存你的密码。

下方是 Amazon 登录 WebView。没有“登录完成”“下一步”按钮，也不在 2FA/验证码期间弹提示催促。

登录成功不能只依赖某一个 Cookie。至少同时确认：

- 当前页面属于所选 storefront 的精确 Kindle 书架路径；
- 页面没有处于 `authRequired` 或登录重定向状态；
- 页面已具备可信书架信号，或具备可信的空书架证据。

Cookie 只能用来加速探测，不能单独驱动页面前进。

### 3.4 第 3 屏：状态页没有主按钮

扫描页只显示三个层级：

1. 当前任务：`正在准备你的 Kindle 书架`；
2. 已取得的真实结果：`已找到 N 本`；
3. 当前阶段：`正在定位你最近阅读的一本…`。

使用不确定进度动画，不显示无法精确计算的百分比。只要第一本可播放书已经准备好，就可以进入第 4 屏；剩余同步仅在前台条件允许时继续，不能承诺 App 退到后台后仍会扫描。

空书架不是“失败”，改为明确恢复卡：

- 标题：`这个站点暂时没有找到可播放的书`
- 说明：`你的书可能在 Amazon.co.jp。`
- 主按钮：`试试 Amazon.co.jp`
- 次级：`返回示例内容`

建议站点由系统根据候选顺序给出，一次只推荐一个；不要重新摆出完整站点列表。

### 3.5 第 4 屏：系统先选一本，用户只决定是否开始出声

系统选书顺序固定且可解释：

1. 当前站点内有阅读进度、最近阅读且入口有效的书；
2. 最近加入书架且正文可读的书；
3. 按稳定排序选出的第一本文字书；
4. 当前候选不可读时自动尝试下一本一次。

页面默认只展示这一部。`换一本` 是次级入口，点后才展示完整书架。

不建议扫描完成后突然直接出声。登录或验证码可能耗时较长，用户此时所处环境已经变化。保留 `开始听这本` 这一个明确动作，既没有让用户做内容决策，也避免意外播放。

点击后必须满足：

- 打开正式 Reader，而不是在 onboarding 内另建播放器；
- 读到可朗读正文、布局与高亮坐标就绪后再开始；
- 冷启动 autoplay 使用一次性令牌，重复 `onAppear`、导航回调或恢复回调不能产生叠音；
- 首段 TTS 失败自动重试一次；仍失败只显示 `重试朗读`，不能重新登录或重扫书架。

## 4. 朗读与解读模式

首启全程固定使用：

- 模式：朗读；
- 音色：基础默认音色；
- 速度：1.0×；
- 高亮：开启；
- 自动滚动：开启。

首启前不出现：

- 朗读 / 解读选择；
- 解读场景或深度；
- 音色与语速；
- 内容来源矩阵；
- 付费页或额度说明。

解读放在真实朗读完成 30 秒之后渐进发现。在不暂停播放的位置出现轻提示：

- 文案：`想更快抓住这一页？试试解读`
- 操作：`解读这一页`

用户不点就继续朗读；不自动切模式。

## 5. 最小可靠状态机

只持久化用户已经完成的语义阶段，不持久化 WebView、扫描 Task 或临时进度：

```text
sampleReady
  → samplePlaying
  → sampleCompleted
  → storefrontConfirmed(storefrontID)
  → login(storefrontID)
  → scan(storefrontID)
  → firstListenReady(storefrontID, bookID)
  → firstListening(storefrontID, bookID)
  → activated

任意未激活阶段 → postponed(resumePhase)
```

持久化字段：

- `phase`
- `sampleCompleted`
- `storefrontID`
- `recommendedBookID`（可选；恢复时必须重新验证）
- `activationPlaybackSeconds`
- `isActivated`

仅运行时保存两个令牌：

- `attemptID`：换站、重试、返回、跳过时更新；所有迟到的登录、扫描和恢复回调必须丢弃；
- `autoplayToken`：绑定一次 onboarding flow 与一本书，只能消费一次，防止重复播放。

恢复规则：

| 被杀阶段 | 重启行为 |
|---|---|
| 示例播放中 | 回到示例待播放，不从中间自动出声 |
| 登录中 | 重建同站点 WebView，先验证已有会话；有效则扫描，无效才显示登录页 |
| 扫描中 | 重新开始一次完整扫描，不尝试续接旧 Task |
| 首听待开始 | 推荐书仍有效则恢复第 4 屏，否则重扫一次 |
| 真实播放未满 30 秒 | 回到对应书的待开始状态，保留已累计的合法秒数 |
| v1 已激活 | 直接迁移为 `activated`，不重新展示 |
| v1 已跳过 | 迁移为 `postponed`，不重新强弹 |

## 6. 稳定性边界

### 登录与扫描

- 2FA/验证码时不自动刷新；
- 同一次登录重定向异常最多自动恢复一次，之后停在当前页提供重试或稍后完成；
- 扫描 60 秒仍无终态时取消当前 attempt，允许自动重试一次；
- 退后台、换站或跳过后立即取消本轮 attempt；迟到回调不能继续开书或播放；
- WKWebView 退后台后可能暂停，因此回前台从 `scan` 语义阶段重新开始，不能宣称后台持续扫描；
- 判定真实空书架必须排除登录失效、reader 页面、未 ready 与临时 DOM 空白。

### 首听与长文朗读

- 向导只负责把用户送进现有 Kindle Reader，不新建第二套 TTS、播放器或翻页逻辑；
- 点击 `开始听这本` 后先确认可读段落，再预热首段；
- 网络中断时只播放已经缓冲的音频；缓冲耗尽停在当前段，恢复网络后从当前段继续；
- 没有下一页预取时在页边界等待，不能跳页或误报完成；
- TTS 故障只影响朗读层，不回退到重新登录或重新扫描；
- 关闭 onboarding 不能销毁正在播放的 Reader 或夺走音频回调所有权。

## 7. 异常状态的唯一恢复动作

| 异常 | 主操作 | 次操作 | 禁止行为 |
|---|---|---|---|
| 2FA / 验证码 | 继续在 Amazon 页面完成 | 30 秒后出现「稍后完成」 | 倒计时失败、自动刷新、重建 WebView |
| 登录重定向异常 | 自动恢复一次；失败后「重试登录」 | 「稍后完成」 | 无限跳转、清空 Cookie |
| 扫描 0 本 | 「试试 Amazon.{recommended}」 | 「返回示例内容」 | 展开全部站点让用户重新研究 |
| 扫描超时 | 自动重试一次；失败后「重新扫描」 | 「稍后完成」 | 同时启动多个扫描 Task |
| 推荐书失效 | 自动换下一本一次 | 「换一本」 | 循环打开、循环恢复 |
| 首段 TTS 失败 | 自动重试一次；失败后「重试朗读」 | 「换一本」 | 重新登录、重新扫书架 |
| 断网 | 「网络恢复后继续」 | 保留当前页 | 跳段、清进度、误计激活 |

## 8. 数据口径

示例体验和真实激活必须严格分开：

| 漏斗阶段 | 建议记录 |
|---|---|
| 示例曝光 | `onboarding_step{step:sample,result:shown}` |
| 示例开始 | `onboarding_step{step:sample,result:started}` |
| 示例 30 秒 | `onboarding_step{step:sample,result:done}` |
| 同意连接 | `onboarding_step{step:storefront,result:done,storefront}` |
| 登录结果 | `onboarding_step{step:login,result:done|skipped|failed}` |
| 书架就绪 | `onboarding_step{step:scan,result:done|failed,book_count_bucket}` |
| 真实首音 | 复用现有 `read_first_audio`，`entry_point=library_onboarding` |
| 真实 30 秒 | 复用真实播放里程碑，并完成 `isActivated` |

核心漏斗：

```text
首启
→ 示例开始
→ 示例 30 秒
→ 同意连接 Kindle
→ 登录成功
→ 书架就绪
→ 真实首音
→ 真实播放 30 秒
→ D1 / D7 留存
```

任何示例播放都不能：

- 计入 Kindle 真实激活；
- 抬高普通内容的 `read_first_audio`；
- 进入用户历史；
- 扣除免费额度；
- 触发付费页或评分请求。

## 9. 本版本只做三组工作

### A. 零内容即刻价值

- 随包示例文本、音频与词级时间戳；
- 第 0 屏真实播放、高亮、自动滚动；
- 示例独立状态与数据口径。

### B. Kindle 连接自动化

- 默认站点确认；
- 登录可靠判定与同一 WebView 会话；
- 无按钮扫描与唯一恢复动作；
- 首听候选的确定性选择。

### C. 第一次真实朗读稳定性

- 幂等冷启动 autoplay；
- 首段预热与一次重试；
- 真实 30 秒累计与断点恢复；
- 强杀、退后台、断网、迟到回调的验证。

明确不做：

- 内容广场、书城或多本预置内容；
- 远程推荐系统或 CMS；
- 新音色、新播放设置；
- 首启解读流程；
- App Store 截图与文案再优化；
- Android 同步、A/B 平台或大规模首页改版。

## 10. 发布验收门槛

| 目标 | 验收标准 |
|---|---|
| 一键获得价值 | 全新安装后 1 次点击开始本地示例；无需网络；首音 P95 ≤ 0.5 秒 |
| 登录不误推进 | 有效登录、过期 Cookie、错误站点、2FA、真实空书架五类场景零误推进 |
| 扫描可恢复 | 每个语义阶段强杀重启 10 次，恢复位置正确，无重复扫描 |
| 首听唯一播放 | 快速连点、重复导航回调、退后台返回各 30 次，始终只有一个音频 owner |
| 首听成功率 | 推荐书点击到首音成功率 ≥ 99%，P95 ≤ 12 秒 |
| 长文连续性 | 30 次、每次 60 分钟朗读中，非用户主动停止为 0；自动翻页成功率 ≥ 99%，页间静音 P95 ≤ 2 秒 |
| 断网恢复 | 断网 10～30 秒后，同段续播成功率 ≥ 95%，恢复 P95 ≤ 10 秒 |
| 激活准确 | 自然播放可跨页、跨进程累计；seek、暂停、缓冲不计入；完成事件只发一次 |
| 数据闭环 | 每个 shown 都有 done / skipped / failed 终态，事件 schema rejection 为 0 |

## 11. 最终不再讨论的产品决策

1. 第 0 屏必须是真实本地示例，不再使用纯价值动画；
2. 首启默认朗读，不让用户选朗读或解读；
3. 站点默认推荐，不让用户先浏览列表；
4. 扫描正常态没有按钮；
5. 首听由系统推荐一本，不先展示完整书架；
6. 真实书开播前保留一次明确点击，避免登录耗时后突然出声；
7. 示例 30 秒不等于业务激活，真实内容 30 秒才等于激活；
8. 本版本不扩成内容平台，只解决“没有内容、不能立刻听”和“第一次真实朗读不够稳”两个问题。

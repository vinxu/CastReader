# CastReader Android 平板适配实施任务表

日期：2026-09-22。所有任务当前均为 **待实施/待核验**；不是 Android 完工清单。

总规范：[iOS 对齐与问题复盘](Android-Tablet-Adaptation-Handoff-2026-09-22.md)。逐条操作：[验收 CSV](Android-Tablet-Acceptance-Checklist-2026-09-22.csv)。同一 CSV 条目如果涉及多个设备/地区/内容，应复制成子行分别记结果，不能用一个 PASS 代表未跑过的组合。

## 排期与放行规则

| 顺序 | 任务 | 依赖 | 完成后才可继续的证据 |
| --- | --- | --- | --- |
| M0 | 锁定手机基线与设备/账号条件 | 无 | BASE 全部通过，功能继承清单、源码身份和测试隔离方案落盘 |
| M1 | 窗口、语义锚点与音频所有权基础 | M0 | 所有权/迟到回调/账号隔离合同；两个宿主原型真实交接 |
| M2 | 导航、窗口测量与公共播放 UI | M1 | NAV 全屏/窄窗/短高/IME/最大字号截图复核；手机导航不退化 |
| M3 | 原生文档与网页重排 | M2 | NAT 各源 Read/Explain、几何/zoom/冷恢复全部有证据 |
| M4 | Kindle 在线/离线 | M3 | KD 真实账号、播放中旋转、完整标注、自然续页和缓存恢复 |
| M5a | Google Play 图书 | M4 | GB 的核心/长正文/布局/真实续页/冷恢复通过 |
| M5b | Kobo | M5a | KO 的裁切/点击/重排/前后恢复/真实续页通过 |
| M5c | 微信读书 | M5b | WR 的句级锚点、Canvas、目录精确跳转和双向冷恢复通过 |
| M5d | O’Reilly 及现有其他在线源 | M5c | OR 的真实账号结果；无条件时明确阻塞，不算完整平台对齐 |
| M6 | 导入、声音、账号、表单与系统入口 | M2–M5 | IMP/FORM/VOICE 核心流程、全键盘可达与账号边界 |
| M7 | 真正多窗口、外设、生命周期与无障碍 | M1–M6 | WIN/SYS 实际系统窗口和真外设；关闭/重开/音频焦点结果 |
| M8 | 两区最终 Release、手机回归与性能 | M0–M7 | CORE 全矩阵、PERF、手机基线；源码和产物绑定 |
| M9 | 平板物料、打包/商店核验与交付 | M8 | REL 所有门禁、资产回执；仅在获发布授权后上传/送审 |

每模块执行“复现→修复→受影响合同→正常 UI 操作→截图目检→写证据”，不先修改全部页面再统一验收。阶段失败不得清空用户数据、换一个未登录设备或删掉断言后宣布通过。若基础修复影响已通过模块，精准回归受影响部分。

P0 = 数据/账号/音频所有权/错读/丢位置/生产服务与发布门禁；P1 = 完整平板体验必须实现；P2 = 可独立后续增强。P0/P1 未完成时不能使用“完整 Pad 对齐完成”。PDF 双栏、任意笔记、独立桌面产品不借此进入 P0/P1。

## M0：手机基线与验收环境（P0）

- 重新读取当前 Play/CN 线上状态、最高已占用 code 和发布源码；核对本轮目标渠道及所有待合并手机功能，记录 merge-base/祖先关系。
- 当前文档参考 Android 1.0.53（60）/源码 `d4e6316`，不是自动指定下一版或新分支起点。
- 建独立 `codex/` 工作分支；保留主目录既有未提交工作。列出读取进度、Kindle 离线/预读、EPUB/PDF/插图、音色续播、额度/区域/云盘等保留项。
- 先确认已有平板/手机、授权账号/书架、Pro/克隆额度、设备电源和可操作通道；优先复用同一模拟器与账号。
- 隔离测试 applicationId、存储、Keystore/账号目录和后端测试身份。不得使用会登出/清空真实容器的 setup/teardown；不要因签名不同卸载正式 App。
- 建 `reports/android-tablet-<date>/` 单一索引，原始日志/账号截图保持私有，发布报告只记录去敏后的事实。

交付：baseline.json、功能继承表、设备/账号条件表、排除与阻塞清单、测试隔离说明。

## M1：共享基础合同（P0）

落点：`DocSession`、`PlayerCoordinator`、`GlobalPlayerState`、`PlaybackController`、`AudioPlayerManager`、`AudioPlaybackService`、`ResumeCoordinator`、各 checkpoint。

- 确定稳定 session/window ID、accountEpoch、playbackGeneration、layoutEpoch 的关系；为每条异步结果明确匹配条件。
- 将“内容正在浏览”和“拥有音频”拆开；Read/Explain/离线/preview 同一仲裁，保留现有实际播放器和通知能力。
- 旧 stopper/close/preview completion 只能处理原 owner，不能停止新的会话。
- `DocSession` 从单例单值向按 session 分区演进；保留不可变原子提交；临时文件引用计数/所有者清理，B 不删除 A 文件。
- 定义 semantic source、消费范围、严格唯一匹配、geometry-only 与 navigation 的独立事件。
- 验证两个实际宿主原型：B 只浏览不抢 A；B 显式播放才交接；关闭 B 与账号切换不执行旧回调。

必须回归：同一文档两窗口、不同文档、声音准备中换窗口、旧 VM 清理、账号切换后的旧结果、定时到期与手动恢复。

## M2：自适应导航与公共外壳（P0/P1）

落点：`MainActivity`、`CastReaderNavHost`、`ReaderShell`、首页/文库/设置/声音页面、Manifest/依赖声明。

- 引入单一窗口信息入口；将实际阅读容器尺寸传到各 reader，避免按方向或整个屏宽硬算。
- 窄窗/宽窗导航复用同一导航状态和 VM，不因结构切换触发重新导入、重新生成或重新登录。
- 处理系统栏、任务栏、标题栏、cutout、IME；明确 inset 的消费层；顶部返回、导入、播放条和最后一项始终可达。
- 按宽高和字号选择播放条/模式控件；保留大屏合理正文宽度；触控目标至少 48dp。
- 解除平板 YouTube 保留会话的竖屏依赖；手机既有方向策略只在其真实适用条件下保留。
- 若引入 adaptive 依赖，先通过当前 Kotlin/Compose/AGP 兼容原型和双 flavor 编译；不要顺带进行全栈升级。

门禁：所有尺寸边界左右各测试；320/375 窄窗、短高、四方向、最大字号、深色、IME/浮动键盘；实际截图目检与点击确认。

## M3：原生与普通 Web 内容（P0）

- 文本/EPUB 的 TextLayoutResult 按实际容器失效；processed text 高亮与原文 mark 映射各走原有正确管线。
- EPUB 插图/SVG/目录、章节段落 ID、非 spine 图片和大书解析保持；正文图片按目标尺寸解码。
- PDF/照片保存 page-space anchor、相对 zoom；顶部 fit-width 与手动浏览采用不同恢复策略；阅读控件和字幕不进入正文坐标。
- 扫描 PDF/照片验证 OCR origin/旋转/缩放；无几何变化不重新 OCR，内存按页受限。
- DOCX/网页长段按 mark 范围跟随；WebView 不因旋转重建，SVG marks 不重新播放已完成动画。
- YouTube 封面与字幕按空间布局，保留 session/字幕语言；字幕待提取不能报导入成功。

门禁：每类源分别有 Read 和 Explain（产品原本不支持 Explain 的源如 YouTube 按真实能力处理），包含播放、暂停、加载、边界状态；大文件、缩放、重开和相同文本不同几何。

## M4：Kindle 在线/离线（P0）

- 在已登录真实书架开正文，保留手动翻页确认、预读、遮罩、声音续播、离线格式与原 checkpoint。
- 旋转保留 immutable source、实际音频与 VM；OCR 重排只更新投影，迟到 OCR 不覆盖新页。
- 处理拆词/连字符/稀疏 ID、跨行标注；未读/未解释尾部先消费，真正下一页再走物理翻页确认。
- 重排中暂停和自然切段不能丢恢复权；快照遮罩不等于暂停音频。
- 离线书行整行可点、原页 fit/zoom、下载管理/缓存/账号恢复正确；对联网合成依赖说清楚。

门禁：完整跨行 mark、真实 Read/Explain 自动下一页、主动下一页保持暂停、Aa/目录旋转开关、迷你播放器、冷重开和离线现有能力。

## M5：其他平台按顺序完成（P0）

每个平台都做六组：书架/搜索/排序/加载；真实 Read；真实 Explain；自然物理续页；Aa/目录/迷你播放器；窄宽双向恢复。

- Google：frame 来源校验、source 身份变化后的唯一严格 overlap、短标题、UTF-16、暂停词显式重画、有依据的相邻页 reveal；不要弱化 frame/origin 门禁。
- Kobo：所有 clipping ancestor 与 iframe 交集、正文手势层命中、同源不同 geometry 提交、视觉遮罩上限与导航隔离、前后双向恢复。
- 微信：检测实际尺寸先于 paint 提交，保留 Canvas scope；中文句级 hash 和短句上下文；精确点击真实目录 action；已在可见右列不强制翻页。
- O’Reilly：确认本端真实入口和账号，长章节/代码/图片的 semantic page；缺少条件单独阻塞，不能继承 Kindle/fixture 的通过结果。

iOS 对照记录中的“修复前 assertions passed 但目检失败”“几何 reveal 被误当续页”“自然段结束使 same-segment 断言失败”要作为测试设计反例写入本端用例。

## M6：导入、声音、表单与系统入口（P0/P1）

- 目录/Aa/声音/语速/定时面板：窗口有界、内部滚动、IME 结果行可达；模态期间底层站点不可点击。
- 各格式 picker/系统分享/拖放/云盘复用现有持久身份与授权；批量最多 8 项顺序执行、取消、逐项结果、去重重试、默认暂停打开。
- URI grant 与内容复制在有效期完成；仅删自身副本；已取消任务/旧账号回调不能保存；关闭源/目标窗口要可解释。
- 音色试听、选择、创建录制/上传、礼物/私人管理沿用服务合同和地区 capability；旋转不重启任务、不乱扣额度。
- 登录/购买/权限/云盘返回发起宿主；账户变化使旧弹窗返回失效，不改变原有合规/支付行为。
- 深链/通知/Widget/快捷入口存在的逐项验证冷/热启动和路由；新增入口要登记一次性消费与重复投递策略。

门禁：键盘+旋转+最大字号实际成功提交/取消，不能只看页面存在；合法授权环境下执行完整账号/支付测试矩阵。

## M7：系统多窗口、外设与生命周期（P0/P1）

- 真正两个 Android 系统窗口，各自文档/导航/草稿/目录/弹窗独立；平板分屏与同应用多实例分别测试。
- 窗口关闭、后台、可见失焦、任务销毁、音频焦点丢失、进程回收分别处理，不统一当“停止”。
- 最小书签按账号/文档/窗口原子保存；恢复后默认暂停；Bundle 不存大正文/图片/音频。
- 大字号/TalkBack/焦点顺序/屏幕阅读语义；主控件至少 48dp；键盘 Space 不抢文本输入，Ctrl+A/C/V 等标准编辑正常；Escape/返回先退出顶层面板。
- 真鼠标/触控板/笔、折叠铰链/外接显示窗口按目标能力验证；不照抄 iOS 未通过键盘测试的补丁。

门禁：WIN/SYS 有设备证据；“预览能显示两栏”“模拟按键被发送”都不是系统能力通过。

## M8：最终 Release 与回归（P0）

- 冻结应用/配置与 JS 依赖摘要，记录手机基线祖先与平板所有模块提交。
- 运行现有发布技能规定的 Release 单测/lint/包及涉及的架构合同。候选修复只重测受影响项；涉及共享管线再扩大范围。
- **在最终正常 Release APK** 做 CN/中文与 Global/英文六格服务矩阵、两种模式的常规→社区→私人→常规、朗读↔解读、试听恢复、准备中取消、真实字幕/marks/额度。
- 复用同源码 Debug 的诊断结果，但不能据此替代 Release 的 R8/资源/签名/正常启动表现。loading 动画必须真实时钟正常启动检查。
- 真机 60 分钟长文、频繁缩放、30 次旋转、窗口反复创建/关闭、后台前台；记录 PSS/资源/掉帧/音频间断/耗电趋势，按预先定义的基线预算判定。
- 旧正式手机版升级覆盖到通用版，账号/书架/Cookie/缓存/音色偏好/进度保留；同时验证旧 checkpoint 兼容。

交付：final-source.json、artifact.json、core-matrix.json、性能记录、手机回归、CSV 最终状态。缺失项不从报告删除。

## M9：发布物料与交接（P0/P1）

- 在实际 Android 平板捕获首页、Kindle《地心游记》朗读、解读、音色、文件入口五场景；中英文、目标尺寸集合及横屏画面；保留原图/版本/设备/hash。
- 按当次 Play Console/CN 要求准备文字与素材；保留手机图片和无关商店设置，说明已验证的平板范围。
- 包名/签名、versionCode、flavor、不可调试、生产线路/Key、资源语言、测试夹具排除、设备过滤、AAB mapping 等核查。
- 获得发布授权后按既有技能上传与回读；同一上传不因结果暂时不明确直接重发，先查包/版本/提交记录。
- 最终报告清楚区分“审核中”“已发布”和 CN manifest 可下载；不默认创建监控任务。

## 开工时可直接使用的任务说明

> 从当前最新、已验证的 Android 手机发布源码建立独立平板适配分支，先按本交接核对基线和已绑定账号，不覆盖主目录未提交工作。按 M0–M9 完成同包名手机/平板适配，必须支持旋转、分屏、窗口缩放以及文档/音频所有权隔离。先完成一个模块，运行受影响合同并在同一已登录平板环境验证实际功能和截图，再推进下一模块。Kindle、Google Play 图书、Kobo、微信读书及其他已支持平台分别实测，不用 fixture、试听或 HTTP 200 代替真实朗读/解读和自然续页。将证据填入配套 CSV；保留未验证边界，最终 Release 服务与手机回归全部过门禁后再按明确渠道授权发布。

这段是供用户或 Android 开发者使用的开工说明；交付文档本身没有自动触发新任务或发布。

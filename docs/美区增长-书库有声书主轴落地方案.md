# 美区增长 · 「书库有声书」主轴落地方案

> 版本：v3（2026-08-16 收敛：新增 §12 循环验证协议，取代 §8 的分阶段路线；§5.6 分区定价与 §11 市场分层保留）
> **v3 收敛原则：所有动作围绕一个可测量的赚钱循环——进来 → 绑书库 → 留下来 → 按新价付费 → CAC < LTV。验证单位是循环整体配置，不是单个改动。**
> 目标：把美区主轴从「YouTube 转录」切到「把你已有的书变成有声书」，并同步修复定价与免费额度的变现结构。
> 适用范围：**美区（en-US）先行**；其他市场按 §11 分层推进——中文区不套用本主轴，各区价格按 §5.6 分区覆盖。
>
> **2026-08-23 执行修订**：§6 的“3 小时首装赠额”不再进入下一版本。它会把试用触点推迟到 72h 转化窗口之外，改为“书库就绪成功页 + 30 秒软试用触点 + US 一次性 5 分钟试听”。数据身份、Apple period 事实表与完整版本范围以 `docs/US-GB-增长闭环-下一版本产品与数据迭代计划.md` 为准。

## 0. 一句话结论

产品已经把最贵的工程做完了（5 个书库绑定），但 App Store 叙事、ASO 词位、定价锚点三样全都没有对齐到它。本方案不新增任何核心功能，只做**对齐**。

## 2. 主轴决策

**书库有声书做主轴，YouTube 降级为「输入源之一」。**

- YouTube 功能**不下线**，只是从描述第一段移到「BRING YOUR OWN CONTENT」列表里
- 关键词字段保留 `transcript` / `caption`（有真实流量），删掉 `video` / `subtitle`（意图不匹配）
- 后续版本更新说明不再以 YouTube 为主打

**一句话定位（美区）：**

> Your Kindle, Kobo, EPUB and PDF library — read aloud, in a real voice.

## 3. 叙事重构（美区 en-US）

### 3.1 名称

| | 文案 | 字符 |
|---|---|---|
| 现在 | `CastReader: Read Aloud & AI` | 26 |
| **改为** | `CastReader: Read Aloud Books` | 28 |

保住 `read aloud`（当前 #28、流行度 45，是现有最好的大词位置），新增 `books` token。

### 3.2 副标题

| | 文案 | 字符 |
|---|---|---|
| 现在 | `Text to Speech for PDF & Web` | 28 |
| **改为** | `Audiobook from PDF, EPUB, Web` | 29（原方案的 `& Web` 版本实测 31 字符超限，已改逗号连接） |

`audiobook` 进副标题是本方案的核心动作——它是整个价值锚点的锚，且当前在任何字段都不存在。

### 3.3 推广文本（170 字符内，可随时改不用过审）

```text
Turn the books you already own into audiobooks. Connect Kindle, Kobo, Google Play Books or O'Reilly, or open any PDF and EPUB, and listen with synced highlighting.
```

段落顺序改为：

1. **YOUR LIBRARY, AS AUDIOBOOKS** ← 新的第一段，讲 5 个书库 + PDF/EPUB
2. **READ ALOUD — STAY FOCUSED** ← 保留，讲三位一体
3. **AI EXPLAIN — GO BEYOND THE WORDS** ← 保留，差异化武器
4. **BRING YOUR OWN CONTENT** ← YouTube 并入此处
5. BUILT FOR / 合规声明 ← 保留

新第一段建议文案：


## 4. ASO 词簇重组（美区）

### 4.1 字段分配原则（沿用既有纪律）

同一 token 不跨字段重复；名称 > 副标题 > 关键词字段。

- 名称占用：`read`、`aloud`、`books`
- 副标题占用：`audiobook`、`pdf`、`epub`、`web`
- 关键词字段不再重复以上 token

### 4.2 关键词字段（100 字节上限）

**现在：**
```text
tts,video,caption,transcript,subtitle,voice,reader,ocr,scan,pdf,epub,article,dyslexia,study
```
（91 字节）

**改为：**
```text
tts,voice,reader,ocr,scan,article,dyslexia,study,ebook,listen,transcript,caption,library,text
```
（93 字节）

变更明细：

| 动作 | token | 理由 |
|---|---|---|
| 删 | `video`、`subtitle` | 搜索意图指向下载/提取，与付费点不匹配 |
| 删 | `pdf`、`epub` | 已移入副标题，避免重复 |
| 加 | `ebook` | #35，流行度 45，现有可爬区最高价值词 |
| 加 | `listen` | 组合词基础 token（listen to books / listen to pdf） |
| 加 | `library` | 书库叙事核心词 |
| 加 | `text` | 组合 text reader（#26，流行度 30） |
| 留 | `transcript`、`caption` | YouTube 仍有真实流量，降级保留 |
| 留 | `dyslexia`、`study` | 无障碍/学生人群，第二渠道伏笔 |

### 4.3 `kindle` token 的处理

**建议本轮仍不入关键词字段**，仅在 ASA 投放和描述正文中使用。

理由：`kindle reader for iphone` 流行度 53 确实诱人，但元数据被拒会阻塞发版；ASA 侧已能验证该词转化，先拿数据再决定是否冒险。

### 4.4 ASA 投放调整

新增 Exact 词组（建议 ¥12 档，与现有高档并列）：

```
ebook to audiobook
turn books into audiobooks
listen to ebooks
audiobook from epub
kindle to audio
kobo read aloud
```

原 ¥12 档中 `text to speech pdf` / `pdf text to speech` 两词若 4 周内仍零转化，降档让位。

## 5. 定价方案

### 5.1 现状与竞品

| 产品 | 月付 | 年付 | 折合月 |
|---|---|---|---|
| **CastReader（现在）** | **$4.99** | **$34.99** | **$2.92** |
| ElevenReader | $11 | $99 | $8.25 |
| Speechify Premium | $29 | $139 | $11.58 |
| Audible Premium Plus | $14.95 | — | $14.95 |

现价比 Speechify 便宜 4 倍。低价在美区不构成优势：

1. 传递「低质量」信号，与 Audible 锚点冲突
2. **LTV 过低导致买不起量**——这是 ASA 投不出去的重要原因之一

### 5.2 新价格（分两步走）

**第一步（本方案范围）：**

| 档位 | 新价 | 折合月 | 相对现价 |
|---|---|---|---|
| 月付 | **$9.99** | $9.99 | +100% |
| 年付 | **$59.99** | $5.00 | +71% |

保留 1 周免费试用（现有 `introductoryOffer` 配置不变）。

**第二步（观察 4 周后决定）：**

若转化率下降幅度 < 30%，继续提至月付 $12.99 / 年付 $89.99（对齐 Audible 与 ElevenReader 之间的位置）。

### 5.3 产品 ID 策略

**必须新建产品，不得修改现有产品价格。**

```
ai.castreader.pro.monthly.v2    $9.99
ai.castreader.pro.yearly.v2     $59.99
```

- 老用户继续持有 `ai.castreader.pro.{monthly,yearly}`，**永久保价**（grandfathering）
- 直接改价会触发 Apple 的订阅涨价同意流程，导致大量流失
- `ProManager.productIDs` 需同时包含新旧 4 个 ID；`isProProduct(_:)` 判定逻辑不变
- 新用户只展示 v2 产品；`Product.products(for:)` 请求全部 4 个，但付费页只渲染 v2

### 5.4 关于 Lifetime 买断

**不建议做。**

TTS 是持续变动成本（云端按量计费），买断用户会产生无上限的长期成本负债。若确实需要现金流，改做「3 年期」非续订订阅，而非永久买断。

### 5.5 定价页文案改造

`PaywallView.swift` 现有卖点列表：

```
无限朗读时长 / 无限解读次数 / 全部高级音色 / 最高 3x 语速
```

问题：全是**功能描述**，没有**价值锚定**。

改为在卖点列表**上方**增加一行锚点文案：

```text
One audiobook costs $15–25. CastReader is $5/month.
```

（中文版：`一本有声书 ¥100+。CastReader 每月一杯咖啡。`）

卖点列表调整为：

```
你的整个书库，全部可听    ← 新增，置顶
无限朗读时长
无限解读次数
全部高级音色
最高 3x 语速
```

### 5.6 分区定价（v2 新增）

$9.99 是**美区基准价，不是全球统一价**。App Store 同一订阅产品支持按 storefront 单独覆盖价格（900 价位点体系；ASC 里选基准国后可逐国手改）。v2 SKU 解决「老用户保价」，分区覆盖解决「购买力差异」，两者独立叠加，无需按地区增建 SKU。

| 市场带 | storefront | 月付基准 | 说明 |
|---|---|---|---|
| 美英加澳 | US / GB / CA / AU | $9.99 等值 | 主轴主战场 |
| 欧日 | DE / FR / IT / ES / JP | €9.99 / ¥1,200–1,500 档 | Kindle/Kobo 渗透高、Audible 贵，锚成立，不建议深折 |
| 中文区 | CN / TW / HK | 维持现价档 | 主轴不适用（§11.1），先不动价 |
| 拉美 / 印度 | BR / MX / IN | 当地惯例价（R$19.90 / ₹99–199 档） | 获客市场，变现次要 |

**成本红线**：TTS 变动成本全球一价，低价区重度用户可能烧穿 PPP 定价。当前体量可接受；低价区起量后再上成本闸（更紧免费额度或仅标准音色层），不要提前做复杂度。

## 6. 免费额度改造（历史方案，下一版本不执行）

> 本节保留用于解释旧设计。2026-08-23 已决定不发布 3 小时首装赠额；现行执行方案是 US 一次性 5 分钟试听，并在“书库就绪”和真实听读 30 秒两个价值时刻承接试用。

### 6.1 现状问题

`QuotaManager` 当前配置：

```swift
let dailyListenLimit: Double = 1200      // 每日 20 分钟
let dailyExplainLimit: Int = 3           // 每日 3 次
```

午夜重置。**这个设计对付费转化是负向的**：用户永远「差一点点够用」，永远不产生购买冲动。这是 freemium 设计的经典陷阱。

### 6.2 改造方案：两层额度

| 层 | 额度 | 补充方式 |
|---|---|---|
| **首装赠额** | 朗读 **3 小时** + 解读 **10 次** | 一次性，不重置 |
| **月度维持额** | 朗读 **20 分钟** + 解读 **1 次** | 每月 1 日重置 |

设计意图：

- 首装 3 小时足够读完一本书的开头几章 → 产生「我想听完」的冲动，**在价值峰值处触发 paywall**
- 用完后月度小额度维持存在感，但明显不够用 → 持续的购买压力
- 「读完本篇」15 分钟宽限（`graceCapSeconds`）保留不变，避免中断体验引发差评

### 6.3 技术改动点

**客户端（`Services/QuotaManager.swift`）：**

- `dailyListenLimit` / `dailyExplainLimit` → 拆为 `onboardingGrant` 与 `monthlyRefill` 两组常量
- `rollIfNewDay()` → 改为 `rollIfNewMonth()`，并新增首装赠额的一次性发放与持久化标记
- `listenRemaining` / `explainRemaining` 计算改为「首装余额 + 月度余额」两段消耗，先扣首装
- 存储键需升版（否则老用户的每日计数会被误读为月度计数）

**服务端（`/api/pro/status`）：**

- 返回值需增加首装余额字段；现有 `listenRemaining` / `freeRemaining` 语义从「日剩余」改为「总剩余」
- **服务端与客户端必须同版本发布**，否则 `applyServerStatus` 会把日额度当月额度用

**迁移策略：**

- 已安装用户在升级后视为「已消耗首装赠额」，直接进入月度维持层
- 或（更友好）给老用户一次性补发 1 小时，作为改版补偿，降低差评风险

### 6.4 埋点

需新增/调整事件，用于验证改造效果：

- `quota_onboarding_grant_exhausted` — 首装额度耗尽时刻（这是新的核心转化触点）
- `paywall_shown` 需带 `trigger` 区分：`onboarding_exhausted` / `monthly_exhausted` / `pro_voice` / `speed_gate`
- 契约文件 `docs/analytics/mobile-events-v2.json` 同步更新，并跑 `scripts/verify_mobile_analytics_contract.rb`

## 7. 首页与入口调整

当前首页把 5 个书库入口与拍照/文件/网址等并列。主轴切换后需要区分权重：

1. **书库区上移至首屏第一屏**，标题从「书架来源」改为更有价值指向的文案（如「你的书，变成有声书」）

## 10. 不做什么

明确排除，避免资源分散：

- **不做明星音色**：授权方要求逐脚本审批（平均 72 小时），与「用户自带任意内容」的产品形态根本冲突
- **不做用户声音克隆**：市场无成功先例；Apple Personal Voice 已免费内置同等能力
- **不做方言扩展**：除粤语外，中文方言无「朗读书面语」传统，属娱乐需求
- **不下线 YouTube**：功能保留，仅调整叙事权重

以上四项的完整论证见本轮讨论记录，不在此重复。

## 11. 市场分层与风险复核（v2 修订，2026-08-16）

### 11.1 主轴的地理边界

「书库→有声书」的价值 = **书平台自身不提供听书能力的缺口**，因此天生分市场：

- **缺口大**：Kindle iOS 端无 TTS（Amazon 保护 Audible）、Kobo 同类 → 美英德日加澳直接适用。
- **缺口小**：微信读书自带免费 AI 朗读，中文区用户无需第三方即可听书 → 中文区**不套用本主轴**，继续以解读/学习为主叙事；本方案的元数据改动不动 zh-Hans / zh-Hant。
- 结论：**不是「高价只能做美国」，而是「不同市场用不同主轴 + 不同价」**（价格见 §5.6）。美区先行是排序，不是放弃其他市场。

### 11.2 风险复核（对 v1 的修正）

| # | 修正 | 内容 | 对策 |
|---|---|---|---|
| R1 | audiobook 锚点的质量预期负债 | 锚价格可以，锚体验不行：真人演播的小说 TTS 无法替代，小说用户会失望差评。主轴真正成立在非虚构/学习/技术书。 | 文案红线：只说 "listen to the books you already own"，不承诺 narration 质量；BUILT FOR 段引导 nonfiction / study 人群。 |
| R2 | Kindle 曝光度风险（v1 最大遗漏） | 集成靠 WKWebView 抓 read.amazon.com（ToS 灰区）。从安静功能变成招牌，被 Amazon 针对（markup 对抗升级 / 法务函 / Apple 问询）的概率随曝光度上升。Speechify 公开打 Kindle 词多年未被封，说明容忍度存在，但其体量与法务承受力与我们不同。 | 主叙事用 "your library" 五平台并列，不单点绑 Kindle；`kindle` 维持仅 ASA 不进元数据；预设退路——Kindle 被掐后主轴仍由 EPUB / PDF / Kobo / GPB 支撑。 |
| R3 | 排名因果修正 | 「Top10=0 因定位不收敛」只对一半：元数据是相关性门槛，**排名引擎是下载速度**。改叙事必要不充分。 | 阶段二配 ASA 放量；读数看中长尾组合词与转化率，大词不动不构成方向证伪。 |
| R4 | 提价前置条件 | 转化率基线「待测」。漏斗若本身坏，提价只让数据更稀。 | 阶段一先铺 paywall trigger 埋点，拿 2–4 周基线，再切 v2 价格。 |
| R5 | 首装赠额可被刷 | 删装重来若重置 device_id → 无限 3 小时。 | 赠额以 Keychain 持久 id + 服务端记账双锚定；仅 UserDefaults 本地计数不可作为发放依据。 |

### 11.3 复核后维持的判断

明星音色不做（授权审批制与任意内容冲突）、用户自声克隆不做（Personal Voice 免费在位）、方言不做（除粤语外无书面语朗读传统）、YouTube 降级但不下线——均维持（§10）。

## 12. 循环验证协议（v4，US / GB iOS 投放→付费）

> 所有动作围绕一个循环：**进来 → 绑书库 → 留下来 → 按当前可售价格付费 → 真实广告 CAC < 净 LTV**。
> 最新关键词路由于 2026-08-23 11:52 CST 调整；2026-08-23 为混合日，当前 clean cohort 从 2026-08-24 开始，只看 US Discovery 与 GB Discovery。完整拉数与成熟度口径以
> `docs/US-GB-Apple-Ads-增长闭环数据目标与拉数SOP.md` 为唯一事实源。

### 12.1 五环与预注册通过线

| 环 | 严格口径 | 核心指标 | 通过线 | 最早读数 |
|---|---|---|---|---|
| ① 进来 | US / GB attributed 新用户，排除自然量与切点前用户 | CPT / tap→install / 安装 CPA | ≤¥8 / ≥35% / ≤¥23 | D+1 |
| 数据门 | ASA 安装可以稳定连到 production AdServices 设备 | 48h 归因覆盖 | ≥80% | D+2 |
| ② 绑书库 | 72h 内 `library_connection.sync_completed` 或 EPUB/PDF `content_ready` | 绑定/导入率 | ≥20% | D+3 |
| ③ 留下来 | W1 ≥2 个听读日；W4 在 D22–D28 仍听读 | 全体 W1 / 绑定人群 W1 / W4 | ≥15% / ≥40% / ≥30% | D+8 / D+29 |
| ④ 付费 | US 只计 v2；GB 当前只计 v1，不宣判新价 | install→trial / trial→paid / install→paid | ≥20% / ≥35% / ≥7% | D+10 |
| ⑤ CAC<LTV | 广告设备连到 Apple 正价交易 | 真实广告付费 CAC | US 首年≤¥329；扩量≤¥263 | ≥10 付费初判 |

阈值规则：数据覆盖未过门时，②–⑤一律报 `UNKNOWN`；不允许用 ASC 全渠道数据填补广告 cohort。

### 12.2 方法论纪律

1. **单配置整体验证**：小流量无多变量归因的统计功效，新价 + 新额度 + 绑定优先首页 + 新叙事一次发版；测量窗内配置冻结。
2. **阈值预注册**：读数只按 §12.7 决策树走。
3. **实验隔离**：额度改造走服务端区域门控，**仅美区新用户**；老用户保留旧价+旧每日额度（不进实验）→ §6.3 的迁移与补偿逻辑作废。

### 12.3 iOS 投放渠道判定（美区）

| 渠道 | 归因质量 | 判定 |
|---|---|---|
| **Apple Ads Search Match / Broad（US、GB Discovery）** | AdServices token：设备级；ASA 报表：搜索词级 | **当前实验主渠道**；当前 clean cohort 切点 2026-08-24 |
| Apple Ads Exact | 词级，但 US 已实测 CPA 过高 | 当前暂停；只接收 Discovery 中已验证的搜索词 |
| Meta/TikTok → App Store 直投 | SKAN/AdAttributionKit：粗粒度、延迟、小量触发隐私阈值丢数 | **不做**——测试预算下读不出数，且现价结构大概率倒挂 |
| Meta/TikTok → 网页收银台（落地页 → Stripe → 装 App → `serverPro` 解锁） | Stripe + CAPI：确定性 | **门后**——信息流唯一可行形态；管道现有架构已支持 |

只买 search results。当前不买 Today tab / Search tab；Search Match 负责找词，Broad 只保留已验证种子词，Exact 只用于承接达标搜索词。

### 12.4 跑通的瀑布数学

净 LTV（小企业计划 15% 抽成后，年费占比 60%）：US v2 **首年 ≈ $46 = ¥329，含续订两年 ≈ $54–65 = ¥386–465**。实验汇率锁定 `1 USD = 7.15 RMB`。

唯一核心公式：

```text
真实广告付费 CAC = 广告花费 / 广告归因的正价付费人数
允许的安装 CPA = 净 LTV × install→trial × trial→paid
```

旧阈值 `10% × 30% = 3% install→paid` 在当前安装成本下不可回本。
新的联动目标用 `install→trial = 20%`、`trial→paid = 35%`，即 `install→paid = 7%`；
由此 US 首年可允许的安装 CPA 约为 `¥329 × 7% = ¥23`。

| 判定 | 真实广告 CAC | 动作 |
|---|---:|---|
| 可扩量 | ≤¥263 | 首年 LTV:CAC ≥1.25，且两个成熟周 cohort 稳定 |
| 首年跑通 | ≤¥329 | 继续小额投放，验证留存与退款 |
| 仅两年回本 | ¥329–386 | 不扩量，保留学习预算 |
| 容忍上限 | ¥386–465 | 优化获客或价格，禁止扩量 |
| 失败 | >¥465 | 停对应 Campaign，回产品/渠道 |

GBR storefront 当前仍展示 v1，所以 GB 只报当前价格的付费 CAC；在 GBR 开放 v2 且核定当地净 LTV 前，不与 US 合并宣判“新价跑通”。

```
D+2   AdServices 归因覆盖
```

样本门槛：

- 扩量：≥30 个正价付费人，且连续两个成熟周 cohort 达标。

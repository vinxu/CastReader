# iOS 微信读书：错误页隔离、模式同步与短页续播

日期：2026-09-20。工作树：`codex/mobile-voice-explore-20260914`，HEAD `febfeabf869c2f77b57d360e970218899c87aa02` 加未提交修改。本轮没有提交、推送或发布 App Store。

## 定位

1. 原 WeRead JS 只有正文、封面和提取未完成状态。正文被网络错误页取代时，不会通知原生端撤销旧正文。原生导航失败的重试也没有区分“旧正文仍显示”的 provisional failure 与正文已经失效的 committed failure。
2. 仅暂停/释放播放器所有权仍保留旧队列，不能作为页面失效的完整清理。旧 TTS、预读、解读、手动翻页 2.5 秒超时均需要失效，否则可能再次操作旧页面。
3. “自然片段结束但后续音频未到”时的续播判断已由前一轮 VM 修复；本轮补实际 WebKit → bridge → VM → AVPlayer 的验证，而非再改一套判断。
4. 真机《茶花女》曹操音色在 09:08–09:10 自动确认 3 次翻页，随后微信读书显示“试读结束 / 登录”，自动翻页确认超时。这个边界来自微信读书当前网页会话，不是 CastReader 克隆分钟数耗尽。

5. 已恢复登录后真机发现：朗读翻页仅更新了活动模式，切到解读仍使用旧页段落；反向切换还可能复用朗读旧页缓存。可控 WebKit 双向测试先复现，补丁后通过。
6. 第一章章末短页的真实服务响应是 HTTP 400 `text_too_short`。此前该业务原因被抹成普通 HTTP 错误，重试后显示“不支持解读”，没有调用语义下一页。它不是截图失败。

## 修改

- JS 只依据可见错误 UI、独立错误文档和可见试读/登录墙报正文不可用；隐藏模板、普通正文包含错误词、暂时尚未画出的正文不直接判错。
- 已隐藏的阅读容器、没有阅读容器的 body 不再借历史排版快照产生伪正文。
- 正文失效一次性撤销页级事务：取消连续衔接、预读、解读预取、初始自动播放、手动翻页提交/超时与刷新；清空两种模式的旧正文和当前所有者的音频队列，并阻止工具栏/迷你播放器/重播重启旧内容。
- 正文经正常候选提交恢复后才解除拦截。同一页也可恢复；恢复本身不自动播放，用户再次点播放才开始。
- provisional 导航错误保留仍可见的旧正文；committed 失败和主框架 HTTP 错误撤销正文。用户取消导航不按网络错误处理。
- 网络重试归属可取消任务；换导航或有效正文提交后取消旧重试，避免过时重试覆盖新页。
- 复用已有网页内容门控并保留 AO3 兼容入口；所有清队列操作带播放会话令牌。
- 新增正文恢复提示，覆盖当前 9 个语言键。

- 每次确认提交新页，同时轻量更新非活动模式的正文、计划/高亮状态和页级音频缓存，不抢当前播放器所有权。
- 精确识别 HTTP/SSE `text_too_short`，不对确定性的短内容拒绝重试。WeRead 的本地短页校验与服务端短页拒绝均复用现有语义翻页；无下一页正常完成。
- 自动连续短页最多 4 次；普通文章、未知 HTTP 400、登录/权限/网络错误不自动跳过，旧代或取消后的结果不翻页。

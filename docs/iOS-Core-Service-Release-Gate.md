# iOS 送审核心服务验收

本规范用于 [App Store SOP](iOS-AppStore-Release-SOP.md) 第 2 步。目标是证明**选中的声音可以稳定完成朗读和解读**。本文件定义放行条件，不表示已有一键执行全部真实矩阵的工具。

## 1. 最小准备

- 使用候选源码及生产合同一致的配置，记录 commit、应用源码/配置摘要、设备/iOS、实际 Build、日期及地区入口。正常签名 App 不启用注入音频/假账号/跳过鉴权夹具。
- 准备中文和英文各一篇短文：至少两个可朗读段落，解读可产生至少两个块；优先使用固定自有样本文本。导入/网页适配有改动时，用改动的真实入口承载同一验收，不重复堆案例。
- 使用专用测试账号、已有有效私人音色 `vc_` 和运营可用社区音色 `vl_`；确认 Pro、授权、初始余额。测试额度有限使用，不重置或透支用户个人额度，不为每次送审重新录一遍声音。
- 中国 TTS/账号走 `api.castreader.cn`，QuickRead 走 `quickread.castreader.cn`；国际走 `api.castreader.ai`。记录 App 真正使用的路由，不能用请求的 URL 标签代替。地区覆盖可以顺序测试，不必重建相同源码多次。

## 2. 四条核心管线，两条实际服务线路

每条线路各完成下表四组：中国用中文、国际用英文。克隆组内先社区再私人，复用当前文档、讲解和选择入口，不扩大为每种声音 × 九种语言的组合。

| ID | 管线 | 必须取得的证据 |
| --- | --- | --- |
| R-K | 朗读 × Kokoro | App 选择常规声音；实际请求 voice ID 一致；生成原文且可解码；真机播放进度推进；英文词高亮/中文句段高亮符合合同，阅读位置与滚动正确；自动进入下一段，暂停/继续有效 |
| R-C | 朗读 × 克隆 | `vl_` 和 `vc_` 各成功生成并播放；用正确输出语言读原文；续文不丢失；余额按成功生成更新；切回常规不保留旧克隆音频 |
| E-K | 解读 × Kokoro | 真实 QuickRead 提取/生成讲解，再以常规声音朗读**讲解**；标注在原文正确位置和时间出现；至少一项可定位标注可见、进入下一块，不能只播放原文冒充解读 |
| E-C | 解读 × 克隆 | `vl_` 和 `vc_` 各朗读生成的讲解；实际生成 ID、播放 ID 与选择一致；块推进和原文标注有效；换声音可保留讲解文字，但旧音频不得回流 |

每条地区线路至少有一次新的完整 QuickRead 请求，证据包含实际采用的 plan/block/compose 或现有等价快通道阶段。随后为另一声音重生成同一份讲解音频可以复用文字；不能用预置假讲解或录好的试听代替解读链路。每种被测声音必须至少有一次新音频生成，之后才用缓存验证重播不扣费。

两种模式都顺带走 **常规 → 社区 → 私人 → 常规**，保留当前位置。区分“已选中”和“新声音已出声”；根据请求、音频归属和真机播放确认，不能只听到某个声音就算身份正确。

## 3. 同轮顺带验证，不增加全库压力测试

- **切换与所有权：** 两种模式各覆盖播放中切换、等待时主动暂停、再继续；读/解读互切及返回时不叠音、不回放旧缓存。快速连续改选只有最后一次生效。
- **冷准备与预读：** 选一个尚未准备/已有明确冷准备证据的社区声音，观察当前段优先于预读，`VOICE_PREPARING`/`Retry-After` 在总期限内正确等待；若本轮实际未遇冷准备，标注“warm”，用确定性并发用例验证该分支，不伪报实测冷启动。
- **失败恢复：** 在隔离测试中注入网络失败、旧响应、词时间戳拆合变化，检查准备状态能收尾、位置保留、重试继续。不要为触发失败扰动生产服务。
- **额度：** 固定试听与缓存重播不产生新扣费；普通声音不扣克隆额度；成功新生成按时长结算。通过隔离测试验证“78 分钟 → unknown → 78 分钟”、确认零余额、旧 429、后台预读不弹全局警告。未知不能算耗尽，confirmed zero 不能被未知解除。
- **负载：** 连续播放、切换及返回后界面可操作，没有持续高 CPU、资源一直增长或 watchdog；录制相关日志，而不是从 MP3 文件大小推断内存。

这些确定性分支用例不代替第 2 节真实播放矩阵。生产故障无需注入；真实 API 验证、模拟器/真机夹具验证分别记录。

现有快速定位入口（名称是 XCTest suite，不一定同名文件）：`VoiceCloneTests`、`VoiceCatalogTests`、`ReadingResumeTests`、`ReadAloudContinuationTests`、`AudioStreamingPauseIntentTests`、`AudioPlaybackOwnershipTests`、`PresetTTSRequestSchedulerTests`；QuickRead/地区鉴权变化同时跑 `ServiceRoutingTests` 对应完整套件。选择受影响套件，随后复用同一次候选全量单测结果，避免再重复跑。

## 4. 最小证据

在本版唯一报告中放一张表。每个克隆格写明 `vl_ / vc_` 的子结果，不能用一个成功遮住另一个失败。

| 地区/输出语言 | R-K | R-C（vl/vc） | E-K | E-C（vl/vc） | 证据 |
| --- | --- | --- | --- | --- | --- |
| CN / zh | 待测 | 待测 / 待测 | 待测 | 待测 / 待测 | 实际 App/接口/日志记录 |
| International / en | 待测 | 待测 / 待测 | 待测 | 待测 / 待测 | 实际 App/接口/日志记录 |

每次真实运行记录：

1. 应用 commit/源码配置摘要、实际版本 Build、设备、服务线路、后端部署身份（可读时）和时间。
2. `voice ID`、输出语言、样本文档标识/哈希、请求 ID；解读记录实际阶段及生成块身份。
3. 请求发起、收到首音频、首次真实播放进度、下一段/块推进的时间；界面高亮/原文标注观察或自动化证据。
4. 选择/切换结果、是否 warm/cache、额度前后及新生成时长、失败/跳过原因、日志/xcresult/必要截图路径。

状态只用 `PASS / FAIL / NOT_RUN`；缺设备、缺账号、服务不可用均为 `NOT_RUN` 或 `FAIL`，不计入 PASS。不写令牌、私有录音或用户正文。可以复用同候选、同配置、同后端部署的已有真实证据，但必须可回溯；历史不同包或不同线路不能自动沿用。

## 5. 放行与证据失效

**放行：** 两区四格及克隆子项均 PASS；切换/额度/异常回归无未解决失败；归档应用源码与核心验收一致。HTTP 200、能试听、`isPlaying=true`、生成了 MP3、单测 1,000 项通过均不能单独证明全链路通过，必须有真实播放进度与产品效果。

若实测是同源码开发包，报告明确签名/配置差异，不声称测试过 App Store 分发包；对 Release 包补验签名、资源、端点及夹具排除。涉及 `#if DEBUG` 或 Release 专属逻辑的核心行为，用等效 Release 配置签名包补测对应格。

代码、模型配置、账号/额度合同、路由或后端部署影响哪条管线，就让哪部分证据失效并补验。证据不充分时按更大的受影响范围重测。纯商店文案/截图处理不使核心服务证据失效；不能因此重新跑全量生成，也不能据旧核心证据对新增代码直接放行。

# CastReader 划重点·批注 场景化需求（双端通用 PRD）

> 适用 iOS 与 Android 双端。Android 已按本文档实施 P0；iOS 据此对齐。
> 版本：2026-06-25。

---

## 0. 产品定位（一句话）

> **CastReader = "AI 自动在你的原文上「划重点 + 写批注」的视觉标注层"。**

两根支柱，缺一不可：

1. **自动** —— AI 替你划重点、替你写批注，不用手动（区别于 Readwise / MarginNote / LiquidText 等手动标注工具）。
2. **锚定** —— 重点与批注**贴在原文那句话 / 那个词上**，不脱离原文（区别于 ChatGPT/Gemini 把解读飘在聊天框里；区别于 Google Lens 只翻译不批注）。

**刻意不做（避开红海，别和巨头竞争）：**
- 不跟大模型拼"解读一段文字"（已被 ChatGPT/Gemini commoditize）。
- 不跟 Lens/Gemini 拼"拍照看懂一张图"（菜单/路牌/药盒等**短查询**场景一并放弃——内容太短没几个字可划，用户也不是在"读"它）。
- **不卷朗读 / TTS**（Speechify / ElevenLabs / 微信读书 太多）。朗读退为**附带能力**（"想听时可念批注"），不是卖点，不投研发去比音色。

---

## 1. 场景策略

**选场景的标准不是"大模型能不能解读"，而是"自动划重点+锚定批注在这类内容上价值大不大"。** 价值最大的是 **长、密、需要理解结构、且必须盯着原文读** 的内容。

首批 **6 个长内容场景**，每个 = 一组"划什么 / 怎么批"的预设：

| 场景 | content_type | 划重点划什么 | 批注侧重 | 主要来源 |
|---|---|---|---|---|
| 📄 论文/学术 | `paper` | 研究问题 · 方法 · 关键结论 · 贡献 · 术语 | 这步在干嘛、为何重要、局限在哪 | PDF / 网址 |
| 📖 书籍/长篇 | `book` | 核心观点 · 金句 · 关键概念 · 情节转折 | 脉络梳理、本章主旨 | EPUB / PDF |
| 📊 长报告/研报 | `report` | 核心结论 · 关键数据 · 风险提示 | 这个数字意味着什么 | PDF / 网址 |
| 📜 合同/条款·法律 | `contract` | 权利义务 · 金额期限 · 风险/陷阱条款 | 哪里对你不利、要注意什么 | PDF / 拍照 |
| 📚 教材/学习 | `study` | 知识点 · 定义 · 易考点 | 通俗解释、记忆点 | PDF / 拍照 |
| 🧾 说明书/技术文档 | `manual` | 关键步骤 · 警告 · 参数 | 别漏这步、这个参数干嘛 | PDF / 拍照 |

> **「解读深度」不再随场景预设**——content_type 与 depth 正交，深度始终由用户在设置里选的 3 档（速览/标准/深入）决定。详见 `场景解读适配规范.md`。

> **场景的本质 = 让划重点「懂内容」。** 同一篇 PDF，以 `paper` 进入和以 `contract` 进入，划出的重点与批注侧重应明显不同。差异主要由**后端 prompt 按 content_type 分支**（目标驱动：明确目标→定义工具→LLM 决策）实现；客户端只负责把场景信号传到位 + 选对入口 + UI。

## 2. 客户端职责（双端一致）

### 2.1 解读请求带上 content_type

解读三段式管线的 **extract-plan**（及快道 fast-block0）请求体新增字段：

```
content_type: string | null   // 取值见上表 id：paper|book|report|contract|study|manual；无场景时为 null
```

- `depth` 字段**始终发用户设置**的 3 档（速览/标准/深入）——content_type 与 depth 正交，**场景不覆盖深度**（修订：旧版曾让场景预设深度覆盖全局，已废除，见 `场景解读适配规范.md`）。
- **向后兼容**：后端未接 content_type 前，字段被忽略 = 通用解读，**零回归**。`content_type` 缺省时后端行为与扩展端线上一致，不影响其 3 档深度服务。所以客户端可独立先行上线。

### 2.2 场景信号的承载与生命周期

- 在"文档会话对象"（Android = `DocSession`，iOS = 对应的会话/打开上下文）上加 `scenario: String?`。
- 用户从某个场景入口导入内容时，把该场景 id 写入会话；进入解读时读取并随请求发送。
- 拍照来源的会话（OCR 路径）同样要能携带 scenario。
- 会话清理 / 换文档时复位 scenario。

### 2.3 从场景进入即"解读优先"

本产品核心就是划重点+批注（= 解读）。**从任意场景入口进入的内容，落地后应自动进入解读模式**（auto-explain），而不是停在朗读。
- Android 注意：`autoExplain` 此前只有 WebReader 处理；PDF / EPUB reader 需补齐"渲染完成后若 autoExplain 则自动 startExplain"。iOS 各 reader 同理需统一支持。

## 3. 信息架构 / 导航（双端对齐）

### 3.1 底部导航：`[首页 | ➕居中 | 设置]`

- 原"历史/文库"中间 tab **移除**，并入**设置**里一个列表入口（复用现有历史/文库列表页，只换入口位置）。
- 中间 **➕（凸起）** 不是导航页，而是 **打开"导入方式"弹层**（拍照 / 上传文件 / 输入网址 / 输入文字 / 上传图片），此路径 **scenario = null**（通用，不声明场景）。

### 3.2 首页 = 长内容批注本

- **顶部**：剪贴板快捷卡片（保留现状）+ **"继续看"区**（最近批注过的材料，点击重开）。
- **主体**：**6 个场景入口**（图标 + 名字 + 一句"划什么"）。点场景 → 写入 scenario → 触发该场景主入口（多为文件选择器，按场景过滤文件类型）→ 落地后自动进解读。
- 不做"一大堆分类卡平铺"（评审已否）；就这 6 个，清爽。

---

## 4. 后端契约（quickread 服务，readout-desktop 仓库）

`/api/quickread/extract-plan` 与 `fast-block0` 读取请求体新增的 `content_type`，按值分支"划重点 + 批注"的 system prompt（第 1 节表格即规则）：

- `paper` → 划 问题/方法/结论/贡献/术语；批 为何重要 + 局限
- `book` → 划 观点/金句/概念/转折；批 脉络 + 主旨
- `report` → 划 结论/数据/风险；批 数字意味着什么
- `contract` → 划 义务/金额期限/风险条款；批 哪里对你不利 + 注意
- `study` → 划 知识点/定义/易考点；批 通俗解释 + 记忆点
- `manual` → 划 步骤/警告/参数；批 别漏这步 + 参数含义
- **未知值 / 缺省 → 降级为通用解读，绝不报错**。字段名 `content_type`（snake_case）。

---

## 5. "划重点·批注"做深的方向（P0 之后路线图）

P0 让划重点**懂内容**后，沿这些轴持续加深（双端通用）：

1. **划得准·分层（命门）** —— 核心论点粗笔 / 支撑细节细线 / 生词圈注 / 风险波浪线，不同重要度不同标注样式。（后端 prompt 给出 weight/role，客户端按等级渲染不同笔触）
2. **批注质量** —— 贴着原文、短、点破"为何重要"，不复述原文。（后端 prompt）
3. **标注语言丰富** —— 圈 / 下划线 / 波浪 / 星标 / 序号 / 旁注 / 连线(标关系)，每种表达不同语义。
4. **能追问 / 能沉淀** —— 点一个重点可展开 / 重批 / "再说细点"；划过的重点攒成"我的批注库"、可导出笔记。（新功能）

---

## 6. 分期

- **P0**：客户端 content_type 全链路 + 6 场景预设 + 首页场景化 + 底部导航(➕居中、历史进设置) + 场景进入即解读 + 中英 i18n。客户端独立可上线。
- **P1**：后端按 6 个 content_type 精调 prompt；客户端按 weight/role 分层渲染标注（轴 1、3）。联调验差异化。
- **P2**：点重点追问 + 批注库/导出（轴 4）；➕ 通用导入**自动识别 content_type**；历史按场景筛选。

---

## 7. 验收要点

1. 底栏 = 首页 / ➕ / 设置；➕ 弹 5 个导入方式；历史在设置里能进、列表功能不变。
2. 点"论文"→选 PDF→自动进解读→请求体含 `"content_type":"paper"` 且 `depth:"deep"`；其余 5 场景同理带各自 content_type/depth。
3. ➕ 通用导入：content_type 缺省、depth 用用户设置，现有导入流程零回归。
4. 后端未接时解读照常出（不空不崩）。
5. 中/英 文案、深色模式正常。
6. 后端接好后：同一篇 PDF 以 paper vs contract 进入，划重点与批注侧重明显不同。

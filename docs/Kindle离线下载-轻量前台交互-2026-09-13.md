# Kindle 整本图片下载：轻量前台迭代

日期：2026-09-13。以用户最新约束为本轮实施范围。源码基线为 `f5d6411`，发布祖先 `b6dd4d7`。

## 产品边界

从阅读器「更多 → 离线保存整本书」进入，沿用当前阅读器顺序采集整本原图。下载阶段不执行 OCR；本机播放时才执行 Vision OCR 和系统 TTS。当前迭代不引入独立下载器、后台传输、并行翻页或存储格式迁移。

下载期间保持 App 前台与屏幕唤醒，固定当前屏幕方向，用下载面板阻止阅读、翻页和字号等操作。这里的锁定是阅读界面锁定；普通系统锁屏或切到其他 App 会请求暂停，不是锁屏后台下载。iPhone 屏幕镜像所要求的手机锁屏，不作为后台能力证据。

## 提速前必须满足的内容正确性约束

用户于 2026-09-13 明确：不漏页、不重复、不乱序是原则性要求，速度目标不能降低这些要求。本节约束后续所有性能改动；以下新增验收项是待实施标准，不代表当前均已完成验证。

1. **每页与源内容绑定。** 页面记录绑定账号、书籍、内容版本、版式、源起止范围和图片摘要。采集前后核对同一目标页，并固定图片字节后再允许继续推进。图片哈希证明字节一致，不证明它属于哪个页；Blob 产生顺序、百分比、章节标题和回调完成顺序不能代替源页身份。
2. **顺序由源页链决定。** 只有确认是已提交末页的合法后继，才追加下一页。遇缺口、回退、重复源页或无法解释的范围重叠就停止；不能跳过去、事后仅靠排序掩盖缺口，或拿下一张图片替代失败页。相同空白图可能对应不同真实页面，不能按图片哈希删除页面记录。
3. **重试与续传不产生新页。** 只重试当前未提交的源页；已提交位置与正在采集的位置分开。取消、重启、迟到及重复回调不得推进新任务游标或二次提交旧页。图片落盘并成功提交清单后才增加“已保存”进度。
4. **完成与播放各自验证。** 标记整本完成前，核对书首至书末的合法后继链、唯一页面出现记录、资源摘要与图片对应关系。播放严格消费已提交页序；OCR/TTS 预处理完成的先后不能重排播放，失败不得静默跳过有正文的页面。只有可信源证据确认的无正文页才能按既定规则跳过；OCR 得到空结果不等于空白页。旧播放任务的迟到回调不能把第二章推进到第三章再回退。

### 当前证据与需要先补齐的边界

源码 `02f72a4` 的 `KindleOfflineSourcePosition.follows` 校验起止单调前进、无缺口及相同版式，但 `start <= previous.end + 1` 仍允许较大范围重叠。独立校验脚本也使用同类范围规则，因此两者通过不构成对该缺陷类型的独立证明。下一轮先验证并限定合法的源边界语义，再做速度实验。

当前 427 页真机清单的 426 个相邻边界中，425 处为后页 start 等于前页归一化 end，1 处为 start 等于前页 end + 1（封面后）。这与当前源坐标归一化有关，不能机械地要求所有页都加一，也不能将一本书的观察当作所有书型的规则。尚未发现该书出现较大重叠；需用原始响应和更多书型补充合法后继证据。页数、范围连续和图片摘要各有用途，均不能单独证明没有存错页。

### 据此收紧优化顺序

- 先补缺页、重复、错序、异常重叠及播放顺序的故障测试，确认错误被拒绝且已提交进度不变。
- 第一轮只减少重复扫描和原生/网页往返，改用网页内部就绪通知。保持单个在途翻页、现有逐页提交以及同等或更强的目标页确认。DOM 变化事件只是检查触发器，不直接算翻页成功；不能单独删除加载状态或稳定性校验来换速度。
- 暂不启用按 Blob 创建顺序批量保存，不并发驱动同一个阅读器翻页。已有预渲染图片只有建立可靠的源页绑定，并通过乱序返回、重复通知与缺图测试后，才进入下一轮候选方案。
- 2–3 页的保存重叠队列也须先验证取消、乱序完成和迟到回调；当前约 5.6 秒的保存耗时不是主要瓶颈，不优先增加这部分复杂度。

### 性能版本的新增验收门槛

| 故障或场景 | 必须观察到的结果 |
|---|---|
| 故意漏掉一页、重复交付一页、交换两页 | 拒绝提交错误后继，不标整本完成；末个正确提交位置不变 |
| 源页号已前进但图片仍是旧页；预取图先到 | 拒绝错误绑定，不能凭页号或图片变化单独确认 |
| 范围有较大重叠，或不同书籍/版式的图片混入 | 拒绝；错误清楚可见且旧副本仍可读 |
| 合法的相同图片页、空白页、封面边界 | 页面出现记录保持正确，不误去重、不误跳正文 |
| 任意页取消、后台暂停、重启，再重复投递旧回调 | 续传只补未提交内容，已有页记录不重复、不改变 |
| OCR/TTS 结果乱序返回、失败后重试、切页后旧任务完成 | 播放仍按页面及句子顺序；失败页不静默跳过，旧任务不复播 |
| 同书整本优化前后对比 | 源页身份及顺序逐项一致，逐页图片对应，完整覆盖且下载 OCR 为 0 |
| 章节边界与断点附近实听 | 连续朗读没有遗漏、重复或章节往返；单页播放正常不算通过 |

先做固定 50 页的小样对比，再做整本和上述故障回归。任何内容正确性回归都停止采用该优化；通过当前单书测试也不宣称所有书型已经无缺陷。

## 用户流程

1. 进入面板后显示书名、图片保存说明和保持前台提示，用户点击开始。
2. 保存中显示同步动画、已落盘页数、百分比、体积、当前阶段和动态预计剩余时间。尊重系统减少动态效果设置。
3. 预计时间来自本次运行新保存页面的速度；续传不把旧页面计作新吞吐。首张图片提交后才开始记录速度样本，排除首次定位的一次性等待。最初数页显示「正在估算」，随后用近期样本更新并向上取整。30–60 秒是同书实测目标，不是界面固定承诺。
4. 「取消下载」弹出确认；「继续下载」关闭确认框，任务继续；确认取消后停止采集、保留已提交页面、恢复原阅读位置，再解除操作锁定，显示继续下载入口。
5. 顶部关闭在运行时弹出同一确认；「停止并关闭」等待恢复原位后关闭。恢复失败时保留提示，用户可以明确关闭。重复点击停止不会创建新任务。
6. 运行时禁止下滑关闭。退出前台自动请求暂停，回到前台后完成收尾；用户点击继续后从最后一个已提交页续传。已保存内容不删除，不自动重启明确取消的任务。
7. 整书源范围连续且所有资源校验通过后才完成。保存到最后一页后进入完整性校验和恢复原位阶段，过程中进度最多显示 99%。

取消与删除分开：本轮取消只终止本次运行并保留进度；不因用户关闭面板而删除已保存书籍。

## 本轮实现

- 原有下载协调器增加准备、保存、校验、恢复状态及停止原因；取消可等待收尾完成，空闲计时器和屏幕方向在收尾后释放。
- 保持每页先保存资源、再提交目录和书籍清单的顺序。源位置与图片身份仍核对，账号、版式、代次与连续覆盖检查保留。
- 合并旧图片身份读取与翻页调用，合并轮询中的源证据和图片身份读取，图片返回时同时带回源证据，减少 WebView 往返。保留原有稳定等待时长。
- 整书校验只读取一次页面索引，逐页仍检查图片与快照摘要、图片格式和快照版本；缺页、损坏资源和取消均停止校验。
- 记录每页采集与落盘毫秒数，供下一次真书测试判断瓶颈。不记录正文或账号凭据。
- 对页面未就绪的超时最多进行两次同页重试，重试时仍可取消，不提交空页或跳过目标页。若确认阅读器已空闲、但还停在目标页之前，一次重新定位同一目标页以恢复可能未生效的快速翻页；已到目标或仍在加载时不重复翻页。账号、版式、完整性等其他错误保持停止处理。
- DEBUG 合成测试书只验证下载界面，使用临时目录和非持久化 WebView，不是速度测量或真机验收证据。

## 验收顺序

| 项目 | 通过条件 |
|---|---|
| 准备时取消 | 不写入虚构页面；能够退出；恢复错误可见 |
| 保存时取消/关闭 | 已提交页保留；收尾结束前仍锁定；原位置恢复后退出 |
| 继续下载 | 从最后已提交页继续，不重复第一页、不丢页 |
| 前后台和旋转 | 保存期间方向固定；离开前台暂停；返回不自动启动新下载 |
| 完整性 | 整书连续范围通过；损坏图片不能标记完成；100% 不提前出现 |
| 阅读回归 | Kindle 位置与字号所有权回归、本机书籍跨页朗读与断点恢复通过 |
| 真书速度 | 同一设备、书和版式，明确源缓存条件；比较总耗时和分项耗时；下载 OCR 为 0 |
| 飞行模式朗读 | Wi-Fi 关闭的飞行模式下，打开尚未 OCR 的已保存页并首次朗读，人工确认声音和高亮 |
